## 3. 🔴 드러난 것 — 카드의 평이 원자료가 아니다

오너 지적: *"전용 59·84로 단지 서칭은 하되, 카드에는 실제 공급평수를 적어야지."*

`packages/collectors/src/parse/singo.ts`:

```ts
export const PYEONG_LABEL = { "59": "25평", "84": "34평" };
```

단지가 뭐든 같은 값이다. **오보 0 규칙 위반**이고, 캡션 각주가 "관용 환산 (단지에 따라 ±1평)"
이라고 스스로 자백하고 있었다. 특히 **화서역푸르지오더에듀포레 25평**이 의심스럽다
(2009년 준공 전용 59.98 → 24평일 가능성).

**전용률 환산은 답이 아니라고 판단했다.** 단지 평균 전용률을 타입에 적용하면, 주거공용이
면적이 아니라 세대 단위로 걸리는 성질 때문에 작은 평형은 부풀고 큰 평형은 깎인다(각 0.6~0.9평).
그 크기면 24평/25평이 뒤집힌다 — 지금 틀리는 그 자리에서 똑같이 틀린다.

**오너 결정: 건축물대장 호별 실측으로 간다.**

## 4. 건축물대장 — 어디까지 됐나

`BldRgstHubService/getBrExposPubuseAreaInfo` 는 호별 전유·공용 면적을 줄 단위로 준다.

| | |
|---|---|
| API 접근 | ✅ **`DATA_GO_KR_API_KEY` 로 열린다**(MOLIT 키 아님). 신청 불필요 |
| 법정동 10자리 코드 | ✅ **이미 있었다** — `data/datasets/apt-list/*.json` 의 `bjdCode` |

| **무엇이 주거공용인가** | ❌ **미정 — 이것만 정하면 된다** |

`공급면적 = 전유 + **주거**공용`인데, 공용 줄에 지하주차장·펌프실 같은 **기타공용**이 섞인다.
v1 표본(상가 호)에서 `계단실 / 통로 / 화장실 / 펌프실(지하)` 이 보였다.
v2(`scripts/probe-bldrgst.mjs`)는 **아파트 호**를 골라 후보 셈법 5가지를 나란히 찍는다.

⚠️ **이 API 도 주차대수처럼 몇 시간 단위로 문이 닫힌다.** 14:33 성공 → 14:36 전량 실패(HTTP 0).
그래서 `apt-area-probe.yml` 이 **30분마다 스스로 다시 온다**(받으면 건너뛴다). 사람이 밀 필요 없다.
