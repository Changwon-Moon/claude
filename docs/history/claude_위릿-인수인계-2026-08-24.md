## 1. 무엇이 났나

08-24 07:09 KST 예약 런이 **61개 지역 중 18개까지 가서 100% `fetch failed`** 로 접혔다.
`fetch failed` 는 HTTP 응답조차 없는 — **연결 자체가 안 열린** 신호다. `401`/`403`(응답은
있고 인증 거부)과는 **다른 사건**이다.

## 2. 원인 — 실측으로 확정

같은 키·같은 인자로:

| 시각(KST) | 러너 | 결과 |
|---|---|---|
| 07:09 (예약) | A | ❌ 수집 성공 **0회** / 실패 18회 |
| 13:26 (세션이 대기열 푸시) | B | ✅ 판정 지역 **61/61** · 성공 61회 / 실패 0회 |
| 13:39 (시험 중 우연히) | C | ❌ 수집 실패 |
| 13:40 (**1분 뒤**) | D | ✅ 61/61 성공 |

**1분 차이로 갈렸다.** 어떤 키 가설도 이걸 설명하지 못한다.
공공데이터포털 게이트웨이가 GitHub 러너의 **일부 출구 IP 대역**을 막는 것이다.

최근 예약 런 11번 중 2번 실패(08-19·08-24) — **약 18%, 5~6일에 한 번.**

## 3. 왜 기존 재시도로는 안 됐나

수집기는 실행 안에서 **60초씩 5번**을 기다린다. 오늘 그 5분을 다 태우고도 똑같이 실패했다.
**같은 실행 안에서는 출구 IP 가 안 바뀌기 때문**이다.
고칠 곳은 대기 시간이 아니라 **어디서 두드리는가**였다.

## 4. 고친 것 — 예약 런이 죽으면 새 러너로 1회 (오너 승인)

- `singo-daily.yml` 에 **`workflow_call`** 문 추가
  (`months`·`top`·`sort` 를 비워 두면 예약 런과 **똑같이 대기열을 읽는다** — 값을 박으면
  예약 런이 쓴 조건과 조용히 갈라진다)
- **`singo-retry.yml` 신설** — `workflow_run` 으로 「예약 런 실패」만 받아 1회 호출
- 실패 알림에 **재시도가 따라붙는지**를 먼저 적게 했다
  (없으면 오너가 ⛔ 를 읽고 사람을 부르는데 10분 뒤 조용히 정상 알림이 온다)

**무한루프가 구조적으로 불가능한 이유** — ① 예약 런 실패에만 뜬다 ② 재시도는 `workflow_call`
이라 「오늘의 신고가 (daily)」 런을 새로 만들지 않는다 ③ 재시도의 event 는 `schedule` 이 아니다.

기대 효과: 두 러너가 **모두** 막힐 확률이라 실패율 **18% → 3%대**.

### ⚠️ 함정 하나 — 대기열 푸시로는 안 된다

처음엔 "세션이 손으로 하던 대로 대기열에 한 줄 밀자"로 갔는데, **GITHUB_TOKEN 으로 민 커밋은
워크플로를 트리거하지 않는다.** push 방아쇠로 뜬 런 100건을 훑어 **봇이 민 것이 0건**임을
확인하고서야 알았다. 그대로 넣었으면 **조용히 아무 일도 안 하는 장치**가 됐을 것이다.

→ **손으로 되던 길이 자동으로도 될 거라 가정하지 않는다. 센다.**

## 5. 되돌려 확인했다 (통과만 보지 않았다)

재시도는 **실패한 날에만** 도는 장치라, 진짜 실패를 기다리면 5~6일 뒤에야 켜졌는지 안다.
그래서 **조건만 뒤집어**(`success` + `workflow_dispatch`) 배선을 시험했다:

| 시험 | 결과 |
|---|---|
| 04:40 UTC **성공** 런 → 04:52 재시도 | ✅ **떴다**. singo-daily 호출 → 61/61 수집. `singo-last.md` 에 「방아쇠 `workflow_run` · **자동 재시도**」 |
| 04:39 UTC **실패** 런 → 04:51 재시도 | ✅ **skipped**. 조건이 실제로 **거른다** |

**뜨는 것만 보면 조건이 켜졌는지 알 수 없다 — 안 뜨는 쪽도 봤다.**
시험 조건은 같은 세션 안에서 되돌리고 눈으로 확인했다(커밋 `8665886`).

## 6. 새로 알게 된 것 — 세션이 워크플로를 **띄울 수 있다**

`POST /actions/workflows/{file}/dispatches` 가 **204** 로 통한다(프록시 우회 `--noproxy '*'`).
저장소 문서는 아직 "세션은 Actions 버튼을 못 누른다"로 되어 있다 — 토큰에 권한이 들어왔다.
대기열 푸시 말고 **직접 실행**할 수 있다.

```bash
curl -s --noproxy '*' -X POST -H "Authorization: Bearer $TOK" \
  https://api.github.com/repos/Changwon-Moon/claude/actions/workflows/singo-daily.yml/dispatches \
  -d '{"ref":"claude/instagram-content-automation-roadmap-fxnb7p","inputs":{"months":"1","top":"0","sort":"price"}}'
```

⚠️ 다만 **워크플로가 워크플로를 부르는 데는 못 쓴다**(그건 GITHUB_TOKEN 이라 막힌다).
세션이 손으로 쓸 때만 되는 길이다.
