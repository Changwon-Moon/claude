## 2. 🔴 잡은 버그 — 빌더가 **기록이 아닌 거래**를 실었다

빌더가 여러 히트 중 **계약일이 가장 늦은 건**을 골랐다. 틀렸다 — 이 카드가 그리는 것은
「최고가 기록」이고 기록은 **값**으로 정해진다. 신고 순서와 계약 순서가 어긋나기 때문에
**늦게 드러난 건이 더 이른 계약**일 수 있다.

| 단지 | 빌더가 고른 것 | 실제 기록 |
|---|---|---|
| 성복역롯데캐슬클라시엘 | 14.5억 (계약 08-13, 08-23 확인) | **14.9억** (계약 07-22, 08-25 확인) |
| 꿈의숲아이파크 | 14.6억 (계약 08-07, 08-22 확인) | **14.7억** (계약 07-30, 08-25 확인) |

둘 다 **그날 텔레그램과 다른 숫자**가 카드로 나갈 뻔했다.
잡아 준 것은 빌더 자신의 가드 — `곡선의 최고가와 신고가 판정이 다릅니다`.
**가드가 없었으면 조용히 나갔다.** 이제 가장 비싼 건을 고르고, 값이 같으면 늦게 계약된 쪽을 쓴다.

## 4. 🔴 주차대수 배관이 죽었다 — IP 문제가 아니다

`단지 주차대수` 워크플로가 세 번 연속 실패. 문구가 바뀌었다:

```
살아 있는 오퍼레이션이 없습니다 — 시도: AptBasisInfoServiceV4/getAphusDtlInfoV4,
  V4/getAphusDtlInfoV3, V3/getAphusDtlInfoV3, V2/getAphusDtlInfoV2
```

엔드포인트 4종을 다 시도해 전부 실패다. **연결 문제(`fetch failed`)도 인증 문제(401)도 아니다** —
서비스 URL 자체가 바뀌었거나 이 API 활용신청이 빠진 것으로 보인다.
그래서 오늘 15장은 **제원이 2줄**(주차 줄 없음)이다. 화서역푸르지오만 예전 자료가 있어 3줄이다.

→ **다음 세션 1순위.** 공공데이터포털에서 「공동주택 상세 정보」 서비스 URL·활용신청 상태 확인.

## 6. ⚠️ 정기물의 `confirmedMd5` 검사는 구조적으로 항상 깨진다

렌더 회귀에서 `mae-streak`·`jeonse-streak`·`jeonwolse-map` 3장이 어긋났다. **회귀가 아니다** —
이 카드들은 **발행일을 카드에 찍는 정기물**이라(`date` = 오늘) 날짜가 바뀌면 md5 가 바뀐다.
즉 정기물의 `confirmedMd5` 는 **확정 다음 날부터 영원히 불일치**다.

지금은 사람이 매번 "이건 정기물이니 괜찮다"고 판단하고 있다. 그러면 언젠가 **진짜 회귀를
같은 이유로 넘긴다.** 검사 방식을 고쳐야 한다(제안: 정기물은 md5 대신 *같은 date 로 두 번
그리면 같은 픽셀*이라는 결정성 검사로 바꾼다).

## 7. 배운 것 — kaptCode 는 이름으로 물리지 않는다

19건 중 **이름 매칭이 8건 빗나갔다**(신고명 `삼환`·`두산`·`주공5`·`미성` 처럼 짧은 이름).
그 경로가 정확히 **상록마을 사고**(남의 단지 세대수가 알림에 나감, 2026-08-13)다.
`(지역코드 + 법정동 + 세대수)` 로 물리니 **18건이 유일하게** 걸렸다.
미성만 대장 주소가 불광동·실거래가 신사동이라 구+세대수로 다시 물렸다.

→ 앞으로도 kaptCode 는 **이름이 아니라 이 조합으로** 찾는다.

## 이번 건의 교훈

**가드가 값을 했다.** 「곡선 최고가 ≠ 판정값」이라는, 없어도 카드가 나오는 검사 하나가
오보 두 건을 막았다. 검사는 통과할 때가 아니라 **틀렸을 때** 값을 한다.
