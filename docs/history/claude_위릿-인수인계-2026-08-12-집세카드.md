## 1. 오너가 잡아 준 것 — 이게 이 세션의 중심이다

세션이 오너에게 **"KOSIS API 키를 주세요"라고 물었다.** 물을 일이 아니었다 —
그 키는 **이미 GitHub Secrets 에 있었고 워크플로가 매일 그걸로 데이터를 받고 있었다.**

> 오너: *"이미 KOSIS는 API 연결되어 있어. API 연결 리스트를 스킬 및 작업 기준에 반영해서
> 다음부터 이런 질문 하지 않도록 해줘."*

**왜 오판했나**: "컨테이너에 키가 없다"와 "저장소에 배관이 없다"를 가를 목록이 어디에도 없었다.
`doctor` 의 `⚠️ ○○_API_KEY 없음` 경고를 세션이 "연결 안 됨"으로 읽었다. 그건 *이 컨테이너에*
없다는 뜻일 뿐이다 — 세션은 원래 키를 쥐지 않고 외부망도 막혀 있다.

### 그래서 만든 것

| 무엇 | 어디 |
|---|---|
| **연결된 API 단일 창구** | `docs/API_CONNECTIONS.md` (신설) |
| 스킬 정본에 🔌절 | `docs/WIRIT_CARDS_SKILL.md` 3단계 |
| 체크리스트·소스 카탈로그에서 그리로 | `docs/CARD_CHECKLIST.md` 머리말 · `docs/DATA_SOURCES.md` 머리말 |

`API_CONNECTIONS.md` 에 담은 것: 키가 필요한 API **18종** · 키 없는 공개 원천 **6종** ·
대기열 파일 **16종** 전수(실측). 맨 앞에 **「세션이 하지 말아야 할 것」 5줄**을 두었고
1번이 *오너에게 API 키를 요구하지 않는다* 다.

문서와 실제가 어긋나 있던 곳 6건도 함께 정정했다. 대표적으로:
- KOSIS 여섯 표는 **08-04 에 전부 켜졌는데** 08-03 시점 표만 남아 "5개 표 검증 대기"로 읽혔다.
- 서울 생활인구는 **"키 대기"가 아니다** — 키도 서비스명도 있다. 없는 것은 **정기 수집 워크플로**다.
  (`seoul-foreign-2025.json` 은 API 산출물이 아니라 오너가 올린 출입국 통계연보 엑셀이다.)

## 2. 표 ID 를 추측하던 습관을 배관으로 바꿨다

그전까지 KOSIS 표 ID 는 **웹 검색결과에 뜬 제목까지만** 보고 `confidence: "추정"` 으로 박았다
(kosis.kr 본문이 robots 로 막혀 세션에서 목록을 못 연다). 그 습관이 사망표 사인축 사고를 낳았고,
새 소재마다 세션이 표를 추측하거나 오너에게 되묻게 만들었다.

**KOSIS 는 통계표 검색·목록도 같은 인증키로 API 를 연다.** 그러니 찾는 일도 코드가 한다.

```
data/kosis-probe-queue.txt 에  run <날짜> search=키워드[,키워드…] — 사유   한 줄 → 푸시
  → data/kosis-search.md 에 orgId · tblId · 통계표명 · 수록기간이 적혀 커밋된다
  → 고른 표를 sources/kosis.ts TABLES 에 enabled:false 로 넣고 다시 푸시(probe)
  → data/kosis-probe.md 에서 itmId·분류축 확인 → enabled:true → selftest
```

신설: `packages/collectors/src/kosisSearchCli.ts` · `pnpm --filter @wirit/collectors search-kosis` ·
`kosis-probe.yml` 의 「통계표 찾기」 단계.

## 3. 덤으로 잡은 것 셋 — 전부 "조용한 실패"였다

### ① probe 잡이 취소되면 커밋이 안 돈다
표 검증이 잡 한도 40분을 통째로 먹어 **잡이 취소**됐다. 취소는 `if: always()` 로도 안 살아난다 —
결과 파일이 통째로 사라질 뻔했다(이번엔 아슬하게 살았다). **세션의 유일한 눈은 커밋된 파일**이므로
단계별 시간 한도를 박았다(찾기 20분 · 검증 25분). **반쪽 결과라도 커밋되는 쪽이 낫다.**

### ② `fetch failed` 한 줄로는 아무것도 못 가른다
Node 의 fetch 는 연결 끊김·TLS 오류·호스트 못 찾음을 **전부 그 한 줄로만** 말한다.
같은 실행에서 표 검증은 성공했는데 검색만 실패했고, 기록만으로는 "망이 죽었나 / 주소가 틀렸나"를
가를 수 없었다. `http.ts` 가 `err.cause` 까지 적게 고쳤다.

→ 원인 확정: **`ConnectTimeoutError · kosis.kr:443 · UND_ERR_CONNECT_TIMEOUT`**

### ③ kosis.kr 은 러너에서 문이 닫히는 창이 있다
**주소 문제가 아니라 TCP 연결이 간헐적으로 안 잡히는 것**이었다.
`fetchText` 의 1·2·4초 백오프로는 나쁜 창(수 분)을 못 넘는다 — 90초씩 쉬며 재시도하는
표 검증만 성공한 이유가 이것이다.

그래서 검색도 같은 인내심을 갖게 했다: **연결 확인을 최대 8회×60초 반복해 문이 열린 뒤에** 후보를
태우고, 끝내 안 열리면 **아예 시도하지 않는다**. 닫힌 창에 태운 실패 기록이 다음 사람에게
"주소가 틀렸다"로 읽히는 것이 이번에 실제로 벌어진 일이다.
판정은 `data/kosis-search.md` 맨 위 「연결 확인」 절이 문장으로 말해 준다(✅/❌).

## 4. 카드 — 오너가 정한 것 (아직 제작 전)

| 항목 | 오너 결정 |
|---|---|
| 수치 원천 | KOSIS 로 직접 계산(verified=true 목표). *키를 달라는 질문 자체가 틀렸음이 확인됨* |
| 각도 | **"4년 만에 최고"** (시간 비교) |
| 판형 | 세션 재량 → **`record-grid@1`** 로 정함 |
| 장수 | **1장** |

**판형을 `record-grid@1` 로 고른 근거**: 이 카드는 *큰 숫자 하나(1.7%)* 와 *시간 궤적* 을 같이
말해야 하는데, 저장소에서 그 둘을 한 장에 담을 수 있는 확정 판형은 이것뿐이다
(`lead{label,value,delta,deltaNote}` + `spark` 꺾은선 + `cells[]` 기록 장부).
`year-bars@2` 는 x축이 연도 전제라 월별로 쓰려면 개조가 필요하고, `news-figure@1` 은 빅넘버 자리가
숫자가 아니라 헤드라인 텍스트다.

**설계 초안**(수치는 전부 데이터셋에서 코드가 뽑는다 — 빌더에 손으로 적지 않는다):
- `lead`: 서울 집세 **+1.7%** / delta "2022년 8월 이후 최고" / deltaNote "전년 동월 대비"
- `spark`: 월별 전년동월비 추이
- `cells` 4~6: 전세 1.6% · 월세 1.8% · 전국 1.1%(서울이 0.6%p 높다) · 1~3월 1.3% → 7월 1.7% · 직전 최고 시점
- `source`: 국가데이터처 소비자물가동향 (2026년 7월)

> ⚠️ **보도 수치 ≠ 발행값.** 위 숫자는 전부 뉴시스 보도에서 옮긴 것이다. 발행값은 원자료에서
> 코드가 세고, 계산이 보도와 다르면 **계산값을 쓰고 차이를 보고**한다. "2022년 8월 이후 최고"도
> 코드가 전 기간을 훑어 확인해야 한다.

## 5. 다음 세션이 할 일

   **시도별 품목 소비자물가 표**를 고른다. ❌면 대기열에 한 줄 더 밀어 다시 돌린다(주소 문제 아님).
2. 고른 표를 `sources/kosis.ts` 에 `enabled:false` 로 넣고 probe → `itmId`·분류축 확인.
   **집세·전세·월세 항목이 어느 축에 있는지**가 핵심이다.
3. ⚠️ **수집 배관은 인구 계열과 나눠야 할 수 있다.** CPI 는 **시도 단위**인데 셀프테스트는
   *켜진 모든 표가 `kosis-region-map.json` 에 시군구 코드 100개 초과* 를 요구한다(게이트 ④).
   시도 17개짜리 표는 이 게이트를 통과 못 한다 — 게이트를 지역 단위에 따라 가르거나,
   물가 전용 수집기(`kosisPriceCli`)를 따로 두는 판단이 필요하다. **게이트를 그냥 낮추지 않는다.**
4. 데이터가 들어오면 `scripts/build-jipse-record.mjs` → 렌더 → §0.5 3팀 선검수 → 오너에게 PNG.
