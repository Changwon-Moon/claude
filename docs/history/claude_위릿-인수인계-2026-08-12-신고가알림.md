## 3. 주간 배관 — 두 컨셉

```
일간(매일 08:05) ──▶ data/datasets/singo-log/{YYYY-MM}.json  (foundOn = 확인한 날)
                                    │
주간(금 08:00) ─────────────────────┘
   → data/datasets/singo-weekly.json   conceptA / conceptB  ← 카드 빌더가 읽을 곳
   → docs/weekly/금주의신고가-{날짜}.md  ← 오너가 골라 볼 목록
   → 텔레그램
```

- **컨셉 A — 금주의 돌파 단지**: 10억·20억…100억 선을 넘은 단지를 한 장에
- **컨셉 B — 개별 카드 후보**: 오너가 몇 개 골라 각각 1장

### 설계에서 붙잡은 것 (되돌리지 말 것)

1. **주간을 계약일로 자르지 않는다.** 신고기한이 30일이라 계약일로 자르면 주간이 텅 빈다.
   `foundOn`(확인한 날)으로 자른다. 계약일은 카드에 그대로 싣는다.
2. **주간은 다시 판정하지 않는다.** 돌파는 일간이 판정 시점의 인덱스(=직전 최고가)로 이미
   정확히 쟀다 — 주간이 다시 재면 인덱스가 그새 갱신돼 있어 **틀린 값**이 나온다.
3. **주간은 API 를 안 두드린다.** 일간이 받아 둔 것을 묶기만 한다.
4. 같은 칸이 여러 날 잡히면 **가장 높은 한 건만** — 아니면 "이번 주에 두 번 신고가"가 된다.

### ⚠️ 빈 주가 생기는 것이 정상이다

돌파는 **주 1~2건**이다. 오너가 기준을 안 넓히기로 확정했으므로(넓히는 선택지는
전 평형 주 4.5건 / 5억 단위 주 3.6건 / 명부 해제 주 13.2건 — 전부 거절), 0건인 주에는
**컨셉 B 후보에서 골라 개별 카드로 가거나 격주로 묶는다.** 산출물이 그 사실을 문구에 적는다.

## 4. 오보 0을 위해 일부러 안 하는 것

1. **기준선이 안 찬 지역은 판정하지 않는다.** "0건"도 세 갈래로 갈라 말한다 —
   *명부 준비중 / 기준선 준비중 / 정말 없었다*.
2. **수집이 실패한 날의 0건을 "신고가 없음"으로 안 보낸다.** 없었던 게 아니라 못 본 것이다.
3. **직거래는 알림에서 빼되 인덱스에는 넣는다.** 빼면 직거래로 세워진 고점을 모른다.
4. **명부와 애매하게 붙는 단지는 안 붙인다.** 놓친 건 고치지만 잘못 붙인 건 오보다.
5. **전용 59·84 밖은 알고 안 잡는다** — 리센츠 48평 신고가는 안 온다.
6. **'00평'은 환산값**(전용 59→25평, 84→34평). ±1평 어긋난다. `PYEONG_LABEL` 한 줄.
7. **"역대"라고 안 쓴다.** 문구는 `baselineLabel()` 이 `BASELINE_FROM` 에서 자동 생성 —
   사람이 적으면 기간을 바꾼 날 조용히 어긋난다.

## 5. 하루 동안 잡은 배관 결함 (다른 카드도 같이 구제됨)

- **`git add A B C D` 를 한 줄로 쓰면 안 된다.** 없는 경로 하나 때문에 명령이 통째로 실패해
  산출물이 커밋에 하나도 안 담겼다.
- **공동주택 API 주소**: 기본정보가 `AptBasisInfoServiceV3` 가 아니라 **V4**,
  포맷은 **JSON**. 오퍼레이션 이름은 판올림 때 바뀌므로 후보를 돌려 살아 있는 것을 고른다.
  확정: `AptListService3/getSigunguAptList3` · `AptBasisInfoServiceV4/getAphusBassInfoV4`
- **`fetch failed` = `UND_ERR_CONNECT_TIMEOUT`** — 연결이 안 열리는 창이 있다.
  초 단위 재시도로 못 넘는다 → **60초씩 기다렸다 다시**(KOSIS 와 같은 처방).
- **35분 매달림**: 엔드포인트가 죽으면 122회를 전부 재시도하며 30분을 태운다.
  **아무 말 없이 30분 붙들려 있는 건 실패보다 나쁘다** — 접고 이유를 말하게 했다.
- **로그가 거짓말했다**: 중단 시 `used = budget` 으로 덮어써 "호출 4000회"라 적혔는데
  실제로는 296회. 다음 사람이 엉뚱한 데를 판다.
- **완성을 미완성이라 말했다**: 기준선을 2006→2020 으로 줄였더니 옛 방식으로 채운 종로구가
  창보다 커서 `monthsRemaining` 이 -217 이 됐고 `complete` 가 영영 false 였다.
- **세션이 텔레그램을 못 보냈다** → `data/notify-once.txt` 푸시로 한 통 보내는 통로 신설.
