## 2. 신설 — 공고문을 코드가 읽는다

`scripts/extract-danji-notice.py` (pdfplumber)

공고문 PDF 의 **공급금액 표** 행을 **공급대상 표**의 주택형별 세대수만큼 순서대로 먹어,
합이 정확히 맞고 남는 행이 0이어야 통과한다. 두 표는 공고문 안의 서로 다른 표라
파싱이 한 칸이라도 밀리면 합이 어긋난다.

- 상동 104행 → 1,859세대 ✔ (헤럴드경제 보도의 '84㎡ 1,370가구'와도 일치)
- 두산 38행 → 1,158세대 ✔ (청약홈 API supply 와도 일치)

⚠️ **이 검산이 못 잡는 것**(AS팀이 반례로 확인) — 열 정체성(금액 열을 건축비 열로 8px 옮겨도
✅ 가 찍힌다) · 세대수가 같은 주택형끼리의 행 순열. **뽑은 금액은 눈으로 한 번 본다.**

### 원본 PDF 는 커밋하지 않았다 — 오너 판단이 필요합니다
입주자모집공고문에는 조감도·평면도 등 **건설사 저작물**이 통째로 들어 있어 재배포 판단이
필요하다(AS팀). 그래서 `data/review/notices/*.pdf` 는 gitignore 하고,
**sha256 + 추출값**만 `data/review/notices/EXTRACTED.json` 에 남겼다.
오너가 "원본도 남기자"고 하면 gitignore 두 줄만 지우면 된다.

  (근거: 사업주체 소사본1의1구역 재개발정비사업조합).
- '옛 홈플러스 자리'는 공고문에 없는 말 → 헤럴드경제 2026-07-27 로 근거 확보해 `hookSource` 에 기록.

**디자인팀**
- 상동 **흰 영역 코발트가 0군데**(확정본 한강은 1) → `mainArea` 84 지정, 16.4억이 제목의 '16억대'를 받는다.
- 상동 조감도 **무게중심이 카드 중앙보다 89px 왼쪽**(허용 12px) → 왼쪽 130px 크롭, 좌표를 `photo.provided` 에 기록.
  대가로 shift 64→96 이라 타워 머리가 더 잘린다. **하늘이 남는 컷을 주시면 교체하겠습니다.**
- ⚠️ **`weve.png` 로고가 어두운 배경에서 흰 사각 덩어리로 뒤집힌다** — 잉크 픽셀이 단색 남색 블록
  (20.8%)이라 `brightness(0) invert(1)` 이 걸리면 네거티브가 된다. 롯데캐슬·푸르지오는 선화라 정상.
  **아직 안 고쳤다** — 로고 파일을 고치면 확정본 픽셀이 같이 움직여서, 오너 판단이 필요하다.
- 로고 밑선이 확정본보다 7~8px 떠 있다(`normalize-logos` 가 잉크 bbox 아래 여백을 안 맞춘다). 미수정.

**AS(검수)팀** — *검사 자체가 꺼져 있던 것들*
- `.dcv-facts .abv` 가 `designQa` `LEAF` 에 없어 **danji 5장의 회색 머리글이 겹침 검사 밖**이었다.
- `footergap` 목록에 **danji-cover 요소가 하나도 없어**(`.db-note` 는 삭제된 판형 것) 청약 판형 9장에서
  그 검사가 **한 번도 돈 적이 없었다**.
- '보도값이다' 경고를 `byArea` 유무로만 판정 → 분양가를 `byType` 에만 담은 **발행 보류 카드 3장
  (장위·드파인·송파)에 초록불**. 과잉 경고를 고치려다 거짓 안심을 만들었다.
- 코드가 만든 펜트하우스 줄이 `flags.filter(f => f.includes("펜트하우스"))` 로 매달려 있어
  **문구 한 낱말만 바꿔도 줄이 증발**했다(QA 통과) → 인자(`carried`)로 분리.
