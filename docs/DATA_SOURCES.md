### ⚠️ 왜 행안부 주민등록 오픈API 가 아니라 KOSIS 인가
2026-08-03 에 두 가지를 **실측하고** 갈아탔다. 오너 초안은 "주민등록 먼저"였으나 계산이 달랐다.

1. **코드 체계가 지도와 안 맞는다.** 우리 지도는 통계청 행정구역코드다(동작구 `11200`·부산 `21xxx`·경기 `31xxx`).
   행안부 주민등록은 법정동코드라 동작구가 `11590`, 경기가 `41xxx` 다. 시도 2자리가 서울만 우연히
   같아서 얼핏 붙는 것처럼 보이는데, **시군구부터 완전히 다른 체계**다. 그대로 조인하면 엉뚱한 구에
   색이 칠해진다. KOSIS 는 통계청 체계라 지도에 그대로 붙는다.
2. **규격을 검증할 수 없었다.** `data.go.kr` 상세 화면이 세션에서 안 열려(robots) 행안부 API 의
   요청 파라미터·응답 필드를 한 글자도 확인하지 못했다. KOSIS 는 엔드포인트·파라미터·응답 필드
   (`C1`·`C1_NM`·`PRD_DE`·`DT`·`UNIT_NM`)가 공개 문서로 확인된다.

### 지도 — 시군구 경계는 2026년판을 따로 만든다
기존 `data/geo/korea-municipalities.geojson` 은 **통계청 2013년판**이다. 실측하니
청원군(2014 청주 통합으로 소멸)이 살아 있고, 인천 미추홀구가 아직 '남구'이고, 화성 4구
분구(2026-02)가 없다. 전국 인구 히트맵은 시군구를 **전수로** 칠하는 카드라 이 어긋남이 그대로 보인다.

| 파일 | 무엇 |
|---|---|
| `data/geo/korea-sgg-2026.geojson` | 2026-04-01 기준 **시군구 255개** 경계 |
| `data/geo/sgg-codes.json` | **통계청 코드 ↔ 법정동코드 ↔ 이름** 대조표 |
| `scripts/build-sgg-geo.mjs` | 행정동 경계를 시군구로 합치는 스크립트 |
| `.github/workflows/sgg-geo-refresh.yml` | 행정구역이 바뀌었을 때만 돌린다 |

원본은 `vuski/admdongkor` 의 행정동 경계(SGIS 파생, 상업적 이용 가능·출처 표기 권장).
이 파일 하나가 `adm_cd`(통계청)와 `sgg`(법정동) **두 코드를 다 준다** — 그래서 인구(KOSIS)와
실거래(국토부)를 같은 지도 위에 얹을 수 있다. 카드 푸터 출처: `통계청 SGIS / vuski/admdongkor`.

**합치는 방법**: 폴리곤 합집합(union)을 계산하지 않는다. 같은 시군구 안에서 맞닿은 변은
한쪽에서 a→b, 다른 쪽에서 b→a 로 정확히 한 번씩 나타나므로 **쌍이 되는 변을 지운다.**
원본에 없던 좌표가 하나도 생기지 않아 부동소수점 합집합이 만드는 틈·자기교차가 원천적으로 없다.
남은 변이 닫힌 고리로 안 이어지면 **던진다** — 깨진 도형을 조용히 내보내면 카드에 구멍이 뚫린다.

⚠️ **바깥 고리를 회전 방향으로 판정하지 않는다.** 원본의 바깥 고리는 시계방향이라 부호로 가르면
전부 구멍이 된다(2026-08-03 에 실제로 여기서 한 번 막혔다). **포함 깊이**로 가른다.

#### 검증은 첫 호출이 대신한다 — `kosis-probe`
`pnpm --filter @wirit/collectors probe-kosis` (또는 `data/kosis-probe-queue.txt` 푸시)가
표마다 **최근 1개 시점만** 받아 `data/kosis-probe.md` 에 적어 커밋한다:
통계표명(TBL_NM) · 항목코드(ITM_ID/ITM_NM) · 분류축(C1~C4) · 시군구 5자리 코드가 실제로 오는가.

⚠️ **왜 이 단계를 건너뛰면 안 되나.** 사망 표(`DT_1B34E13`)에는 '사망원인 50항목' 축이 있다.
'계'를 안 고르면 **특정 사인의 숫자가 총사망자수로 카드에 나간다** — 응답은 정상이고 숫자도
그럴싸해서 눈으로는 안 잡힌다. 인구이동 표도 총전입/총전출/순이동이 섞여 있어 같은 위험이 있다.

#### 파생 지표는 받아 적지 않고 우리가 계산한다
세대당 인구(인구÷세대수) · 순이동(전입−전출) · 고령화율(65세이상÷인구) · 자연증감(출생−사망).
전용 항목이 표에 있더라도 **원자료에서 코드가 다시 계산한다** — 오보 0 원칙이고,
지표표와 원자료가 어긋날 때 어느 쪽이 맞는지 우리가 안다.

#### ⚠️ 아직 표를 못 찾은 것 — 1인가구 비중
오너가 고른 네 갈래 중 **가구·1인가구**는 절반만 채워져 있다.
`DT_1B040B3`(주민등록세대수)로 **세대수·세대당 인구**는 되지만, **1인가구 비중**은
`세대원수별` 축이 있는 다른 표가 필요하다. 공공데이터포털에 파일데이터
「지역별(행정동) 세대원수별 주민등록 세대수」가 있는 것은 확인했으나 **KOSIS tblId 는 못 찾았다.**

**추측으로 tblId 를 적어 넣지 않았다** — 지어낸 표 ID 가 이 배관에서 가장 위험하다.
`kosis-probe` 를 돌릴 때 `DT_1B040B3` 의 분류축에 세대원수가 들어 있는지 먼저 보고,
없으면 그때 표를 다시 찾는다. 세대당 인구(인구÷세대수)만으로도 "1인가구 시대" 서사의
7할은 나오므로 급하지 않다.

### ⚠️ 세 가지가 표마다 다르다 — 전부 실측으로 확인했다

**① 행정구역 코드 체계.** 종로구를 세 곳이 다르게 부른다:

| | 종로구 |
|---|---|
| **우리 지도** | `11010` |
| 인구·세대·이동·연령 | `11110` (통계청 체계) |
| 출생·사망 | `11010` |

지도 코드 255개와 인구표 코드가 **겹치는 것은 9개뿐이고 그것도 우연**이다.
변환 없이 조인하면 9곳에 엉뚱한 숫자가 들어가고 246곳이 빈다.
`data/geo/kosis-region-map.json` 을 **여섯 표 전부** 거친다. 예외 없다.

시도 이름도 다르다 — 사망표 `강원도` vs 인구표 `강원특별자치도`.
일반구도 다르다 — KOSIS `41110=수원시` + `41111=장안구`, 지도 `수원시장안구`.

**② 지역이 몇 번째 축인가.** 사망 표는 C1 이 **사망원인**이고 C2 가 행정구역이다.
모르고 C1 을 읽으면 `11=호흡기 결핵`이 지역 코드가 된다.

**③ 기간 형식과 4만 셀 한도.** 연간 표에 월 형식(`202407`)을 주면
"데이터가 존재하지 않습니다"가 온다. 표마다 `rangeForTable()` 로 기간을 만들고,
**거기서 나온 시점 수로** 나눠 부를 크기를 계산한다 — 계산과 요청이 어긋나면 한도에 걸린다.

### 🚧 알려진 결손: 화성시

출생·사망이 3% 부족한 것은 **화성시 하나** 때문이다. 2026-02 에 4개 구로 나뉜
도시라 우리 지도에는 만세구·효행구·병점구·동탄구만 있는데, 2024년 데이터에는
`화성시` 한 행으로만 있다. 이름이 안 맞아 버려진다.

**이 결손은 지도에서 안 보인다.** 화성시 자리는 비어 있고 빈 칸은 "데이터가 없는 곳"
으로 읽힌다. 전국 순위 카드를 만들면 화성시 없는 순위가 되는데, 그건 틀린 순위가
아니라 **틀린 줄 모르는 순위**다. 그래서 같은 응답 안의 전국 행(`00`)과 우리 합계를
대 보고 3% 이상 벌어지면 경고를 남긴다.

**출생·사망으로 전국 순위·합계 카드를 만들 때는 화성시가 빠졌다는 것을 알고 만든다.**

### 순이동은 굵기가 다르다
인구이동 표는 일반시를 구로 안 나눈다 — 수원시·성남시·고양시·용인시가 시 단위
한 행으로만 온다. 우리 지도는 그 시들을 구로 쪼개 놓아 39곳이 빈다.
수원시 순이동을 4개 구에 나눠 넣는 것은 만들어 낸 숫자라 비워 둔다.
문턱을 그냥 낮추지 않고 `KNOWN_COARSE` 에 이유와 함께 적었다 —
낮춘 문턱은 다음에 진짜로 깨졌을 때도 통과시킨다.

## 서울 열린데이터광장 — 생활인구 (2026-08-06 배관 완성, 키 대기)

### 무엇을 받나
| 서비스 | 서비스명 | 상태 |
|---|---|---|
| 장기체류 외국인 | `SPOP_FORN_LONG_RESD_DONG` | 이름확실 · **검증 대기** |
| 단기체류 외국인 | (미확인) | 서비스명부터 확인 필요 |
| 내국인(분모) | (미확인) | 서비스명부터 확인 필요 |

### 🔴 KOSIS 와 다른 점 셋 — 배관에 반영돼 있다

**① 인증키가 경로에 들어간다.**
```
http://openapi.seoul.go.kr:8088/{KEY}/json/{서비스명}/{시작}/{끝}/{기준일}
```
쿼리스트링이 아니라 **경로**다. `http.ts` 의 `redactUrl` 은 쿼리스트링만 지우므로
그것만 믿으면 **키가 그대로 새어 나간다**(2026-08-03 KOSIS 키 유출과 같은 사고).
→ `redactSeoulUrl()` 전용 함수를 만들고 셀프테스트로 못 박았다.

**② 한 번에 1,000행까지.**
행정동 약 425개 × 24시간 ≈ 1만 행이라 반드시 걸린다. `fetchDay()` 가 나눠 받고,
**받은 행 수가 전체와 다르면 던진다** — 부분 수집은 순위·합계를 거짓으로 만든다.

**③ Open API 는 최근 2개월만.** 그 이전은 사이트에서 ZIP(2017~)을 받아야 한다.

### ⚠️ 아직 모르는 것 — probe 로 확정한다
1. **중국/중국외 구분 컬럼명**
2. **'총생활인구수' 가 전체 인구인가, 외국인 합계인가**
   ← 착각하면 **분모가 바뀌어 비율이 통째로 달라진다.** 가장 위험한 미지수다
3. **행정동코드 체계** — 우리 지도와 같은가(다르면 대조표 필요)
4. **시간대 컬럼** — 생활인구는 시간별이다. 어느 시간을 쓸지 정해야 한다

### 생활인구 ≠ 거주인구
서울시와 KT 가 통신·공공 빅데이터로 추계한 **"그 시각 거기 있던 사람"** 이다.
구로·가산·독산은 산업단지라 낮 시간 **근무 인구**가 잡히고,
회기·화양은 대학가라 **유학생**이 잡힌다. 카드 제목에 반드시 '생활인구' 를 넣는다.
