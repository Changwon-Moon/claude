# 데이터 소스 카탈로그

"무한 생산"의 원료. 원칙: **공식·공공 데이터 우선, API 우선, 크롤링은 최후**. 모든 콘텐츠에 출처를 표기하므로 소스의 신뢰도가 곧 계정의 신뢰도다.

### 2-1. 실거래 지역코드(LAWD_CD) 운용 — 2026-07-25 보강

- 목록: `packages/collectors/src/data/lawd-seoul.json` · `lawd-gyeonggi.json`(47개). CLI `--region seoul|gyeonggi`
- **코드는 분구·통합으로 죽는다.** 2026-02 화성시 4구 분구로 `41590`(화성시)·`41190`(부천시)이 무효화됐다.
  - 화성 만세 `41591` · 효행 `41593` · 병점 `41595` · **동탄 `41597`** / 부천 원미 `41192` · 소사 `41194` · 오정 `41196`
  - **수집 결과 0건이면 API 장애가 아니라 코드 폐기를 먼저 의심**하고 후보 코드를 실측으로 확정한다.
- 캐시: `data/datasets/molit/{LAWD}-{YYYYMM}.json`. **공용 폴더이므로 빌더는 반드시 지역 정규식으로 좁힌다**
  (`/^11\d{3}-\d{6}\.json$/` 등). 안 하면 데이터가 늘 때 과거 카드가 조용히 오염된다.

### 2-2. 행정경계 GeoJSON

| 파일 | 내용 | 주의 |
|---|---|---|
| `data/geo/seoul-districts.geojson` | 서울 25구 | — |
| `data/geo/korea-municipalities.geojson` | 전국 시군구 | 코드가 **행정구역코드**(서울 11, 경기 **31**) — 법정동코드(경기 41) 아님 |
| `data/geo/korea-submunicipalities.geojson` | 전국 읍면동 | 신설 구 **합성용**(예: 동탄구 = 3124044·3124060~62) |

- 폴리곤은 강하게 단순화돼 있다(서울 1개 구 ≈ 9정점). 이 거친 형태가 오히려 카드 스타일과 맞는다.
- **지리 요소는 손으로 그리지 않는다**: 하천 = 양안 그룹의 공유 정점, 시 경계 = evenodd 클립.

## 5. 뉴스·이슈 감지 (소재 발굴용 — 데이터 원천 아님)

| 소스 | 용도 |
|---|---|
| 주요 언론사/통신사 RSS | 오늘의 이슈 감지 |
| 네이버 뉴스 랭킹, 구글 트렌드 | 대중 관심사 파악 |
| 각 부처·기관 보도자료 | 1차 출처 확인 |

**규칙: 뉴스는 "무엇이 이슈인지"를 알려주는 신호로만 쓰고, 콘텐츠의 수치는 반드시 1차 출처(공공 API·공식 발표)에서 다시 뽑는다.** 언론 보도 수치를 그대로 옮기지 않는다 — 오보 전파 방지 + 저작권 리스크 회피.

## 법적·윤리 체크리스트

- [ ] 공공데이터는 이용약관상 출처 표기 조건 확인 (대부분 표기만 하면 상업적 이용 가능)
- [ ] 크롤링 대상은 robots.txt·약관 확인, 요청 속도 제한 준수
- [ ] 기업 로고 사용: 정보 전달 목적의 지명적 사용(nominative use) 범위 유지, 문제 제기 시 즉시 교체 프로세스
- [ ] 유료 데이터(리서치사 리포트 등)는 인용 범위 준수 또는 라이선스 계약
- [ ] 모든 게시물 하단 출처 표기 자동화 (편집 에이전트 필수 필드)
