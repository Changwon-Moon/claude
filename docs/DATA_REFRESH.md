# 🔄 정기물 자동 갱신 — 업무 기준

> **이 문서가 있는 이유** (2026-07-31 오너)
> "매번 눌러야 돼? 한 번 세팅 해놨는데, 알아서 업무 기준 만들어서 해줘."
>
> 그때까지 이 공장은 **수집도 재생산도 사람이 눌러야** 굴러갔다. 새 데이터가 들어와도
> 그 데이터로 만든 카드는 아무도 다시 만들지 않았고, 오너가 관제탑에서 [제작 실행]을
> 눌러야 반영됐다. **데이터가 바뀌면 카드도 바뀐다 — 이건 판단이 아니라 사실이다.**
> 사실은 자동화하고, 판단만 사람에게 남긴다.

---

## 1. 원칙 — 무엇을 기계에 맡기고 무엇을 남기나

| | 누가 | 왜 |
|---|---|---|
| 데이터 수집 | **기계**(달력) | 언제 받을지는 신고기한이 정한다. 사람이 잴 일이 아니다 |
| 카드 재생산·검수 | **기계**(데이터가 바뀌면) | 같은 데이터 → 같은 픽셀. 결정적 코드 재실행이다 |
| 관제탑 반영·알림 | **기계** | 결과를 눈앞에 가져다 놓는 일 |
| **무엇을 만들지(소재)** | 사람 | 판단이다 |
| **문구·제목** | 사람(+AI 세션) | 말이 사실보다 세지 않은지는 사람이 본다 |
| **발행 승인·인스타 업로드** | **오너** | 2026-07-27 결정. 자동 발행은 폐지됐다 |

기계가 하는 일의 끝은 **"결재 대기에 올려두는 것"**까지다. 그 앞으로는 가지 않는다.

## 2. 배관 — 한 번 밀면 끝까지 간다

```
 달력(cron)                    ┌──────────────────────────┐
 매월 5일·20일 ──────────────▶ │ molit-collect.yml        │  실거래(국토부)
 평일 07:10 KST ─────────────▶ │ kr-market.yml            │  증시
 매월 (reb-collect) ─────────▶ │ reb-collect.yml          │  전월세지수
                               └───────────┬──────────────┘
                                           │ data/datasets/** 커밋
                                           ▼
                               ┌──────────────────────────┐
                               │ auto-produce.yml         │  ← 이번에 새로 만든 고리
                               │  ① 바뀐 파일 → 영향 세트  │
                               │  ② 세트별 재생산·검수     │
                               │  ③ 머리 규격 전수 점검    │
                               │  ④ 카드·리포트 커밋       │
                               └───────────┬──────────────┘
                                           ▼
                        tower-deploy(관제탑 배포) + 텔레그램 알림
                                           ▼
                                 오너: 결재 대기에서 확인 → 발행
```

**빠져 있던 고리는 ②였다.** 수집기는 돌고 있었는데 카드가 안 따라왔다.

## 3. 의존 관계는 손으로 적지 않는다

`scripts/affected-sets.mjs` 가 **빌더 스크립트 소스를 읽어** `data/datasets/…`·`data/geo/…`
경로를 뽑고, 바뀐 파일과 접두사로 대조해 영향받는 세트를 고른다.

```bash
node scripts/affected-sets.mjs data/datasets/molit/11680-202607.json
# → estate-59 / estate-84 / tohuh-rank / years-to-buy
```

`builders.json` 에 `deps:` 칸을 두는 방법도 있었지만 쓰지 않았다.
**그 칸은 반드시 낡는다** — 빌더가 새 데이터셋을 읽기 시작해도 아무도 칸을 고치지 않는다.
코드가 곧 의존 관계다. 두 곳에 적으면 어긋난다(이 저장소가 여러 번 겪은 실패다).

> ⚠️ 처음엔 뽑은 경로에서 파일명을 잘라 폴더로 만들었다가 전부 `data/datasets` 가 되어
> **실거래 한 파일 변경에 12개 세트가 딸려 나왔다.** 경로는 자르지 말고 그대로 접두사로 쓴다.

## 4. 수집 시점은 신고기한이 정한다

실거래 **신고기한은 계약 후 30일**이다. 그래서:

- **5일**: 지난달 1차 확정분
- **20일**: 지난달 늦은 신고분까지 — 이때 그달 숫자가 굳는다

정기 실행은 **항상 `--force`** 로 돈다. 수집기는 캐시가 있으면 건너뛰므로,
force 없이 돌면 이미 받아둔 달은 영영 갱신되지 않는다 — 두 번 도는 의미가 사라진다.

카드에는 최신월이 아직 신고기한 안이면 **"N월분 신고 진행 중"**이 자동으로 붙는다
(`build-map-rank.mjs`). 밝히지 않으면 나중에 신고가 채워져 숫자가 바뀔 때
앞서 나간 카드가 틀린 것처럼 보인다.

## 4b. 청약홈 — 매일 아침 신규 분양·무순위(줍줍) 줍기 (2026-08-01)

오너 주문: *"하루에 한 번 자동으로 돌려서 무순위·신규분양 검색해 소재 뽑아줘."*

| | |
|---|---|
| 워크플로 | `.github/workflows/applyhome-collect.yml` — 매일 **08:00 KST**(`0 23 * * *` UTC) · 대기열 푸시로도 즉시 실행 |
| 키 | `DATA_GO_KR_API_KEY` (공공데이터포털) |
| 오퍼레이션 | `getAPTLttotPblancDetail`(신규 APT) · `getRemndrLttotPblancDetail`(무순위·잔여세대) |
| 산출 | `data/datasets/applyhome-latest.json` + `data/datasets/applyhome/{날짜}.json` |
| 그다음 | `scripts/register-applyhome-ideas.mjs` → `research/ideas.json` 등록 → 텔레그램 알림 |

### 무엇을 소재로 올리나 — 규칙은 코드다

점수는 `packages/collectors/src/parse/applyhome.ts` 의 `score()` 가 계산한다.
LLM 이 고르지 않는다. **45점 이상**만 보드에 올라간다.

| 항목 | 점수 |
|---|---|
| 지역 | 서울 +30 · 경기·인천 +18 · 광역시 +10 · 그 외 +4 |
| 규모(신규) | 1,000가구+ 25 · 500+ 18 · 300+ 12 · 100+ 6 |
| 규모(무순위) | 100+ 20 · 30+ 14 · 10+ 8 |
| 성격 | 무순위(줍줍) +25 |
| 임박도 | 접수 마감 D-0~2 +15 · D-3~6 +8 |
| 브랜드 | 로고 보유 브랜드 +10 |
| 규제 | 분양가상한제 +12 · 투기과열지구 +5 |

오너 선택(2026-08-01): **전국을 다 받되 수도권에 가점.** 지방을 버리지 않는 이유는
범어역 파크드림 디아르(대구 수성) 101.48대 1 같은 건을 놓치지 않기 위해서다 —
세대수·브랜드가 크면 지방도 문턱을 넘는다.

### 블록별로 쪼개진 공고는 한 줄로 합친다 (2026-08-02)

청약홈은 같은 단지라도 **블록마다 공고를 따로** 낸다. 첫 실제 실행에서 소재 보드 상위 5칸을
「더샵 송도그란테르」한 단지가 G5-1·3·4·5·11블록으로 도배했다 — 다섯 줄을 봐도 읽히는 건
"송도에 줍줍 하나 떴다"뿐이다.

`mergeBlocks()` 가 **같은 종류·지역·접수 마감일**이고 이름이 블록 표기만 다른 2건 이상을 합친다.
세대수는 합계(45+36+35+12+22 = **150가구**), 점수는 합친 뒤에 매긴다(앞뒤가 바뀌면 45가구
다섯 줄이 된다). 혼자면 원래 이름을 그대로 둔다 — 블록만 지우면 사실 정보를 잃는다.

⚠️ **'안산고잔2차'의 '2차'는 블록이 아니라 단지 이름의 일부다.** 지우면 1차와 합쳐져 오보가 된다.
회차가 다른 공고는 접수일이 달라 자동으로 안 합쳐진다.

### 보드가 쌓이지 않게 하는 장치

- 같은 공고를 두 번 올리지 않는다(`id = ah-{kind}-{공고번호}`).
- **이미 올라간 자동 소재는 매일 최신 내용으로 갱신한다.** 안 하면 D-N 이 굳어 어제 D-3 이던
  줄이 오늘도 D-3 이라고 적혀 있다 — 틀린 정보다. 오너가 손댄 줄(state·status 가 채워진 것)은
  절대 덮지 않는다.
- **접수가 끝났는데 오너가 아직 안 고른 자동 소재는 지운다.** 지난 줍줍이 남으면
  그건 결정 요청이 아니라 영구 알림이다(CEO 07-26).
- 오너가 손댄 것(state 가 채워졌거나 status 가 있는 것)은 절대 지우지 않는다.
- **알림은 새 게 있을 때만** 간다. 조용한 날이 있는 게 정상이다.
- **오너가 직접 물으면 다르다** — `digest=1` 을 대기열에 넣으면 새것 여부와 무관하게
  **지금 접수가 열려 있는 소재 전체**를 줍줍/신규로 나눠 보낸다. 마감된 건은 뺀다
  (오늘 못 넣는 공고는 정보가 아니라 소음이다). 보낼 게 없으면 "없습니다"라고 보낸다 —
  물었는데 아무 말이 없으면 고장을 의심하게 된다.

### 조용한 실패를 막는 세 곳

1. **키가 없으면 워크플로가 멈춘다**(`::error::` + exit 1). 2026-07-31 에 알림 키가
   등록된 적 없이 몇 주가 지난 사고가 있었다 — 매일 도는 수집기의 침묵은 정상과 구분되지 않는다.
2. **응답 필드 이름이 바뀌면 파서가 던진다.** 빈 배열로 넘기면 "오늘은 공고가 없었다"와
   구분되지 않는다.
3. **셀프테스트는 수집 *뒤에* 돈다.** 증시 수집이 셀프테스트 실패로 며칠 죽어 있던
   2026-07-31 사고 때문이다 — 검사는 하되, 검사가 데이터 수집을 막지는 않게 한다.

### ⚠️ 첫 실행 전에 확인이 안 된 것

작업 세션은 외부망이 막혀 있어(`apis.data.go.kr` → HTTP 000) **실제 응답을 한 번도 못 봤다.**
필드 이름은 공개 스펙에서 가져온 것이고, 표본은 `__fixtures__/fixtures.ts` 의
`APPLYHOME_*_JSON` 이다. 배관(정규화→점수→소재 등록→알림)은
`pnpm --filter @wirit/collectors collect-applyhome -- --dry` 로 세션에서 확인했다.

**첫 실제 실행에서 필드 이름이 다르면 워크플로가 빨갛게 뜬다**(조용히 넘어가지 않는다).
그때 실제 응답 한 건을 표본으로 옮겨 심고 별칭 목록을 고친다.

### 세션이 결과를 보는 창구 — `data/applyhome-last.md`

세션은 GitHub API 가 막혀 Actions 로그를 못 본다. 그래서 이 워크플로는 **성공이든 실패든**
실행 조건·수집 로그·소재 등록 결과를 `data/applyhome-last.md` 에 적어 커밋한다
(`research/article-fetch-last.md` 와 같은 방식). 세션은 `git pull` 로 그 파일을 읽는다.
**오너에게 "Actions 를 열어 보세요"라고 하지 않기 위한 장치다.**

## 5. 세션이 수집을 걸어야 할 때

작업 세션은 `api.github.com` 이 프록시에서 막혀 있어(403) **Run workflow 버튼을 누를 수 없다.**
오너 토큰을 써도 마찬가지다. 하지만 **푸시는 된다.**

그래서 수집 워크플로는 전부 **대기열 파일 푸시**로도 돌게 해 두었다:

| 수집기 | 대기열 파일 | 한 줄 형식 |
|---|---|---|
| 실거래(국토부) | `data/molit-queue.txt` | `region=seoul gu=all months=202607 force=false` |
| **청약홈(줍줍·신규분양)** | `data/applyhome-queue.txt` | `within=7 min=45 digest=1` (전부 선택) |
| 증시 | `data/market-queue.txt` | 아무 줄이나(파일이 바뀌면 실행) |
| 자산·지오코딩 | `data/assets-queue.txt` · `data/geocode-queue.txt` | 각 워크플로 참조 |

**세션은 이 줄을 밀어 넣는 것으로 수집을 시작한다.** 오너에게 버튼을 눌러 달라고 하지 않는다.

## 6. 자동 재생산이 하지 않는 것

- **캡션 없는 세트는 건드리지 않는다.** 올릴 글이 없으면 결재할 것도 없다
  (`smoke-tower` 의 세트↔빌더 정합 검사와 같은 기준).
- **빌더 없는 새 소재는 만들지 않는다.** 데이터 소스 판단·코드 작성이 필요하고, 그건 사람 일이다.
- **발행하지 않는다.** 인스타 업로드는 오너가 직접 한다.
- **자기 자신을 다시 깨우지 않는다.** `data/content`·`data/review` 만 커밋하고
  `data/datasets` 는 건드리지 않으므로 루프가 생기지 않는다.

---

## 7. 고장 났는지 어떻게 아나

- 자동 재생산이 실패하면 워크플로가 **빨간불**로 끝나고 텔레그램 알림이 간다.
- **데이터셋이 오래돼 보이면 원인을 추측해 보고하지 않는다.** 세션은 Actions 실행 기록을
  조회할 수 없다. 오너에게 Actions 화면을 요청한다.
  (2026-07-31 에 증시 수집이 셀프테스트 실패로 며칠 죽어 있었는데,
   "세션 외부망 차단" 탓으로만 설명하고 있었다 — 데이터가 안 온다는 사실만으로는
   "수집이 막혔다"와 "파이프라인이 죽었다"를 구분할 수 없다.)
- 수집 워크플로는 **셀프테스트를 먼저 돌린다.** 테스트가 깨지면 수집이 통째로 멈춘다 —
  그러니 파서 테스트에 `=== 3` 같이 **자라는 목록의 개수를 못박지 않는다**(그래서 한 번 멈췄다).

### ⚠️ 기본은 "보드에 안 올린다" — 오너가 고른다 (2026-08-03 결정)
오너 선택: **"데이터만 자동, 소재는 내가 고른다."** 청약홈은 자동 등록이지만 인구는 아니다.
매달 수집이 돌면 신호를 점수순으로 정리한 **`data/population-signals.md`** 를 커밋하고
텔레그램으로 상위 몇 건을 알린다. `research/ideas.json` 은 **건드리지 않는다.**
나중에 "이건 자동으로 올려도 되겠다" 싶으면 대기열에 `register=1` 한 줄이면 켜진다.

**신호는 코드가 고른다.** 규칙은 `packages/collectors/src/parse/kosis.ts` 의 `score()` 한 곳에 있다.
① 문턱 돌파·붕괴(5만·10만·20만·30만·50만·70만·100만) ② N개월 연속 증감 ③ 1년 증감률 전국 상·하위 TOP10.
가점은 지역(서울 18·수도권 12·광역시 7)과 규모(100만 22·50만 16…). 문턱 45점, 알림에는 상위 8건.
**잘라낸 개수는 반드시 알림에 적는다** — 조용히 자르면 "이번 달은 이게 다"로 읽힌다.

⚠️ **"N개월 연속"에서 값이 같은 달은 연속을 끊는다.** 이어 세면 개월 수가 부풀려져 그대로 오보가 된다.

### 지도 조인은 매번 검사한다
수집할 때마다 `data/geo/sgg-codes.json` 과 대조해 **맞은 개수·지도에 없는 시군구·데이터에 없는 시군구**를
찍는다. 행정구역이 바뀌면 여기서 먼저 드러난다 — 조용히 빈 칸으로 그리면 그게 곧 오보다.
"지도에 없는 시군구"가 뜨면 `data/geo-queue.txt` 를 밀어 `sgg-geo-refresh.yml` 로 경계를 다시 만든다.

| 수집기 | 대기열 파일 | 한 줄 형식 |
|---|---|---|
| 인구(KOSIS) | `data/population-queue.txt` | `months=25 min=45 top=8 digest=1 register=1` |
| KOSIS 표 검증 | `data/kosis-probe-queue.txt` | 아무 줄이나(바뀌면 실행) |
| 시군구 경계 | `data/geo-queue.txt` | `url=<행정동 geojson> tolerance=0.0004` |
