# 🔥 오늘의 신고가 — 알림 기준

> **이 문서가 있는 이유** (2026-08-12 오너)
> "오늘의 신고가 거래 라는 새로운 위릿카드 템플릿을 만들고자 해. 그에 앞서, 매일 아침
> 텔레그램으로 청약/분양단지에 대해 알림톡 받고 있는데, 이걸 신고가 톡도 받을 수 있도록
> 먼저 세팅해줘."
>
> 카드보다 **알림이 먼저**다. 매일 무엇이 올라오는지 며칠 봐야 카드에 담을 것이 정해진다.
> 이 문서는 그 알림이 무엇을 재고 무엇을 안 재는지의 정본이다.

| 시각 | **아침 8시** (실제 08:05 KST) | 청약 알림(08:00) 바로 뒤에 나란히 |

## 2. "신고가"의 정의 — 코드가 재는 것

한 거래가 아래를 **전부** 만족할 때만 신고가로 부른다.

1. 같은 **구 + 법정동 + 단지명 + 평형대** 칸에서 **2006-01 이후 모든 거래**보다 비싸다
2. 그 칸에 **역대 기록이 실제로 채워져 있다** (기준선 수집이 끝난 지역)
3. **해제(취소) 거래가 아니다**
4. **중개거래다** (직거래 제외)
5. 그 단지가 **1000세대 이상이다** (공동주택 기본 정보의 세대수)

### 평형대 경계 (전용면적 기준)

| 전용면적 | 라벨 |
|---|---|
| 40㎡ 미만 | 10평대 |
| 40 ~ 60㎡ | 20평대 |
| 60 ~ 85㎡ | 30평대 |
| 85 ~ 115㎡ | 40평대 |
| 115 ~ 145㎡ | 50평대 |
| 145㎡ 이상 | 60평대 이상 |

> **평형대로 재는 것이 전용면적으로 재는 것보다 엄격하다.**
> 밴드는 그 전용면적을 부분집합으로 품는다. 그래서 밴드 최고가를 넘었다면 같은 전용면적
> 최고가도 반드시 넘는다 — 이 기준으로 신고가라 부른 것은 더 좁은 기준으로도 신고가다.
> 반대로 밴드 안의 작은 타입은 거의 안 걸린다. **알림이 적고 강해지는 쪽**이라 의도한 결과다.

## 3. 일부러 판정하지 않는 것 — 그리고 그 이유

| 안 하는 것 | 왜 |
|---|---|
| 기준선이 안 찬 지역 | 반쪽 기준으로 "역대 최고가"라 부르면 그게 곧 **오보**다. 초기 수집이 끝날 때까지 그 지역은 건너뛰고, 건너뛴 사실을 `singo-latest.json` 에 남긴다 |
| 역대 기록이 없는 칸의 첫 거래 | "첫 거래 = 신고가"는 사실이 아니다 |
| 직거래 | 특수관계인 거래가 섞여 시세로 읽기 어렵다. **다만 인덱스에는 넣는다** — 기록에서 빼면 직거래로 세워진 고점을 모르고 신고가라 부르게 된다 |
| 같은 금액 재거래 | 기록은 **최초로 그 값에 닿은 거래**다 |
| 세대수를 못 붙인 단지 | 추측해서 붙이지 않는다. 놓친 이름은 `singo-latest.json` 의 `unmatched` 에 남겨 다음에 고친다. **놓친 건 고칠 수 있지만 잘못 붙인 건 오보가 된다** |

## 4. 배관

```
 달력 11:40 KST ──▶ molit-peak-backfill.yml   2006-01~지난달을 나눠 훑어
                    (다 차면 스스로 조용해짐)   data/datasets/molit-peak/{구}.json 에
                                              단지+평형대별 역대 최고가만 남긴다
                                                      │
 달력 08:05 KST ──▶ singo-daily.yml ──────────────────┘
                    ① 최근 2개월 신고분 수집
                    ② 인덱스와 대조 → 넘어선 것만
                    ③ 세대수 붙여 1000세대 이상만
                    ④ 인덱스 갱신(내일의 기준)
                    ⑤ 텔레그램
```

| 파일 | 무엇 |
|---|---|
| `data/datasets/molit-peak/{lawdCd}.json` | 역대 최고가 인덱스. `meta.doneMonths` 가 진행 상황의 **유일한 진실** |
| `data/datasets/molit-peak/_progress.json` | 초기 수집이 얼마나 남았나 |
| `data/datasets/singo-latest.json` | 오늘 판정 결과 전건 (카드 빌더가 읽을 곳) |
| `data/datasets/apt-list/{lawdCd}.json` | 시군구별 공동주택 단지 목록 (세대수 매칭용) |
| `data/datasets/apt-hhld.json` | 단지코드 → 세대수 캐시 + 실거래 표기 매칭표 |
| `data/singo-alert.txt` | 텔레그램 문구 (0건이면 빈 파일 → heartbeat 로 대체) |
| `data/singo-last.md` | 마지막 실행 로그. **"안 왔는데?" 싶으면 여기부터 읽는다** |

### 원본 거래를 저장하지 않는 이유

2006년부터의 전 거래를 그대로 담으면 저장소가 수 GB 가 된다(현재 7개월치가 46MB).
신고가 판정에 필요한 건 "지금까지의 최고가" 한 줄뿐이라 그것만 남긴다.
카드를 만들 때 특정 단지의 시계열이 필요하면 그때 `molit-collect` 로 그 구·월만 받는다.

## 5. 필요한 것 (GitHub Secrets · 공공데이터포털 활용신청)

| 이름 | 쓰는 곳 | 상태 |
|---|---|---|
| `MOLIT_API_KEY` | 실거래 수집 | 이미 있음 |
| `TELEGRAM_BOT_TOKEN` · `TELEGRAM_CHAT_ID` | 알림 | 이미 있음(청약 알림이 쓰는 것) |
| 공공데이터포털 **공동주택 단지 목록제공 서비스** 활용신청 | 세대수 매칭 | **오너 확인 필요** |
| 공공데이터포털 **공동주택 기본 정보제공 서비스** 활용신청 | 세대수 | **오너 확인 필요** |

키 문자열은 같은 계정 인증키를 쓰지만 **서비스별 활용신청은 따로**다.
신청이 안 돼 있으면 `SERVICE_KEY_IS_NOT_REGISTERED` 가 나고, 그날 알림은
세대수 미확인으로 전건이 빠진다(로그에 그대로 찍힌다).
