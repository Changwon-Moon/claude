# 청약·분양 카드 기준 (오너 확정 2026-08-03)

> 이 문서는 **청약·분양 소재를 다루는 에이전트가 손대기 전에 읽는 문서**다.
> 2026-08-01~08-03 오너와의 전 대화에서 나온 지시·수정·실수를 한 곳에 모았다.
> 판형(`danji-cover@1`)의 치수는 `docs/TEMPLATES.md` §11 에, 여기엔 **왜 그런가**와
> **무엇을 하면 안 되는가**를 적는다.
>
> 같은 지적을 두 번 받으면 그건 오너의 잘못이 아니라 **이 문서의 실패다.**
> 새 지시를 받으면 카드만 고치지 말고 여기에도 한 줄 남긴다.

## 0. 원커맨드 — 오너가 이렇게 말하면

> "새 조감도 사진과 함께 **[단지명]** 청약 위릿 카드 만들어줘"

```bash
node scripts/danji-card.mjs "<단지명 또는 공고번호>" --photo <조감도 이미지> [--hook "한강뷰"]
```

이 한 줄이 다 한다:
**청약홈 수집분에서 단지 찾기 → 데이터셋 항목 만들기/갱신 → 조감도 설치(원본 보존) →
크롭 재계산 → 카드 빌드 → 렌더 → 디자인 QA → 아직 사람이 채워야 할 칸 보고.**

```
node scripts/danji-card.mjs "한강 푸르지오 리버프론트"
node scripts/danji-card.mjs 2026000367 --photo ~/uploads/riverfront.jpg --hook "한강뷰"
node scripts/danji-card.mjs "상동역 롯데캐슬" --no-render     # 카드 JSON 까지만
```

### 이 명령이 **일부러** 멈추는 지점

전용면적 구성·타입·**분양가**·동수·층수는 **청약홈 API 가 주지 않는다.** 스크립트는 이것들을
지어내지 않고, 데이터셋에 자리를 만든 뒤 *무엇을 어디서 채워야 하는지*(공고문 URL 포함)를
찍고 **멈춘다.** 평형이 비면 카드는 나오지 않는다 — 빈 표를 조용히 그리는 것보다 못 그리는 편이 낫다.

```
📝 입주자모집공고문에서 채워야 할 칸 — data/datasets/bunyang-danji-2026.json 의 "ah-2026000318"
   · areas — 전용면적별 타입 구성
   · buildings — 동수 / topFloor — 최고 층수
   · price.byArea — 면적별 분양가
   공고문: https://www.applyhome.co.kr/ai/aia/selectAPTLttotPblancDetail.do?...
```

채운 뒤 **같은 명령을 다시** 실행하면 끝까지 간다.

### 자동으로 채워지는 것 (손대지 않는다)

| 값 | 출처 |
|---|---|
| 단지명 · 주소(읍면동) · 총 세대수 · 시공사 | 청약홈 공고 |
| 특공일 · 1순위일 · **당첨자 발표일** · 입주예정월 · 분양가상한제 | 청약홈 공고 |
| **조감도 끌어올림(crop)** | 원본 크기에서 빌더가 계산 — §3 "사진" 참조 |
| 부제 날짜 · 제목 문형 · 대표평형 선택 · 열 수 | 코드 |

- 소재는 `data/applyhome-alert.txt` 보드(청약홈 자동 수집, 매일 08:00 KST)에서 고른다.
- **판형은 하나뿐이다.** 새 템플릿을 만들지 않는다.
- 발행 전 §5 게이트를 통과해야 한다.

### 손으로 돌릴 때 (디버깅·재생산)

```bash
node scripts/build-danji.mjs [날짜] [--only <id>]   # 데이터셋 전체 또는 한 곳
pnpm --filter @wirit/renderer render -- --data ../../data/out/_spike/danji-<slug>.json --out ../../data/out/_spike
pnpm --filter @wirit/renderer qa data/out/_spike/danji-<slug>.json
node scripts/doctor.mjs                             # 확정본 픽셀이 안 깨졌는지
```

## 1. 사실의 원천 — 오보 0

| 값 | 어디서 오는가 |
|---|---|
| 세대수 · 특공일 · 1순위일 · **당첨자 발표일** · 입주예정월 · 분양가상한제 | **청약홈 API**(`data/datasets/applyhome-latest.json`)에서 **코드가 직접 읽는다** |
| 동수 · 최고 층수 · 전용면적/타입 구성 · 분양가 | 청약홈이 주지 않는다 → 데이터셋에 사람이 넣되 **출처를 남긴다** |
| 경쟁률 | 받아 적지 않고 **계산한다**(`ratio()`). 보도값과 1 이상 벌어지면 **던진다** |

**규칙**

- 데이터셋과 청약홈이 다르면 빌더가 **예외를 던진다.** 사람이 눈으로 고르게 두지 않는다.
- LLM 이 숫자를 문장에 적어 넣지 않는다. 카드에 보이는 모든 수치는 코드가 데이터에서 뽑는다.
- **없는 값은 '미고지'로 남긴다.** 줄을 지우면 그 항목이 존재하지 않는 것으로 읽힌다.
- **1차 출처가 보도를 이긴다.** 실제 사례: 분양대행 사이트가 입주예정을 2029.7 이라 했지만
  청약홈 `MVN_PREARNGE_YM` 은 2031-01 이었다. 카드는 청약홈을 쓴다.
- **확인하지 않은 것을 함의하지 않는다.** 실제 사고: `general ?? total` 로 "총 2,432 / 일반분양
  2,432"를 찍어 조합원 물량이 없다고 **주장**했다. 근거가 없으면 그 줄을 만들지 않는다.
- **'역대 최고' 같은 최상급은 `record` 필드(근거 `by`·`via` 포함)가 있을 때만** 쓴다.

## 2. 카드가 말하는 것 (순서 고정)

1. 고정 부제 `오늘의 주요 청약 이슈 (YYYY.MM.DD)` — **날짜 자동**. 손으로 적으면 다음 카드에서 굳는다.
2. 조감도(표지)
3. 제목 — **한 줄**, 태백, 폭에 꽉 차게
4. 단지명(좌) · 주소(우, 로고 옆) — **한 행**에 아랫단을 맞춘다. 단지명 크기는 자동
5. **타입별 분양가(최고가 기준)** — 면적대마다 대표타입 하나씩 **전부**
6. 세대수 / 동수 / 최고 층수 (+ `APT 0,000세대, OT 000실`)
7. 특공 / 1순위 / 당첨자 발표 / 입주 예정
8. 특이사항 한 줄 — 분상제·전매제한 등 **확인된 것만**. 항목마다 앞에 작은 아이콘
   (💡 상한제 / 🔒 전매제한 / ⚠️ 투기과열지구). 본문보다 작고 옅게 — **글자를 이기지 않게** 둔다
9. 푸터 출처

### 제목 문형 (오너 확정 — 임의로 바꾸지 않는다)

```
{훅} 아파트 분양가 {N}억대?
```
훅과 금액 **둘 다 코발트**. 강조가 둘이지만 한 문장의 주어와 술어라 초점이 갈리지 않는다.
분양가가 없으면 규모 문형(`{훅} 아파트 {N}가구`)으로 자동으로 떨어진다.
훅은 `hook` 필드에서 온다 — 코드에 박지 않는다(박았다가 다른 단지에서 "한강뷰 … null억대?"가 나왔다).

### 무순위(줍줍) 카드 — 같은 판형, 세 칸의 뜻만 바뀐다

무순위는 **분양가를 청약홈이 주지 않는다**("사업주체 문의"). 그래서 같은 밴드가 다른 것을 말한다.

| 자리 | 분양 예정 | 무순위(`kind: "remndr"`) |
|---|---|---|
| 머리 밴드 | 타입별 분양가 | **전용면적별 잔여 세대** (줍줍에서 독자가 먼저 묻는 것) |
| 제원 | 세대수 / 동수 / 최고 층수 | **잔여 세대 / 블록 수** / 최고 층수 |
| 일정 | 특공·1순위·당발·입주 | **접수·당발·입주**(접수가 하루면 3칸) / 여러 날이면 시작·마감 4칸 |
| 제목 | `{훅} 아파트 분양가 {N}억대?` | `{훅} 무순위 줍줍 {N}세대` |

- **면적대별 잔여 세대 합 ≠ 총 공급이면 빌더가 던진다.** 블록별 공고를 합산할 때의 유일한 안전장치다.
- 블록이 여럿이면 특이사항에 `5개 블록(G5-1·3·4·5·11블록) 동시 접수` — 이름을 그대로 나열하면
  한 줄을 넘겨 푸터를 민다(검수가 잡았다). 접두어가 같으면 묶는다.
- **잔여 세대 값은 분양가보다 짧아 한 줄에 다섯까지** 들어간다(`cols ≤ 5`). 두 줄로 접히면
  종이 단이 길어져 푸터를 민다 — 열 수는 값의 길이가 정한다.
- **잔여 세대는 전체 대비로 읽힌다.** `총 1,640세대 중 / 150세대`(위는 회색 작게, 아래 숫자만
  코발트). 전체 세대수는 청약홈에 없으므로 `totalComplex` 가 있을 때만 얹는다.
- **강조는 여기 하나뿐.** 밴드의 주력 면적대는 칠하지 않는다 — 양쪽을 칠하면 강조가 둘이 된다.
- **동수를 알면 '5개 블록'보다 동수가 낫다.** 블록은 공고 편의상의 구분이고 독자가 궁금한 건 단지 규모다.
- 카드에 보이는 단위는 **'세대'로 통일**한다(오너 지시). '가구'를 쓰지 않는다.
- **무순위 일정에는 요일을 붙인다** — `8/4(화)`. 접수가 하루뿐이라 그 하루가 무슨 요일인지가
  곧 "내일 넣을 수 있나"다. 요일은 **코드가 날짜에서 계산한다**(손으로 적으면 다음 카드에서 틀린다).
  분양 예정 카드에는 붙이지 않는다 — 일정이 며칠에 걸쳐 있어 요일 가치가 낮고, 4칸이라
  가장 긴 칸이 공통 수치 크기를 통째로 끌어내린다.
- **무순위 접수일은 코발트**(`schedule[].hi`). 이 카드에서 색이 있는 곳은 잔여 세대와 접수일
  둘 — '얼마가' 와 '언제까지' 가 줍줍 카드의 두 축이라 오너가 그렇게 정했다.

### 대표평형

84A~D 가 여러 개여도 면적대마다 **하나만** 적는다.
고르는 순서는 ① 주력 면적대(`mainArea`) ② 국민평형 84㎡ ③ 타입이 가장 많은 면적대.

## 3. 판형 — 무엇을 건드리면 안 되는가

치수는 `docs/TEMPLATES.md` §11. 여기선 **원칙**만.

- **떠 있는 상자를 만들지 않는다.** 오너의 결정적 지적: *"사진도 아래 박스도 나뉘어져 보인다."*
  원인은 종이 위에 얹힌 모서리 둥근 사진 + 모서리 둥근 잉크판이었다.
  지금 판형에 덩어리는 **표지와 종이 둘**뿐이고, 경계는 그라데이션 하나와 괘선이다.
- **AI티 금지** — 큰 라운드 + 옅은 회색 채움 상자. '카드처럼 묶기'가 필요하면 **괘선**으로 한다.
- **강조는 한 군데.** 흰 영역에서 색을 쓰는 곳은 주력 면적대 **금액** 하나.
  빨강(`--wirit-red`)은 **상승·과열 시그널 전용**이다. 분양가에 쓰지 않는다.
- **글자 크기는 세 종류.** 제목 / 공통 수치(타입·금액·제원·일정을 **한 자로** 잰다) / 라벨 26px.
  (+ 특이사항 34, 내역 24) 이보다 늘리지 않는다. `@2` 에는 크기가 열 종류, 여백이 아홉 종류였다.
- **서체**: 제목만 태백. **흰 영역 전부 프리텐다드.** 숫자가 열 개 넘게 깔리면 디스플레이
  서체는 획이 뭉쳐 읽히지 않는다.
- **단위는 크기 그대로, 색만 회색.** `2,682세대` 는 숫자와 단위가 한 낱말이다.
- **아래 단(제원·일정)은 칸마다 가운데 정렬.** 단, 라벨(특별공급·1순위…)과 내역(APT …)은
  값과 **왼쪽 선을 맞춘다** — 각자 가운데로 맞추면 짧은 라벨이 값 한가운데로 밀려 두 줄이
  어긋나 보인다. 구현은 라벨+값을 `.box` 로 묶어 **덩어리를 가운데**, 덩어리 **안은 왼쪽**.
  ⚠️ 그래서 폭 맞춤은 부모(`.box`, shrink-to-fit)가 아니라 **`.cell` 내용 폭**으로 잰다.
- **칸 여백은 좌우 대칭**(`padding: 0 22px`). 한쪽에만 주면 `text-align:center` 가
  '패딩 안쪽의 가운데'를 잡아 글자가 칸 중심에서 밀린다.
- **한 줄에 놓인 값들은 밑선이 같아야 한다.** 한 칸에만 회색 줄이 붙으면 그 칸의 값만 밀린다 →
  **없는 칸에 같은 높이의 빈 자리**를 만든다. 덩어리를 통째로 위/아래로 미는 방식은 안 된다 —
  줄이 위(`.abv`)에 붙는 카드와 아래(`.brk`)에 붙는 카드에서 방향이 반대다.
- **상자가 맞아도 글자는 어긋난다.** 프리텐다드 숫자는 52px 에서 잉크가 약 7.5px 안쪽에서
  시작하고, 한글 라벨은 24~26px 에서 약 2.5px 다. 그래서 회색 줄을 **5px 민다**.
  (캔버스·SVG 로 잉크를 재려 했지만 Chromium 은 둘 다 레이아웃 상자를 돌려준다 —
  렌더 PNG 실측값을 상수로 박고 근거를 주석에 남겼다.)
- **라벨을 지우는 것과 뜻을 지우는 것은 다르다.** 제원 라벨은 지웠지만
  층수엔 `pre:"최고"`, 결과 카드 경쟁률엔 `pre:"1순위"` 를 값 앞에 붙인다.
- **어두운 배경 위 브랜드 마크는 흰색으로 뒤집는다**(`filter: brightness(0) invert(1)`).
- **머리 규격은 불변**: 카드 패딩 72, 우상단 잉크 뱃지, 흰 3px + 잉크 12px 테두리, 잉크 푸터.
  `pnpm --filter @wirit/renderer audit-head` 가 판정한다.

### 사진

- **위치는 빌더가 계산한다 — CSS 에 숫자를 박지 않는다.**
  표지 사진 칸은 446px. 그림은 카드 폭(1080)에 맞춰 비율대로 그려지고, **남는 세로의 42.5%** 를
  위에서 걷어낸다(`build-danji.mjs` `heroShift` → `hero.shift`).
  한강 카드(1200×660 → 렌더 594 → 남는 148 → **63px**)가 오너가 승인한 값이고, 이 규칙이 그
  값을 그대로 재현한다. 사진을 바꾸면 값이 저절로 따라온다 — **손으로 옮겨 적지 않는다.**
- **가로로 너무 긴 사진은 던진다.** 1080px 폭에 맞췄을 때 세로가 446px 미만이면 표지 칸을
  못 채운다. 조용히 늘리지 않고 멈춘다.
- **조감도 원본 하단에는 대개 건설사 고지문이 박혀 있다.** 크롭이 원본 아래 5% 에 닿으면
  빌더가 경고한다. 잘리지 않으면 사진을 다시 받는다.
- **사진 위 출처 표기는 없다**(오너 지시). 대신 푸터 출처 줄에 남긴다 —
  조감도는 건설사 저작물이라 카드 어딘가에는 출처가 있어야 한다.
- **조감도가 없으면 노란 경고 뱃지가 뜬다.** 그 카드는 발행 금지다.
- 오너가 준 원본은 `templates/_shared/photos/_source/` 에 보존한다.

### 푸터 출처 줄

- **한 줄이어야 한다.** 넘치면 지울 것을 고른다 — 우선순위는
  ① 1차 출처(청약홈 입주자모집공고) ② 사진 출처 ③ 보도 ④ 날짜.
- `한국부동산원 청약홈` → `청약홈`. 청약홈은 한국부동산원이 운영하는 자체 브랜드다.
- **분양 예정 카드는 1차 출처만** 적는다. ⚠️ 이는 **분양가를 입주자모집공고문으로 확정한 뒤에야**
  참이 된다. 보도값을 둔 채 보도 출처만 지우면 **출처 없는 숫자**가 된다.
- **결과 카드는 보도를 남긴다** — 경쟁률이 실제로 거기서 왔기 때문이다.
  푸터의 유일한 기준은 "이 숫자가 실제로 어디서 왔는가"다.

## 4. 소재 자동 수집 (매일 08:00 KST)

```
청약홈 API ──→ .github/workflows/applyhome-collect.yml (0 23 * * * UTC)
           ──→ scripts/register-applyhome-ideas.mjs  (점수 ≥ 45 만 보드에 올림)
           ──→ data/applyhome-alert.txt → 텔레그램 알림 → 오너가 고른다
```

- 점수는 코드가 매긴다(지역·규모·무순위·마감임박·브랜드·규제).
- **같은 단지의 블록 분할은 합친다**(`mergeBlocks`). 안 하면 한 단지가 보드 상위 5칸을
  전부 차지한다. 단, `안산고잔2차` 의 '2차'는 블록 표기가 아니다.
- 만료·삭제된 자동 항목은 **오너가 손대지 않은 것만**(`state === ""`) 정리한다.
- 살아 있는 항목은 매일 **갱신**한다. 안 하면 D-N 이 굳는다.
- 이 세션 컨테이너에서는 GitHub API 를 못 쓴다. **큐 파일 push 가 유일한 트리거**다
  (`data/applyhome-queue.txt`).

## 5. 발행 게이트 — 하나라도 걸리면 발행 금지

- [ ] `pnpm --filter @wirit/renderer qa <카드>.json` → **error 0건**
- [ ] `pnpm --filter @wirit/renderer audit-head` → **규격 위반 0장**
- [ ] `node scripts/doctor.mjs` → 확정본 **픽셀 동일**
- [ ] 조감도 미확보 경고 뱃지가 **없다**
- [ ] **분양가를 입주자모집공고문으로 대조했다** (청약홈 API 는 분양가를 주지 않는다.
      보도값만 있는 카드는 나가지 않는다)
- [ ] 카드의 모든 수치가 코드 산출물이다 — 사람이 옮겨 적은 숫자가 없다
- [ ] 캡션에 1차 출처 링크(`source.url`)가 들어갔다

통과하면 `data/out/_spike/` → `data/content/{날짜}/` 로 옮기고 `node scripts/confirm.mjs <라벨>` 로
확정한다. 다만 **이 카드는 `pixel-baselines.json` 에 넣지 않는다** — 청약홈 수집분을 읽는데
그 데이터셋은 워크플로가 매일 갱신하므로, 접수가 끝나면 doctor 가 통째로 빨간불이 된다
(정기물을 기준값에 넣는 실수. `confirm.mjs` 머리 주석 참조).
**판형 회귀는 `templates/danji-cover/sample.json`(얼린 카드 JSON)으로 잰다.**

## 6. 이미 저지른 실수 (반복 금지)

| 실수 | 무슨 일이 있었나 | 규칙 |
|---|---|---|
| 렌더 출력을 `>/dev/null` 로 죽임 | 스키마 오류로 **렌더가 계속 실패하는데 옛 PNG 를 보며** "왜 안 바뀌지" 하며 시간을 썼다. QA 는 자체 임시 HTML 을 그리므로 통과했다 | **렌더 출력은 절대 죽이지 않는다** |
| 새 템플릿을 `designQa` `LEAF` 에 등록하지 않음 | 그 카드의 글자가 통째로 겹침 검사 **밖**에 있었다 | 템플릿을 만들면 `LEAF` 도 만진다. **빠진 요소는 없는 것과 같다** |
| 문장형 값과 큰 숫자를 같은 자로 잼 | "12개동 \| 최고 38층"이 세대수까지 끌어내렸다 | 공통 fit 그룹에는 **순수 수치만** |
| 훅을 코드에 박음 | 다른 단지에서 "한강뷰 … null억대?" | 문구 재료는 전부 데이터에서 |
| 사진 출처를 지우며 자리표시 경고까지 지움 | 대체 사진이 그 단지 조감도로 읽힐 뻔했다 | 출처를 지우는 것과 거짓을 허용하는 것은 다르다 |
| 4열 균등 분할 | 가장 긴 '2031년 1월'이 **모든 수치**를 52→41px 로 끌어내렸다 | 열 폭은 데이터가 정한다 |
| 탈락 시안을 남겨 둠 | 다음 사람이 무엇이 정답인지 다시 고민한다 | 고르고 남은 선택지는 **폴더째 지운다** |
| 한쪽에만 패딩을 주고 `text-align:center` | 글자가 칸 중심에서 14px 밀렸다(오너가 눈으로 잡았다) | **가운데 정렬은 패딩이 대칭일 때만 가운데다** |
| DOM 을 한 겹 감싸고 자를 안 고침 | 값의 부모가 shrink-to-fit 이 되자 폭 맞춤이 늘 "딱 맞음"을 반환 → 넘침 보호가 통째로 꺼질 뻔 | **감싼 DOM 을 자로 쓰던 코드는 조용히 거짓말을 시작한다** |
| 크롭 px 를 CSS 에 박음 | 다음 사진에서 하늘 비율이 틀어진다 | 사진에 딸린 수치는 **데이터로**(원본에서 매번 계산) |
| 빌드 대상 목록을 코드에 손으로 적음 | 새 단지를 넣어도 카드가 안 나온다 | 목록은 **데이터셋이 정한다** |

## 7. 오너와 일하는 법 (이 소재에서 실제로 그랬다)

- **오너는 세 번만 개입한다**: 소재 선택 / 기획 방향 / 발행 승인.
  그 사이의 판단은 우리가 한다. 판단을 미루려고 질문하지 않는다.
- **승인된 구성은 임의로 바꾸지 않는다.** 제목 문형·표기 형식은 오너가 고른 그대로 둔다.
- **지시와 원칙이 부딪히면 말한다.** 예: "푸터에서 파이낸셜뉴스를 빼 달라" →
  뺐지만 "분양가를 공고문으로 확정한 뒤에야 이 줄이 참이 된다"를 코드 주석과 보고에 남겼다.
- **한 번에 하나씩 고치고 매번 렌더해서 보여 준다.** 눈으로 보기 전에는 아무것도 확정되지 않는다.
- **같은 지적을 두 번 받았다면 이 문서에 그 줄이 없었다는 뜻이다.** 카드보다 문서를 먼저 고친다.
