# 관제탑 썸네일이 비는 이유 (2026-09-03)

> 새 코워크 컨테이너에서 `confirm.mjs` 가 **늘 같은 자리에서 멈췄다** —
> 「관제탑 스모크 309/311」, 실패는 **보관함 카드 실물 썸네일**과 **결재 화면에 나갈 카드 실물** 둘.
> 관제탑 코드에는 잘못이 없다. **아직 카드를 안 그린 것**이다.

## 무슨 일이었나

카드 PNG(`data/out`)와 콘텐츠 JSON(`data/content`)은 **gitignore** 다. clone 직후에는 없다.

```
data/out 이 비었다
  → collectProduced() 가 아무것도 못 찾는다
  → 보관함 item 54개의 thumb 이 전부 null (images 1개)
  → <span class="fthumb"></span> 만 나온다 (img 가 아니다)
  → 스모크의 `.folder img.fthumb` 가 0 → ❌
  → confirm.mjs 가 여기서 멈춰 **어떤 카드도 확정되지 않는다**
```

`scripts/build-tower-site.mjs` 머리말에 이미 적혀 있던 사실이다 —
*"로컬에서 그냥 돌리면 썸네일만 빠진 채로 조립된다."*
다만 **스모크는 그 사실을 말해 주지 않아서**, 다음 사람이 관제탑을 파게 된다.

## 고치는 법 — 관제탑이 아니라 렌더다

```bash
node scripts/render-sets.mjs        # 170장 · 10분 안팎. data/out 을 채운다
node scripts/build-archive.mjs      # 보관함 색인에 실제 PNG 경로를 붙인다
node scripts/stage-public-cards.mjs # 결재 화면이 쓰는 download/*.jpg
node scripts/build-tower-site.mjs
node scripts/smoke-tower.mjs        # → 311/311
```

⚠️ `rebuild-cards.mjs` 로는 **안 된다.** 그건 빌더와 검수를 돌릴 뿐 `data/out` 에 PNG 를
남기지 않는다(검수는 제 임시 자리에 그린다). 실제로 163장을 재생성하고도 PNG 는 3장이었다.

## 같이 고친 것 — `_spike` 를 페이지로 세던 버그

`stage-public-cards.mjs` 의 `pagesOf()` 가 `data/out` **아래 모든 폴더**를 훑었다.
거기엔 작업용 스크래치 `_spike` 가 섞여 있어, 같은 카드가 두 번 잡혀
**1장짜리가 2장으로 나갔다**(실측: `danji-mokdong` 이 2장으로 찍히고 결재 화면에
존재하지 않는 2번째 장 링크가 걸렸다). 밑줄로 시작하는 폴더는 날짜가 아니므로 건너뛴다.

## 재발 방지

`smoke-tower.mjs` 가 썸네일·실물 검사에서 실패하면 **위 명령을 그대로 찍어 준다.**
원인이 관제탑이 아님을 그 자리에서 알 수 있다.
