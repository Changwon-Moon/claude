# 관제탑 상시 운영 — 썸네일 문제 · private 저장소 문제를 0원으로 푸는 법

> 2026-07-25 작성. [control-tower-realtime.md](./control-tower-realtime.md) 1단계(고정 주소)에 걸린 두 가지 걸림돌의 해법.
> 결론 먼저: **둘 다 0원으로 해결됩니다.** 저장소는 계속 비공개로 두고, 썸네일도 다 나옵니다.

---

## 걸림돌 두 개, 원인부터

### 걸림돌 ① — Pages 버전에 카드 썸네일이 빠진다

**원인**: 완성된 카드 이미지(PNG)와 카드 데이터(`data/content/`)를 **저장소에 안 넣도록** 막아뒀습니다.
용량이 크고, 언제든 다시 만들 수 있는 결과물이라서요. 그래서 자동 배포 서버가 저장소를 받아 가면
**그릴 그림이 손에 없습니다.**

**핵심**: 이건 "이미지를 저장소에 넣어야 풀리는 문제"가 **아닙니다.**
카드를 만드는 **재료**(`data/datasets/` 실거래·정책 데이터 443개 파일)는 저장소에 다 들어 있습니다.
→ **배포할 때 그 자리에서 카드를 다시 그리면 됩니다.** 저장소는 그대로 깨끗하게 두고요.

### 걸림돌 ② — 비공개 저장소는 GitHub Pages가 유료다

맞습니다. GitHub Pages를 **비공개** 저장소에서 쓰려면 GitHub Pro(월 4달러 안팎)가 필요합니다.
무료 요금제에서는 저장소를 **공개**로 바꿔야만 됩니다.

**그런데 공개로 바꾸면 안 됩니다.** 소재 목록, 회사 판단 원칙, 팀 프롬프트, 제작 노하우가
전부 인터넷에 열립니다. 이 저장소의 가치가 곧 그 내용이라서요.

**핵심**: "GitHub Pages"가 유료인 것이지, **웹사이트를 공짜로 띄우는 방법이 없는 게 아닙니다.**
비공개 저장소를 무료로 배포해 주는 곳이 따로 있습니다.

## 해법 — 무료 조합

| | 무엇을 쓰나 | 왜 |
|---|---|---|
| **집(호스팅)** | **Cloudflare Pages** 무료 | 비공개 저장소도 무료로 배포. 용량·트래픽 넉넉 |
| **일꾼(빌드)** | **GitHub Actions** 무료분 | 이미 12개 작업이 여기서 돌고 있음. 카드 렌더도 여기서 |
| **문지기(비밀 유지)** | **워커 비밀번호 문** | 서버 측 검사. Access 대시보드 버그 회피(2026-07-26 교체) |
| **저장(3단계)** | GitHub 저장소 전용 토큰 | 이미 만들어져 있는 라이브 모드 그대로 |

**월 비용 0원.** GitHub Pro 결제 불필요, 저장소도 비공개 그대로입니다.

### 왜 이 조합인가

- **Cloudflare Pages**: 비공개 저장소를 무료 요금제에서도 배포합니다. `<이름>.pages.dev` 주소가 공짜로 나옵니다.
- **빌드를 GitHub Actions에서 하는 이유**: 카드를 그리려면 브라우저 엔진(Playwright)이 필요한데,
  이미 저장소 안에서 잘 돌고 있습니다. 검증된 곳에서 그리고 **결과물만 Cloudflare로 보냅니다.**
- **비밀번호 문**: 주소를 아는 사람은 누구나 들어올 수 있는 게 기본입니다.
  워커가 앞단에서 쿠키를 검사하므로, 비번을 모르면 파일 자체가 안 나갑니다.

> ⚠️ 각 서비스의 무료 한도·메뉴 이름은 바뀔 수 있습니다. 가입 화면에서 "Free" 요금제인지 한 번 확인하세요.

## 절차

### A. 오너가 할 일 (약 15분, 한 번만)

#### A-1. Cloudflare 무료 가입 (3분)
1. `dash.cloudflare.com` 접속 → **Sign up**
2. 이메일 + 비밀번호만 입력. **카드 등록 안 합니다.**
3. 도메인을 사라고 권하는 화면이 나오면 **건너뜁니다**(필요 없음)

#### A-2. Pages 프로젝트 만들기 (3분)
1. 왼쪽 메뉴 **Workers & Pages** → **Create** → **Pages** 탭
2. **Upload assets**(직접 업로드) 쪽을 선택
3. 프로젝트 이름에 `wirit-tower` 입력 → 생성
4. 만들어진 주소를 적어둡니다: `https://wirit-tower.pages.dev`
   *(내용은 제가 자동 배포로 채웁니다. 지금은 빈 껍데기여도 정상입니다.)*

#### A-3. Cloudflare 열쇠 만들기 (4분)
1. 우상단 계정 아이콘 → **My Profile** → **API Tokens** → **Create Token**
2. **Custom token** 선택
3. 권한(Permissions)에 **Account → Cloudflare Pages → Edit** 하나만 추가
4. 만든 **토큰 문자열**을 복사 (한 번만 보여줍니다)
5. Cloudflare 대시보드 오른쪽에 있는 **Account ID**도 복사

#### A-4. GitHub에 열쇠 넣기 (3분)
1. `github.com/Changwon-Moon/claude` → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret** 두 번:
   - 이름 `CLOUDFLARE_API_TOKEN` / 값 = A-3의 토큰
   - 이름 `CLOUDFLARE_ACCOUNT_ID` / 값 = A-3의 계정 ID

#### A-5. 문 잠그기 — 비밀번호 (2분) ※방식 변경 2026-07-26

> **원래 계획(Cloudflare Access)은 폐기했습니다.** 실제로 시도했더니 대시보드에서
> `use_clientless_isolation_app_launcher_url can only be enabled for apps with private destinations`
> 에러가 반복됐고(App Launcher 설정이 공개 주소와 충돌), Access가 `workers.dev` 주소를
> 실제로 보호하는지도 불확실했습니다. → **워커 코드 안에 서버 측 비밀번호 문**을 넣는 방식으로 교체.

브라우저에 심는 자바스크립트 비번(소스보기로 뚫림)이 아니라, **워커가 요청을 받아 쿠키를
검사한 뒤에만 파일을 내보내는** 구조라 실제로 막힙니다. 구현 = `packages/tower-worker/src/worker.js`.

1. `github.com/Changwon-Moon/claude` → **Settings → Secrets and variables → Actions**
2. **New repository secret**
   - 이름 `TOWER_PASSWORD`
   - 값 = 원하는 비밀번호 (기억하기 쉽되 추측하기 어려운 것)
3. 끝. 다음 배포부터 문이 걸립니다.

**동작**
- 주소를 열면 비밀번호 입력창 → 맞으면 30일간 유지(쿠키)
- 쿠키에는 비번이 아니라 해시가 들어가므로, 쿠키가 새도 비번은 복원 불가
- 검색엔진 색인 차단(`noindex`) 헤더 자동 부착
- 비번을 바꾸려면 GitHub 시크릿 값만 바꾸고 워크플로 재실행
- `/​__logout` 으로 로그아웃

> ⚠️ `TOWER_PASSWORD`를 **안 넣으면 관제탑이 공개 상태**가 됩니다(문이 없어서 잠기는 사고를 막는
> 설계). 배포 로그에 경고가 뜨니 확인하세요.

### B. 제가 할 일 (1세션)

1. 배포 워크플로를 Cloudflare용으로 새로 작성
   - 저장소 받기 → **카드 데이터·PNG를 그 자리에서 재생성**(썸네일 문제 해결)
   - 관제탑 HTML + 아이디어 보드 + `thumbs/*.png`를 한 폴더로 묶기
   - `wrangler pages deploy`로 Cloudflare에 업로드
2. 썸네일은 **HTML에 박아 넣지 않고 별도 파일**로 둡니다
   → 페이지가 가벼워지고, 브라우저가 이미지를 캐시해서 두 번째부터 빨리 열립니다
3. 매일 아침 자동 실행 + 원할 때 수동 실행 버튼

### C. 그다음 (실시간 3단계)

호스팅이 서면 [control-tower-live.md](./control-tower-live.md)의 **GitHub 저장소 전용 토큰**을 발급해
관제탑에 한 번 넣습니다. 그러면 ✓승인·✎수정·🗑삭제가 **누르는 즉시 저장소에 기록**됩니다.

이 토큰은 브라우저 안에만 저장되고, 권한은 이 저장소 하나로 묶여 있습니다.

## 자주 나오는 걱정

**"Cloudflare에 저장소 코드가 넘어가나요?"**
아닙니다. GitHub Actions가 **완성된 웹페이지 파일만** 보냅니다. 소스코드·데이터는 GitHub에 그대로 있습니다.

**"Actions 무료분을 다 쓰면요?"**
비공개 저장소는 월 2,000분이 무료입니다. 하루 한 번 5분 정도 도는 배포면 **월 150분 안팎**이라 여유롭습니다.
빠듯해지면 배포 주기를 이틀에 한 번으로 늦추면 됩니다.

**"주소가 노출되면요?"**
A-5의 비밀번호를 걸면 주소를 알아도 **비번 없이는 못 엽니다.**
`TOWER_PASSWORD`를 안 넣을 거라면, 주소를 아무 데도 공유하지 마세요.

**"나중에 GitHub Pages로 돌아갈 수 있나요?"**
됩니다. 배포 대상만 바꾸면 되고, 만들어 둔 워크플로는 대부분 그대로 씁니다.
