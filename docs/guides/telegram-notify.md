# 텔레그램 알림 설정 — "결정할 일 생겼어요" 를 폰으로 받기

> 2026-07-31 작성(카카오톡에서 전환). **비용 0원.** 약 **3분**, 한 번만 하면 됩니다.
> 결과: 발행 승인이나 고를 소재가 생기면 **텔레그램으로 알림이 오고, 눌러서 관제탑으로** 갑니다.

---

## 왜 텔레그램인가 (카카오톡에서 바꾼 이유)

카카오톡 "나에게 보내기"도 무료였습니다. 문제는 **준비와 유지비**였습니다.

| | 텔레그램 봇 | 카카오톡 "나에게 보내기" |
|---|---|---|
| 비용 | **무료** | 무료 |
| 준비 | 봇 만들기 **1단계** (3분) | 개발자 앱 → 로그인 활성화 → 동의항목 → 인가코드 → 토큰 변환 **5단계** (15분) |
| 토큰 만료 | **없음** | refresh token 을 **2개월마다 갱신** |
| 메신저에서 바로 승인 | 나중에 가능 | 불가(단방향) |

카카오는 켜 두면 끝이 아니라 두 달마다 손이 갔고, 실제로 **키가 등록되지 않은 채
알림이 조용히 안 가고 있던 기간**이 있었습니다. 텔레그램은 토큰이 만료되지 않아
한 번 켜면 계속 돕니다.

원래 설계로 돌아가는 것이기도 합니다 — `CLAUDE.md` 기술 결정에 승인 게이트는
**Telegram/Slack 봇**으로 적혀 있습니다.

---

## 오너가 할 일 (3분)

### 1단계 — 봇 만들기 (2분)

1. 텔레그램 앱에서 **@BotFather** 를 검색해 대화를 엽니다 (파란 체크가 붙은 공식 계정)
2. `/newbot` 을 보냅니다
3. 봇 이름을 물어보면: `wirit 관제탑` (아무거나 괜찮습니다)
4. 봇 아이디를 물어보면: `wirit_tower_bot` 처럼 **`bot` 으로 끝나는** 이름
   (이미 쓰이는 이름이면 다른 걸 요구합니다 — 숫자를 붙이면 됩니다)
5. 그러면 이런 답이 옵니다:

   ```
   Use this token to access the HTTP API:
   1234567890:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```

   이 **토큰**을 복사해 둡니다 → `TELEGRAM_BOT_TOKEN`

> ⚠️ 이 토큰은 봇의 비밀번호입니다. 저장소에 커밋하지 마세요.

### 2단계 — 내 대화 id 알아내기 (1분)

봇은 **먼저 말을 걸어준 사람에게만** 메시지를 보낼 수 있습니다. 그래서 한 번 말을 겁니다.

1. 방금 만든 봇을 검색해 대화를 열고 **아무 말이나** 보냅니다 (`안녕` 이면 충분)
2. 브라우저 주소창에 아래를 붙여넣습니다 — `<토큰>` 자리에 1단계 토큰을 넣으세요:

   ```
   https://api.telegram.org/bot<토큰>/getUpdates
   ```

3. 나오는 글자들 속에서 `"chat":{"id":123456789` 를 찾습니다.
   그 **숫자**가 `TELEGRAM_CHAT_ID` 입니다 (보통 9~10자리, 음수일 수도 있습니다)

> 아무것도 안 나오면(`"result":[]`) 2-1 에서 봇에게 말을 안 건 것입니다. 한 번 더 보내고 새로고침하세요.

### 3단계 — GitHub에 넣기 (1분)

1. `github.com/Changwon-Moon/claude` → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret** 을 두 번:

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계 토큰 |
| `TELEGRAM_CHAT_ID` | 2단계 숫자 |

3. 끝입니다. 이름을 **한 글자도 틀리지 않게** 넣으세요 —
   틀리면 에러 없이 조용히 건너뜁니다(`node scripts/check-secrets.mjs` 로 대조 가능).

## 확인하는 법

시크릿을 넣은 뒤 GitHub → **Actions** → `파이프라인 틱` → **Run workflow** 로 한 번 돌려보면
결정할 일이 있을 때 알림이 옵니다. 로그에 이렇게 찍히면 성공입니다:

```
📨 텔레그램 알림 전송 완료
```

시크릿을 아직 안 넣었다면 이렇게 나옵니다(정상 — 배포는 계속 진행됩니다):

```
⏭ 텔레그램 시크릿(TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID)이 없어 알림을 건너뜁니다.
── 보냈다면 이런 내용이었습니다 ──
```

로컬에서 문구만 시험해 보려면:

```bash
node scripts/notify-telegram.mjs "테스트입니다"
```

- **매일 아침 07:00 (KST)** 결정할 일이 있는지 확인하고, **있을 때만** 보냅니다
  → 할 일이 없으면 알림이 안 옵니다 (알림 피로 방지)
- 소재를 승인하거나 발행 승인을 눌러 저장소가 바뀌면 그때도 확인합니다
- 알림에는 **[관제탑 열기]** 버튼이 붙어 있어 한 번에 이동합니다

받는 메시지 예시:

           [ 관제탑 열기 ]

## 알아둘 것

**토큰은 만료되지 않습니다.** 카카오와 달리 주기적 갱신이 없습니다.
봇을 지우거나 BotFather 에서 토큰을 재발급하지 않는 한 계속 유효합니다.

**알림이 안 와도 파이프라인은 정상 동작합니다.** 시크릿이 없거나 전송이 실패해도
워크플로는 경고만 남기고 계속 진행합니다 — 알림 때문에 회사가 멈추면 안 되니까요.

**나중에 '메신저에서 바로 승인'을 붙일 수 있습니다.** 텔레그램은 버튼 응답을 받을 수 있어
카드 실물을 사진으로 보내고 그 자리에서 승인받는 것도 가능합니다.
다만 응답을 받아줄 서버(웹훅)가 필요해 별개 작업입니다 — 지금은 알림 + 링크까지입니다.

**토큰을 저장소에 커밋하지 마세요.** GitHub Secrets 에만 넣습니다.
