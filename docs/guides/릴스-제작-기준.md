## 원칙 — 릴스는 카드의 영상판이 아니다

| | 카드 | 릴스 |
|---|---|---|
| 목적 | 결론을 **한눈에** | 결론을 **최대한 늦게** |
| 성적표 | 저장·공유 | **완주율** |
| 길이 | — | 8~15초 (초기) |

카드를 그대로 넘기는 슬라이드쇼는 만들지 않는다. 3초에 답을 주면 3초에 이탈한다.

## 규격

- **1080×1920 / 30fps / H.264 / yuv420p / faststart**
- 정사각 카드를 그대로 쓰지 않는다. **세로 전용 레이아웃을 새로 짠다.**
- 안전영역: 상단 250px·하단 400px에 핵심 정보를 두지 않는다 (UI·캡션이 덮음)
- 워터마크 `@wirit_note` 는 하단 230px 위치, 마지막 2초에 페이드인

## 파이프라인 (결정적 렌더 유지)

```
HTML/CSS + window.setT(ms) 로 프레임 단위 상태 계산
      → Playwright 프레임 캡처 (frames/f0000.png …)
      → ffmpeg -framerate 30 -c:v libx264 -crf 18
```

**핵심: CSS 애니메이션에 시간을 맡기지 않는다.** `window.setT(ms)` 하나가 모든 요소의
상태를 계산하고, 캡처 루프가 그 함수를 프레임마다 호출한다. 같은 입력 = 같은 영상이 보장되고
md5 회귀도 그대로 걸 수 있다.

영상 생성 AI는 쓰지 않는다 (저장소 규칙).

## 템플릿 3종

| 형식 | 구조 | 소재 |
|---|---|---|
| **순위 카운트다운** | 하위 → 상위 순차 등장, 1위 마지막 | 최고가, 신고가 지역, 수주 순위 |
| **지도 순차 점등** | 구가 하나씩 채색 + 숫자 | 월세 지도, 신고가 지도 |
| **막대 성장** | 연도별 막대가 자라다 끝에서 급등 | 월세지수, M2 |

## 순위 카운트다운 타임라인 (프로토타입 확정값)

| 구간 | 시간 | 내용 |
|---|---|---|
| 후킹 | 0 ~ 1.7s | 질문 한 문장 + 큰 `?` (코발트) |
| 전환 | 1.7 ~ 2.0s | 후킹 페이드아웃, 타이틀 슬라이드인 |
| 리스트 | 2.0 ~ 8.3s | **8위 → 1위**, 한 줄당 0.9s, 바 성장 0.7s |
| 강조 | 8.3 ~ 9.5s | 1위 행 스케일 펄스(+4.5%) |
| 마감 | 9.8 ~ 12s | `@wirit_note` 페이드인 |

**1위를 맨 위 고정 슬롯에 두고 아래(8위)부터 채워 올린다.** 순위표 읽는 방향과 맞으면서
마지막에 1위가 채워지므로 끝까지 봐야 답이 나온다.

## 타이포

- 한글 **태백체**(굵기 1종) / 라틴·숫자 **Pretendard**(unicode-range 로 분리)
- 태백체는 굵기가 하나뿐 → **위계는 크기와 투명도로만** 잡는다
- 숫자가 Pretendard ExtraBold로 빠지면서 자연스럽게 강조된다

## 절대 규칙

- **오보 0** — 수치는 저장소 빌더가 원자료에서 추출한다. HTML에 손으로 적은 숫자로 발행하지 않는다.
- **픽셀 불변** — 릴스는 공용 템플릿을 건드리지 않고 **릴스 전용 variant** 로 격리한다.
  공용 `base.css` 를 고치면 이미 나간 카드가 조용히 바뀐다.

## 운영

- **카드는 매일, 릴스는 주 2~3개.**
- 인사이트에서 볼 지표: **완주율**, **이 릴스로 늘어난 팔로우 수.** 조회수는 결과지 원인이 아니다.
- 릴스 하나로 터지지 않는다. 10~20개 쌓는 동안 하나가 걸린다. 매번 새로 기획하지 말고
  템플릿에 데이터만 갈아끼우는 구조로 간다.
