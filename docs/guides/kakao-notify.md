# 카카오톡 알림 설정 — "결정할 일 생겼어요" 를 폰으로 받기

> 2026-07-26 작성. **비용 0원.** 약 15분, 한 번만 하면 됩니다.
> 결과: 발행 승인이나 고를 소재가 생기면 **카카오톡으로 알림이 오고, 눌러서 관제탑으로** 갑니다.

---

## 왜 카카오톡인가

관제탑을 매일 열어보러 가는 건 금방 지칩니다. 반대로 **결정할 일이 생겼을 때만 관제탑이 부르는** 게 맞습니다.

| | 카카오톡 "나에게 보내기" | 텔레그램 봇 | 카카오 알림톡 |
|---|---|---|---|
| 비용 | **무료** | 무료 | 건당 과금 |
| 준비물 | 카카오 계정 | 봇 생성 | **사업자등록·템플릿 심사** |
| 알림 + 링크 버튼 | ✅ | ✅ | ✅ |
| 메신저에서 바로 승인 | ❌ | ✅ | ❌ |

**승인은 어차피 관제탑 웹에서 합니다** — 카드 실물과 캡션을 봐야 하니까요.
알림은 "가서 보세요" 한 줄이면 충분하므로 **무료인 카카오톡**으로 갑니다.

> 나중에 "메신저에서 바로 승인"이 필요해지면 텔레그램을 **추가로** 붙이면 됩니다. 지금 고를 필요 없습니다.

---

## 오너가 할 일

### 1단계 — 카카오 개발자 앱 만들기 (5분)

1. `developers.kakao.com` 접속 → 우상단 **로그인**(평소 쓰는 카카오 계정)
2. 상단 **내 애플리케이션** → **애플리케이션 추가하기**
3. 입력:
   - 앱 이름: `wirit 관제탑`
   - 회사명: `wirit` (아무거나 괜찮습니다)
4. 만들어진 앱을 클릭 → 좌측 **앱 키** 메뉴
5. **REST API 키**를 복사해 둡니다 → 이게 나중에 쓸 `KAKAO_REST_API_KEY` 입니다

### 2단계 — 카카오 로그인 켜고 권한 주기 (5분)

1. 좌측 **카카오 로그인** → **활성화 설정**을 **ON**
2. 같은 화면 아래 **Redirect URI** → **등록** 을 누르고 이걸 그대로 입력:
   ```
   https://example.com/oauth
   ```
   > 실제로 접속하는 주소가 아닙니다. 카카오가 "인증 끝났다"고 돌려보낼 **형식상의 주소**이고,
   > 우리는 그때 주소창에 찍히는 값만 쓸 겁니다.
3. 좌측 **카카오 로그인 → 동의항목** → **카카오톡 메시지 전송**(`talk_message`) 을 찾아
   **설정** → **이용 중 동의** 로 바꾸고 저장

### 3단계 — 나에게 보내기 권한 받기 (5분)

이 단계는 주소창을 두 번 쓰는 게 전부입니다.

**3-1. 아래 주소에서 `여기에_REST_API_키` 부분만 1단계에서 복사한 키로 바꿔서 브라우저 주소창에 붙여넣고 이동합니다.**

```
https://kauth.kakao.com/oauth/authorize?client_id=여기에_REST_API_키&redirect_uri=https://example.com/oauth&response_type=code&scope=talk_message
```

→ 카카오 동의 화면이 뜹니다. **동의하고 계속하기**를 누릅니다.

**3-2. 그러면 `example.com` 으로 넘어가면서 페이지는 안 열립니다(정상입니다).**
**주소창**을 보면 이렇게 생겼습니다:

```
https://example.com/oauth?code=ABCDEF1234567890...
```

이 중 `code=` 뒤의 **긴 문자열만** 복사합니다. (이 값은 몇 분 뒤 만료되니 바로 다음 단계로)

**3-3. 이제 그 코드를 refresh token 으로 바꿉니다.**
아래 내용을 저에게 채팅으로 주시면 제가 변환해 드립니다:

- REST API 키
- 방금 복사한 `code` 값

> ⚠️ 이 두 값은 **채팅으로만** 주세요. 저장소에 커밋하면 안 됩니다.
> 제가 변환한 뒤 값은 화면에만 보여드리고 어디에도 저장하지 않습니다.

<details>
<summary>직접 하고 싶다면 (터미널을 쓸 줄 아는 경우)</summary>

```bash
curl -X POST "https://kauth.kakao.com/oauth/token" \
  -d "grant_type=authorization_code" \
  -d "client_id=<REST API 키>" \
  -d "redirect_uri=https://example.com/oauth" \
  -d "code=<3-2에서 복사한 code>"
```

응답 JSON 안의 **`refresh_token`** 값이 필요한 것입니다.
</details>

### 4단계 — GitHub에 넣기 (3분)

1. `github.com/Changwon-Moon/claude` → **Settings** → **Secrets and variables** → **Actions**
2. **New repository secret** 을 두 번:

| 이름 | 값 |
|---|---|
| `KAKAO_REST_API_KEY` | 1단계에서 복사한 REST API 키 |
| `KAKAO_REFRESH_TOKEN` | 3단계에서 얻은 refresh_token |

3. 끝입니다. 다음 날 아침 07:00부터 알림이 옵니다.

## 어떻게 동작하나

- **매일 아침 07:00 (KST)** 결정할 일이 있는지 확인하고, **있을 때만** 보냅니다
  → 할 일이 없으면 알림이 안 옵니다 (알림 피로 방지)
- 소재를 승인하거나 발행 승인을 눌러 저장소가 바뀌면 그때도 확인합니다
- 알림에는 **[관제탑 열기]** 버튼이 붙어 있어 한 번에 이동합니다

받는 메시지 예시:

```
[wirit 관제탑] 26.07.26(일)

🚀 발행 승인 대기 2건
  · 🔥 2026년 6월 신고가 쏟아진 지역은? (토허제 기준)
  · 2026년 국장 성적표 — 코스피·코스닥 고점 대비
💡 고를 소재 4건

              [ 관제탑 열기 ]
```

매일 쓰이면 카카오가 알아서 새 값을 내려주는데, 그때 Actions 로그에 이런 경고가 뜹니다:

> ⚠️ 카카오 refresh token이 갱신됐습니다. GitHub 시크릿 KAKAO_REFRESH_TOKEN을 새 값으로 바꾸세요.

이 경고를 보시면 저에게 말씀해 주세요 — 새 값으로 바꾸는 걸 도와드립니다.
(보안상 새 토큰 전체 값은 로그에 남기지 않고 앞 8자만 찍습니다.)

**알림이 안 와도 파이프라인은 정상 동작합니다.** 시크릿이 없거나 전송이 실패해도
워크플로는 경고만 남기고 계속 진행합니다 — 알림 때문에 회사가 멈추면 안 되니까요.

**토큰을 저장소에 커밋하지 마세요.** GitHub Secrets 에만 넣습니다.
