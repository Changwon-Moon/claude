# AI 팀 조직도 & 에이전트 스펙 v2

> 2026-07-19 전면 개정 (운영자 승인). **다작(多作)·수익화에 최적화된 닫힌 루프 조직**으로 재편:
> ① 만들기 전에 **수요를 검증**하고(트렌드분석팀 신설) ② 만든 자료는 **자산으로 재사용**하며(자료허브팀 신설) ③ 발행 성과가 **다시 소재 선정을 학습**시킨다(마케팅·성장팀 확장).
> 구 버전(v1, 6팀 선형 구조)은 git 히스토리 참조.

공통 원칙 (전 팀 불변):
- 모든 팀의 출력은 **파일 계약(JSON/md)** — 팀을 갈아끼워도 파이프라인은 돈다
- **수치를 창작하는 팀은 없다.** 수치는 raw에서 코드로 추출, `provenance` 필수
- 모든 판단은 **판단+근거+출처+확신도** 구조로 기록 ([CONTROL_TOWER.md](./CONTROL_TOWER.md) §1) — 관제탑에 자동 표출되고, 운영자 개입 기록과 함께 팀의 학습 데이터가 된다
- 자동화 수위: 각 팀은 R0(운영자 수동) → R1(보조) → R2(제안) → R3(자동)로 **개별 승급** ([RESEARCH_WORKFLOW.md](./RESEARCH_WORKFLOW.md) §2)

## 0. 전체 흐름 — 닫힌 루프

```
        ┌──────────────────────── 학습 루프 ♻️ ─────────────────────────┐
        ↓                                                              │
[트렌드분석] 수요 신호·패턴 ──┐                                          │
                            ├→ 6축 채점 → [기획] 편성·시리즈화            │
[리서치] 소재·데이터 가용성 ──┘         ↓                                │
                     [편집] 제작 ←── [자료허브] 자산·데이터셋 공급          │
                        ↓                                              │
                     [품질검수] 6항 체크 → 운영자 승인 게이트              │
                        ↓                                              │
                     [디자인] 렌더 → [마케팅·성장] 발행·확산 → 성과 회수 ──┘
```

핵심: 앞에 **수요 검증**, 뒤에 **성과 학습**이 붙어 원이 닫힌다. 다작할수록 루프가 빨리 돌고, 돌수록 잘 터지는 소재를 고르게 된다.

## 공용 채점 기준 — 6축 rubric (각 0~3, 합 18)

| 축 | 질문 | 채점 주체 |
|---|---|---|
| **수요** | 비슷한 게 실제로 터진 적 있나? 검색·트래픽 신호가 있나? | 트렌드분석팀 |
| 시의성 | 지금/이번 주여야 하는 이유가 있나 | 리서치팀 |
| 데이터 | 신뢰 가능한 1차 출처 숫자로 채울 수 있나 (없으면 즉시 탈락) | 리서치팀 |
| 저장가치 | 팔로워가 '저장'할 정보 밀도인가 | 리서치팀 |
| 관심폭 | 대중적(트래픽) vs 특정층(코어) | 트렌드분석팀 |
| 우리다움 | 경제 코어와 연결되나, 우리 톤에 맞나 | 기획팀 |

## 1. 트렌드분석팀 《신설》 — 수요 검증·패턴 발굴

> **미션: "만들기 전에 수요를 확인한다. 감이 아니라 반응 데이터."**

| 항목 | 내용 |
|---|---|
| 하는 일 | ① 레퍼런스·경쟁 계정의 **터진 콘텐츠를 분해**해 패턴화(소재×포맷×후킹×커버) ② **패턴 라이브러리** 구축·갱신 ③ 검색량·급상승 트렌드 신호 수집 ④ 우리 계정 성과 역분석(마케팅·성장팀 데이터 수신) |
| 입력 | 운영자 스크랩(터진 콘텐츠 링크), 구글/네이버 트렌드, 자체 계정 인사이트 |
| 출력 | `research/PATTERN_LIBRARY.md`(터진 공식 모음), 소재별 **수요 점수** + 근거, 주간 트렌드 리포트 |
| KPI | 수요 점수의 적중률 (높게 준 소재가 실제 평균 이상 성과) |
| 제약(정직) | 타 계정 성과는 API 수집 불가(인스타 정책) → **운영자가 주 1회 15분 스크랩**(링크 전달) + 팀이 분석하는 하이브리드. 검색·트렌드 신호는 완전 자동 |
| 자동화 | R0→R1(트렌드 자동수집)은 즉시, 패턴 분석은 R1 유지(스크랩 의존) |
| 모델 | 상위 (패턴 추출은 판단력 문제) |

## 2. 리서치팀 — 소재 발굴·데이터 확인

> **미션: "데이터 없는 아이디어는 소재가 아니다."**

| 항목 | 내용 |
|---|---|
| 하는 일 | 주제별(주: 부동산·주식·경제·통계·돈·부자 / 부: 기업·정책·인사·스포츠·트렌드) 신호 수집 → 소재 후보화, **1차 출처·데이터 가용성 확인**, 6축 중 시의성·데이터·저장가치 채점 |
| 입력 | 뉴스·트렌드 RSS(가동 중), 트렌드분석팀 수요 신호, 시즌 캘린더, 최근 30일 발행 이력(중복 방지) |
| 출력 | 일일 소재 보드 `research/briefs/{date}-auto.md` + 후보별 채점·근거 |
| KPI | 보드 후보 중 운영자 채택률 |
| 자동화 | R1 가동 중(자동 보드). R2(채점까지 자동 제안)는 결정 로그 축적 후 |
| 모델 | 상위 |

## 3. 기획팀 — 편성·시리즈 설계

> **미션: "단발이 아니라 시리즈로. 오늘의 1건은 내일의 10건."**

| 항목 | 내용 |
|---|---|
| 하는 일 | 채택 소재의 포맷·제목 시안·발행 슬롯 결정, **Tier 믹스 관리**(T1 60~70%/T2 25~35%/T3 0~15%), **시리즈 변주 설계**(같은 템플릿 × 파라미터로 N편 — 다작의 엔진), 콘텐츠 뱅크 재고 유지(7일치), 우리다움 채점 |
| 입력 | 채택 소재+6축 점수, 성과 가중치 테이블(마케팅·성장팀), 시리즈 카탈로그([CONTENT_STRATEGY.md](./CONTENT_STRATEGY.md) §3), 뱅크 재고 |
| 출력 | 기획안 `data/plans/{date}/plan-NNN.json` (포맷·제목 시안·데이터 명세·슬롯) |
| KPI | 주간 발행량(다작), Tier 믹스 준수율, 시리즈화 비율 |
| 자동화 | R0(운영자 결정) → 결정 로그가 쌓이면 R2(기획안 제안) |
| 모델 | 상위 |

## 4. 자료허브팀 《신설》 — 자산·데이터의 재사용 허브

> **미션: "한 번 쓴 자료는 자산으로. 두 번째부터는 공짜다."**

| 항목 | 내용 |
|---|---|
| 하는 일 | ① **비주얼 자산 라이브러리**: 로고·국기·지도·사진 — 전 자산에 출처·라이선스 태그 의무 ② **데이터셋 캐시**: 한 번 수집한 데이터(DART 연봉, 실거래가, 지수 시계열, 인구 통계)를 구조화 보관 → 다음 콘텐츠가 즉시 재사용 ③ 에버그린 재고 관리 ④ 없는 자산 요청 접수→조달 |
| 입력 | 편집팀 자산 요청, 수집기 raw, 운영자 업로드 |
| 출력 | `templates/_shared/{logos,flags,photos,maps}/` + `data/datasets/` 카탈로그 |
| KPI | **자산 재사용률**(허브에서 조달된 비율) — 높을수록 제작 시간 단가 하락 |
| **사진 정책** | 1순위 자체 렌더 그래픽 → 2순위 공공·보도자료·오픈라이선스 사진(허브 등록 후 사용, 출처 표기) → 3순위 없으면 표/차트로 우회. **언론사 사진 무단 전재 금지**. 상세: [TEMPLATES.md](./TEMPLATES.md) §5b |
| 자동화 | R1(수집기가 데이터셋 캐시 자동 적재), 비주얼 자산은 반자동(조달에 운영자 개입) |
| 모델 | 하위(카탈로그 관리) |

## 5. 편집팀 — 데이터 → 콘텐츠

> **미션: "모든 숫자에 출처 경로. 출처 없으면 카드 없다."**

| 항목 | 내용 |
|---|---|
| 하는 일 | 기획안+데이터(허브 캐시 우선)로 템플릿 콘텐츠 JSON 생성. **수치·순위·정렬 = 코드 도구**, 제목·라벨·요약 = 에이전트. 전 수치에 `provenance` 경로. 자산은 허브에서 slug 참조 |
| 입력 | 기획안, 데이터셋 캐시/raw, 템플릿 schema |
| 출력 | `data/content/{date}/content-NNN.json` |
| KPI | 검수 1회 통과율 |
| 자동화 | 정기 고정물은 R3 가동 중(pipeline). 일반 소재는 R1(세션 보조) → R2 |
| 모델 | 상위 (카피 품질 = 계정 톤) |

## 6. 품질검수팀 — 6항 체크리스트 게이트

> **미션: "오보 1건이 계정을 죽인다. 의심되면 막는다."**

| # | 검수 항목 | 방식 |
|---|---|---|
| 1 | 수치 = 원본 일치 (provenance 경로 대조) | 코드(기계 대조) |
| 2 | 순위·합계·단위 정합 (1위≥2위, % 합계 등) | 코드 |
| 3 | 출처 표기 존재·정확 | 코드+LLM |
| 4 | 저작권: 사진·로고가 허브 등록 자산인가 | 코드 |
| 5 | 가독성: 넘침·겹침·저대비·워터마크 (렌더 비전 검사) | LLM(비전) |
| 6 | 오해 소지: 제목-데이터 불일치, 과장, 상식 밖 수치 | LLM |

- **6항 전부 PASS여야 통과.** FAIL은 사유와 함께 편집팀 자동 반송(최대 2회, 이후 운영자 에스컬레이션)
- 출력: PASS/FAIL + 항목별 사유 (관제탑 티켓에 표출)
- 모델: 1·2·4는 코드, 5·6은 중간(비전)

## 7. 디자인팀 — 렌더 (결정적 코드)

> **미션: "동일 입력 = 동일 픽셀. 런타임에 창의성은 없다."**

- 렌더러(`packages/renderer`) + 템플릿 시스템(가동 중). 템플릿 추가·개선은 운영자×Claude 세션 협업으로, 런타임은 코드만
- 커버(1장) 변형 렌더 지원 → 마케팅·성장팀의 A/B 실험 대응 (향후)

## 8. 마케팅·성장팀 《확장》 — 발행·확산·성과 회수·수익화

> **미션: "저장과 공유가 팔로워를 만들고, 팔로워가 수익을 만든다."**

| 항목 | 내용 |
|---|---|
| 하는 일 | ① 캡션(훅+요약+출처)·해시태그 ② 발행 시간 최적화 ③ **커버 A/B 설계** ④ 발행(Graph API) ⑤ **성과 회수**: 도달·저장·공유·팔로우 전환 수집 → 성과 DB ⑥ **트렌드분석팀에 피드백**(루프의 마지막 조각) ⑦ 수익화 준비: 협찬 콘텐츠 규격, 프로필·링크 최적화, 광고 단가 근거 리포트 |
| 입력 | 승인된 콘텐츠, Instagram Insights API |
| 출력 | 캡션, 발행 스케줄, 성과 DB, 주간 성과 리포트, [소재×포맷] 성과 히트맵 |
| **KPI** | **저장률**(핵심)·공유율·팔로워 전환율·콘텐츠 단가(비용/발행)·주간 발행수 |
| 자동화 | 캡션 R2, 발행 R3(승인 후), 성과 수집 R3 |
| 모델 | 캡션 하위, 주간 리포트 상위 |

## 9. 총괄 오케스트레이터 — 파이프라인 구동 (코드 + 얇은 LLM)

- 상태 머신(티켓 단계 이동), 팀 호출 순서·재시도·에스컬레이션, 발행 슬롯 공백 시 뱅크 충원
- 운영자의 자연어 지시("이번 주 부동산 줄여줘")를 파라미터로 해석
- 관제탑(CONTROL_TOWER)은 이 상태의 시각화 — 1:1 대응

## 운영자(사람)의 자리

- **게이트**: 소재 채택(6축 보드에서 선택) / 최종 발행 승인 — 2곳
- **주 1회 15분**: 터진 콘텐츠 스크랩(트렌드분석팀 원료) + 주간 리포트 검토
- **수시**: 아이디어 추가(IDEAS.md), 자연어 수정지시 — 모든 개입은 기록되어 팀들을 학습시킨다
