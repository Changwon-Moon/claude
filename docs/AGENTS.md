# AI 에이전트 팀 상세 스펙

조직 구성: **리서치팀 → 기획팀 → 편집팀 → 디자인팀 + 품질관리(팩트체크·QA) + 성과분석**. 운영자(사람)는 "편집장"으로서 두 개의 승인 게이트에서만 결정한다.

공통 원칙:
- 모든 에이전트는 **파일 in / 파일 out** — 출력은 JSON 스키마로 검증되고, 스키마 불일치면 자동 재시도
- **수치를 창작하는 에이전트는 없다.** 수치는 항상 raw 데이터에서 코드로 추출되거나, `provenance` 경로가 붙어야 한다
- 에이전트별 시스템 프롬프트는 `prompts/{agent}.md`로 버전 관리 — 프롬프트 수정이 곧 "팀 교육"

---

## 1. 수집기 (Collectors) — 에이전트 아님, 결정적 코드

에이전트 이전에 도는 **원료 공급 장치**. LLM이 아니라 코드인 이유: 매일 같은 소스에서 같은 구조로 뽑는 작업은 결정적 코드가 더 싸고 정확하다.

| 항목 | 내용 |
|---|---|
| 실행 | 매일 04:00~06:00 cron, 소스별 독립 실행 (하나 실패해도 나머지 진행) |
| 출력 | `data/raw/{date}/{source}.json` — 소스별 정규화 스키마 |
| 실패 처리 | 3회 재시도 → Slack 알림 + 해당 소스 제외하고 파이프라인 계속 |
| 소스 목록 | [DATA_SOURCES.md](./DATA_SOURCES.md) 참고 |

## 2. 리서치팀: 리서치 에이전트

> "오늘 세상에 무슨 일이 있었고, 우리가 카드뉴스로 만들 만한 게 뭔가?"

| 항목 | 내용 |
|---|---|
| 입력 | 당일 raw 데이터 전체 요약, 뉴스 헤드라인/RSS, 최근 30일 발행 이력(중복 방지), 다가오는 일정(금통위, 월드컵 경기, 청약 일정 등) |
| 출력 | `briefs/{date}.json` — 소재 후보 8~12건. 각 건: 주제, 왜 지금인지(시의성 근거), 활용 가능한 데이터와 위치, 예상 포맷, 참고 링크 |
| 도구 | 웹 검색, raw 데이터 조회, 발행 이력 DB 조회 |
| 모델 | 상위 모델 (판단력이 중요) |

프롬프트 골격:
```
너는 데이터 인포그래픽 매체의 리서치 기자다.
오늘의 데이터와 뉴스에서 '숫자로 보여줄 때 더 흥미로운 이야기'를 찾아라.
기준: (1) 시의성 — 오늘/이번 주여야 하는 이유가 있는가
      (2) 데이터 가용성 — raw 데이터로 표/차트를 채울 수 있는가 (없으면 후보 탈락)
      (3) 저장 가치 — 팔로워가 '저장'할 만한 정보 밀도인가
      (4) 최근 30일 발행 목록과 중복되지 않는가
각 후보에 데이터 출처 경로를 반드시 명시하라. 데이터가 없는 아이디어는 제안하지 마라.
```

**정기물 처리**: "간밤의 미국 증시", "오늘의 한국 증시" 같은 데일리 고정 코너는 리서치를 거치지 않고 오케스트레이터가 직접 기획안을 생성한다(완전 자동 슬롯). 리서치 에이전트는 비정기·이슈성 소재에 집중.

## 3. 기획팀: 기획 에이전트

> "후보 중 뭘, 어떤 포맷으로, 언제 낼 것인가"

| 항목 | 내용 |
|---|---|
| 입력 | 소재 후보(briefs), 주간 발행 캘린더, 포맷별 최근 성과 통계, 콘텐츠 뱅크 재고 현황, **콘텐츠 전략 규칙([CONTENT_STRATEGY.md](./CONTENT_STRATEGY.md) §5 — Tier 쿼터, 시리즈 로테이션)** |
| 출력 | `plans/{date}/plan-NNN.json` — 오늘 발행 3~5건의 기획안. 각 건: 선정 사유·스코어, 템플릿 ID, 제목 시안 3개, 슬라이드 구성(캐러셀이면 장별 내용), 필요한 데이터 명세(어떤 raw의 어떤 필드), 발행 슬롯 |
| 스코어링 | `시의성(0-3) + 데이터확보(0-3) + 예상성과(0-3, 과거 유사 콘텐츠 성과 기반) + 캘린더 적합(0-1)` |
| 모델 | 상위 모델 |

**게이트 1이 여기 붙는다**: 기획안이 Slack/대시보드로 운영자에게 전달 → 승인/수정지시/반려. 수정지시(예: "제목 2안으로, 발행은 저녁으로")는 자연어로 받아 기획 에이전트가 기획안을 갱신한다.

성과 학습: 주간 성과 리포트가 산출한 [포맷 × 소재 카테고리]별 성과 테이블을 스코어링의 "예상성과" 항에 주입 — 계정이 성장할수록 기획이 좋아지는 지점.

## 4. 편집팀: 편집 에이전트 + 팩트체크 에이전트

### 4a. 편집 에이전트

> "기획안을 실제 콘텐츠 데이터로 만든다"

| 항목 | 내용 |
|---|---|
| 입력 | 승인된 기획안, 해당 raw 데이터, 템플릿의 `schema.json` |
| 출력 | `content/{date}/content-NNN.json` — 템플릿 스키마를 만족하는 렌더 입력 + `provenance` 맵 |
| 역할 분담 | **수치·순위·정렬 = 코드 도구 호출로 처리** (에이전트에게 `extract_values`, `sort_rank`, `format_krw` 같은 결정적 도구 제공). **제목·라벨·한 줄 요약·강조 포인트 선정 = 에이전트가 작성** |
| 문체 규칙 | 프롬프트에 명문화: 명사형 종결, 숫자 우선, 과장 금지, 단위 표기 규칙(억/만/%), 출처 표기 필수 |
| 모델 | 상위 모델 (카피 품질이 계정 톤을 결정) |

### 4b. 팩트체크 에이전트 (자동 게이트)

| 항목 | 내용 |
|---|---|
| 1차: 코드 검증 | `provenance` 경로를 따라 콘텐츠의 모든 수치를 raw 원본과 기계 대조. 합계·순위 정합성(1위 값 ≥ 2위 값 등), 단위 환산 검증. **불일치 = 즉시 반려** |
| 2차: LLM 검증 | 상식 범위 체크(기준금리 25%? 아파트 3천원?), 제목-데이터 불일치, 오해 소지 표현, 날짜 표기 오류 |
| 출력 | PASS / FAIL(사유) — FAIL이면 편집 에이전트로 자동 반송 (최대 2회, 이후 사람 에스컬레이션) |
| 모델 | 1차는 모델 불필요(코드), 2차는 중간 모델 |

이 이중 구조가 "오보 0건"의 근간이다. 인포그래픽 계정은 숫자 하나 틀리면 신뢰가 무너진다.

## 5. 디자인팀: 렌더러 + 디자인 QA 에이전트

### 5a. 렌더러 — 에이전트 아님, 결정적 코드

콘텐츠 JSON + 템플릿 → Playwright → PNG. 상세는 [TEMPLATES.md](./TEMPLATES.md). 디자인 품질은 템플릿 제작 시점(사람 + AI 협업)에 확보하고, 런타임에는 창의성이 개입하지 않는다 — 이것이 일관된 룩을 유지하는 방법.

### 5b. 디자인 QA 에이전트 (자동 게이트)

| 항목 | 내용 |
|---|---|
| 입력 | 렌더된 PNG (비전 입력) |
| 검사 | 텍스트 오버플로/말줄임 잘림, 요소 겹침, 빈 셀·깨진 로고 이미지, 대비 부족, 워터마크/출처 누락, 캐러셀 장수 일치 |
| 출력 | PASS / FAIL(문제 위치와 사유) — FAIL 시 파라미터 조정(폰트 축소 단계, 항목 수 축소) 후 자동 재렌더 |
| 모델 | 비전 지원 중간 모델 |

## 6. 발행팀: 캡션 에이전트 + 발행 스케줄러

| 항목 | 내용 |
|---|---|
| 캡션 에이전트 | 콘텐츠 JSON → 인스타 캡션(훅 문장 + 핵심 요약 + 출처 + 해시태그 10~15개). 계정 톤 가이드 준수. 모델: Haiku급 |
| 스케줄러 | 승인된 콘텐츠를 슬롯 시간에 Graph API로 캐러셀 발행. 실패 시 재시도 + 알림. 발행 결과(media id) DB 기록 |

**게이트 2가 발행 직전에 붙는다**: 대시보드/Slack에서 최종 이미지 + 캡션 확인 → 승인 시 예약 확정.

## 7. 성과분석팀: 인사이트 리포터

| 항목 | 내용 |
|---|---|
| 실행 | 발행 24h/72h 후 인사이트 수집(cron) + 매주 월요일 주간 리포트 |
| 입력 | Instagram Insights API (도달, 노출, 저장, 공유, 프로필 방문, 팔로우 전환) |
| 출력 | (1) 게시물별 성과 DB 적재, (2) 주간 리포트: [포맷 × 카테고리 × 발행시간]별 성과 분석 + 다음 주 기획 제언, (3) 기획 에이전트용 성과 가중치 테이블 갱신 |
| 모델 | 상위 모델 (주간 리포트만), 수집은 코드 |

## 8. 오케스트레이터 — 총괄 (코드 + 얇은 LLM)

- 상태 머신 구동, 에이전트 순차/병렬 호출, 재시도·에스컬레이션
- 데일리 고정 코너(증시 요약 등)의 기획안 자동 생성
- 발행 슬롯 공백 시 콘텐츠 뱅크에서 충원
- 운영자의 자연어 지시("오늘은 부동산 쉬고 월드컵 위주로")를 해석해 당일 파이프라인 파라미터에 반영하는 얇은 인터프리터

| 에이전트 | 모델 등급 | 호출 빈도 | 비고 |
|---|---|---|---|
| 리서치 | 상위 | 1회/일 | 판단력 중요 |
| 기획 | 상위 | 1~2회/일 | 성과 데이터 주입 |
| 편집 | 상위 | 건당 1~3회 | 도구 호출 다수 |

| 디자인 QA | 중간(비전) | 장당 1회 | |
| 캡션 | 하위(Haiku) | 건당 1회 | |
| 주간 리포트 | 상위 | 1회/주 | |
