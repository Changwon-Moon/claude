## 2. 이 판형이 만든 **새 오보 통로** — 호가

칸 이름이 `최근 실거래가`로 굳어 있으면 비교값이 호가여도 독자는 실거래로 읽는다. 그리고 안전마진 숫자가 그 위에서 계산된다.

구리역에서 실제로 갈렸다:

| 기준 | 금액 | 안전마진 |
|---|---|---|
| 같은 타입 **현재 최저호가** ← **채택** | 14.5억 | **5.7억** |
| 같은 단지 **분양권 실거래** (2025-12, 14층) | 11.87억 | 3.1억 |
| 인근 신축 실거래 (e편한세상인창어반포레 85㎡) | 13.5억 | 4.7억 |

규칙(문서에 박았다):

1. 칸 이름은 비교값의 성격을 그대로 쓴다 — `최근 실거래가` / `현재 최저호가` / `분양권 실거래`.
2. 다른 단지 시세를 쓰면 **칸 이름에 단지명을 적는다.**
3. 준공 전 단지는 매매 실거래가 없다 → 분양권 실거래가 가장 가깝고, 없으면 호가라고 적는다.
4. 호가를 쓸 땐 **최저호가**를 쓴다(오너 판단). 평균·상단은 카드를 부풀린다.
5. **캡션이 카드가 안 쓴 기준을 받는다.**

빌더가 던지는 것: `market.label` 없음 · `market.source` 없음 · 안전마진 ≤ 0.

## 3. 검수 도구를 하나 고쳤다 — `captionCrossCheck`

5번 규칙 때문에 **캡션 수치 대조 검사(`caption-number`)가 맞는 캡션을 막았다.**
그 검사는 "캡션은 카드가 말한 숫자만 다시 말한다"를 전제로 만든 것인데, 이 판형이 전제를 깼다.

검사를 끄지 않고 **관제탑에 값과 이유를 적어야만** 통과하게 했다:

```json
"captionCrossCheck": [
  { "value": "3.1", "why": "같은 평형 분양권 실거래 기준 마진 — 카드는 호가로 갔다" }
]
```

- `why` 가 없으면 통과 못 하고 **error**.
- 통과한 값은 리포트에 **info** 로 남는다 — 조용히 넘어가는 예외는 없다.
- ⚠️ `reviewCli` 는 `packages/pipeline` 을 cwd 로 돈다. 저장소 루트를 가정하면 `sets.json` 을 못 찾고 **조용히 빈 목록**이 된다(예외가 안 먹은 채 통과처럼 보인다). 위로 올라가며 찾게 고쳤다 — 같은 실수를 다른 검사에서 반복하지 말 것.
