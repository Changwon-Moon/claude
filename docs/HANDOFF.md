## §1. 시작 전 필수 — 이 환경이 공장인지 확인

```bash
pnpm install --frozen-lockfile     # 처음 한 번
node scripts/doctor.mjs            # 3~5분. 실제로 카드를 만들어 봅니다
```

진단기는 **말로 확인하지 않고 실제로 만들어 봅니다**:
빌더 실행 → 카드 JSON → 렌더 → **발행본 md5 대조** → 자동 검수.

| 결과 | 무슨 뜻 | 어떻게 해야 하나 |
|---|---|---|
| `✅ 카드를 만들 수 있습니다` | 이 환경은 공장이 맞다 | 정상 작업 시작 |
| `❌ 만들 수 없습니다` | 렌더·검수가 안 돈다 | **카드 픽셀을 건드리지 마세요.** 기준·기획·캡션 같은 문서 작업만 |

> ⚠️ **가장 위험한 상태**: 렌더가 안 되는 환경에서 "설명은 다 되니까" 카드를 고치는 것.
> 그러면 검수가 사람 눈으로 돌아가고, 그게 오보 0이 깨지는 지점입니다.
> 진단기가 ❌면 오너에게 **"이 환경에서는 카드 제작을 못 합니다"라고 분명히 말하세요.**

**A등급(필수)만 통과하면 카드 제작은 됩니다.** B등급(API 키)은 *새 데이터 수집*에만 필요하고,
없어도 `data/datasets/`의 기존 데이터로 카드는 나옵니다.

## §3. 이 공장의 구조

```
데이터 수집 → 데이터셋 → 빌더 → 카드 JSON → 렌더 → PNG
 (API·Actions)  (검증됨)   (코드)   (계약)   (Playwright)
                                              ↓
                                        자동 검수(designQa)
                                              ↓
                                    캡션 → 검수 리포트 → 발행 대기
```

| 층 | 어디에 | 무엇을 보장하나 |
|---|---|---|
| **데이터셋** | `data/datasets/*.json` | `meta.verified: true`인 것만 카드가 될 수 있다. `meta.unit`으로 단위 확정 |
| **빌더** | `scripts/build-*.mjs` | 수치를 **코드로** 추출. provenance 기록. 가드에 걸리면 던진다 |
| **템플릿** | `templates/{이름}/` | HTML/CSS + `schema.json`(입력 계약) + `config.json`(크기) |
| **렌더러** | `packages/renderer` | Playwright 스크린샷. 동일 입력 = 동일 픽셀 |
| **검수** | `packages/renderer/src/designQa.ts` | 좌표를 **실측**해 겹침·넘침·정렬을 잡는다 |
| **명세** | `data/review/{builders,sets,pixel-baselines}.json` | 무엇을 만들고·무엇을 발행하고·픽셀 기준이 뭔지 |

### 왜 이미지 생성 AI를 안 쓰나
텍스트·숫자 정확도가 보장되지 않고, 매번 결과가 달라 브랜드 일관성이 무너지고,
무엇보다 **회귀 검증이 불가능**해집니다. HTML/CSS는 픽셀 단위로 재현됩니다.

## §4. 자주 쓰는 명령 (이게 사실상 전부입니다)

```bash
# 카드 전체 재생성 + 자동 디자인 검수 15장  ← 내보내기 전 필수
node scripts/rebuild-cards.mjs

# 관제탑 화면 스모크 (97항)
# ⚠️ 갓 clone 한 환경이면 먼저 아래 "관제탑 다시 생성"을 돌립니다 —
#    폰트·썸네일은 gitignore 대상이라 clone 직후에는 없습니다(§4 맨 아래 주석 참고)
node scripts/smoke-tower.mjs

# 환경 자가진단 + 발행본 픽셀 회귀
node scripts/doctor.mjs

# 카드 한 장만 렌더 (경로는 절대경로로!)
pnpm -s --filter @wirit/renderer render --data /절대경로/카드.json --out /출력폴더

# 디자인 검수만
pnpm -s --filter @wirit/renderer qa data/content/{날짜}/{카드}.json

# 발행 전 종합 검수(결정성 + QA + 캡션 린트) → data/review/{label}.json
cd packages/pipeline && pnpm -s review /절대경로/카드.json \
  --caption /절대경로/캡션.txt --label {label} --out /절대경로/data/review

# 관제탑 다시 생성 — 이걸 쓰세요(폰트 복사 + _site 조립까지 한 번에)
node scripts/build-tower-site.mjs

# (참고) 상태·HTML 만 다시 만들기 — 폰트는 복사하지 않습니다
pnpm -s --filter @wirit/dashboard-static all
```

**`error`가 하나라도 있으면 내보내지 않습니다.** `warn`은 이유를 대고 넘길 수 있습니다.

## §5. 새 카드 하나 만드는 전체 흐름

> ⚠️ **단계마다 오너 승인을 받습니다**(2026-07-31 오너 지적).
> ① 어떤 소재로 갈지 → ② 어떤 형태·제목으로 그릴지 → ③ 제작 → ④ **확정 후** 캡션.
> 한 번에 완성해 넘기면 오너는 되돌릴 수 없는 상태로 받게 됩니다.
> **캡션은 카드가 확정된 뒤의 일입니다** — 카드가 바뀌면 캡션도 버려집니다.

1. **소재 확정** — `research/ideas.json`에 있거나 오너가 채팅으로 줍니다
2. **데이터 확인** — `data/datasets/`에 있나? 없으면 수집기부터(§6). `verified: true`인가?
3. **템플릿 선택** — `docs/TEMPLATES.md`. 기존 것으로 되면 **새로 만들지 않습니다**
4. **빌더 작성** — `scripts/build-{이름}.mjs`
   - 수치는 전부 데이터에서 계산. 손으로 적은 숫자 0개
   - "역사상 최고"·"전체"·"N년 연속" 같은 말은 **계산이 확인했을 때만** 나가게 게이트
   - 단위 환산은 `meta.unit` 확인 후. 아니면 throw
5. **렌더 → 검수** — `designQa` error 0
6. **캡션 작성** — 빌더가 생성합니다(손으로 적으면 다음 갱신에 카드와 어긋남).
   `data/review/captions/{label}.txt`
7. **등록** — `data/review/sets.json`(발행 단위) + `builders.json`(재생산).
   **등록해야 관제탑에 뜹니다**
8. **종합 검수** → `data/review/{label}.json`에 PASS
9. **오너에게 렌더 PNG 전송** — 눈으로 볼 수 있는 형태로
10. 오너가 "확정"하면 → `pixel-baselines.json`에 md5 추가

### 오너가 기사 링크를 줬을 때 (버튼 누르지 않게)

작업 세션은 네이버·다음을 못 읽고, GitHub **API** 도 막혀 워크플로를 직접 실행하지 못합니다.
하지만 **git push 는 됩니다.** 그래서 푸시를 방아쇠로 씁니다:

```bash
echo "https://n.news.naver.com/…" >> research/article-queue.txt
git commit -am "기사 요청" && git push        # ← 이 푸시가 워크플로를 깨운다
```

`기사 읽어오기` 워크플로가 브라우저로 본문을 읽어 `research/articles/{날짜}-{슬러그}.md`
에 커밋하고 대기열을 비웁니다. 1~3분 뒤 `git pull` 하면 기사가 와 있습니다.

> **오너에게 "GitHub 에서 Actions 를 눌러 주세요"라고 하지 마세요.** 그러면 자동화가 아닙니다.
> 링크를 받으면 세션이 대기열에 적어 푸시하고, 기사가 올 때까지 기다렸다가 이어서 진행합니다.

결과는 성공·실패와 무관하게 `research/article-fetch-last.md` 에 적힙니다.
세션은 Actions 로그를 볼 수 없으므로(GitHub API 차단) **이 파일이 유일한 눈입니다.**

#### ⚠️ 네이버 모바일 기사(`n.news.naver.com/mnews/…`)는 이 통로로 못 읽습니다 (2026-07-31 확인)

다섯 번 시도해 확인한 사실입니다. 다음 사람이 같은 길을 다시 파지 않도록 적어 둡니다.

| 관측 | 뜻 |
|---|---|
| HTTP 200 · HTML 337KB | 봇 차단 화면이 아니다. 페이지는 정상으로 온다 |
| `body.innerText` 0자 · `document.title` 빈 문자열 · **`location.href` 까지 빈 문자열** | 브라우저 안 실행 컨텍스트가 깨져 있다 |
| HTML 을 Node 에서 직접 파싱해도 본문 컨테이너 없음 | 초기 문서에 본문이 없다(클라이언트 렌더) |

주소가 멎을 때까지 대기, `networkidle` 재시도, 모바일 선택자 추가,
`page.content()` 직접 파싱, **PC 주소(`news.naver.com/main/read.naver?oid=…&aid=…`)로 우회**
— 다섯 갈래를 다 시도했고 전부 같은 결과였습니다.
PC 주소는 네이버가 **다시 모바일로 되돌려 보냅니다**(최종 주소가 `n.news.naver.com` 으로 찍힘).
구 PC 주소 체계는 폐지돼 우회로가 아닙니다.

`page.evaluate` 가 아예 `undefined` 를 돌려주기도 합니다 — DOM 접근 자체가 막힌
안티봇 동작으로 보입니다. **선택자나 대기 시간의 문제가 아닙니다.**

> 📌 `research/articles/` 의 기존 두 건도 **전부 오너가 본문을 붙여 준 것**입니다
> ("확보 경로: 오너가 본문을 직접 붙여주심"). 이 통로로 네이버를 읽어낸 적은 **한 번도 없습니다.**
> 다음 세션이 "예전엔 됐는데" 하고 다시 파지 않도록 못 박아 둡니다.

**✅ 언론사 자체 도메인은 됩니다.** 세션이 `mobile.newsis.com` 을 직접 읽어냈습니다(2026-07-31).
네이버 기사 하단의 "기사원문" 링크가 그것입니다 — **오너에게 그 링크를 달라고 하는 게 1순위**입니다.

**그래도 안 되면**: 오너에게 **기사 화면 캡처**나 본문을 받습니다.
`fetch-article.mjs` 가 처음부터 그렇게 적어 두었습니다 —
*"우회를 억지로 시도하지 않는다. 오너에게 본문을 받는 편이 빠르고 정직하다."*
캡처 한 장이 왕복 다섯 번보다 빠릅니다. **다른 언론사 자체 도메인 링크가 있으면 그건 됩니다.**

## §7. 관제탑 (웹 화면) — 지금은 축소돼 있습니다

2026-07-30 오너 승인으로 **탭 5종**만 남았습니다: 발행 · 소재 · 보관함 · 회사 · 자산.

**관제탑이 하는 일**은 셋뿐입니다:
1. **발행 결재** — 카드 실물·캡션 확인 → `🚀 발행 승인`
2. **발행 기록** — 인스타에 올린 뒤 `✅ 인스타에 올렸습니다`
   (자동 발행을 안 하므로 **오너만 알 수 있는 사실**입니다. 이 버튼이 없어 시스템이
   "발행 0건"이라고 거짓 보고한 적이 있습니다)
3. **소재 조망 · 보관함 열람**

**폐지된 것**: 결정함 · 파이프라인 칸반 · 지시함 · 요청 대장 · 성과 탭.
→ **소재 등록·제작·수정 지시의 단일 입구는 채팅(작업 세션)입니다.**
버튼은 실행 능력이 없어 "접수"만 되므로, 관제탑 경유는 한 단계 우회였습니다.

## §8. 절대 하지 말 것

| 금지 | 왜 |
|---|---|
| **수치를 LLM이 만들게 하기** | 오보 0의 근간. 반드시 코드로 추출 + provenance |
| **발행본·확정본 픽셀 바꾸기** | 그날 무엇을 발행했는지의 증거가 사라짐. 새 스타일은 **variant로 격리** |
| **API 키 커밋** | GitHub Secrets 또는 `.env` |
| **렌더에 타임스탬프·랜덤 넣기** | 결정성이 깨지면 회귀 검증이 불가능 |

| **오너 메모의 수치를 그대로 받아 적기** | 계산값과 다르면 계산값을 쓰고 차이를 보고 (9.6% 요청 → 계산값 9.2%) |

새 검수항을 넣었으면 **일부러 어긋나게 되돌려 실제로 잡히는지 확인**합니다.

**자산은 창구가 아니라 저장소에 있습니다.** 이 저장소를 붙이는 순간
