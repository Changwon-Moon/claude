# 디자인 템플릿 시스템 — "무한 생산"의 핵심

참고 계정(@flow, APT_LAP)의 비밀은 화려한 디자인이 아니라 **철저한 템플릿화**다. 같은 레이아웃에 데이터만 갈아끼우기 때문에 매일 생산이 가능하고, 팔로워는 "익숙한 틀 + 새로운 정보"로 즉시 소비한다. 우리 시스템은 이것을 코드로 구현한다.

## 1. 렌더링 방식

**HTML/CSS 템플릿 + JSON 데이터 바인딩 → Playwright(headless Chromium) 스크린샷 → 1080×1350 PNG**

이미지 생성 AI를 쓰지 않는 이유:
- 텍스트·숫자 정확도가 보장되지 않는다 (인포그래픽에 치명적)
- 매번 다른 결과 = 브랜드 일관성 붕괴
- HTML/CSS는 픽셀 단위로 재현 가능하고, 웹 개발 역량으로 무한히 개선 가능

```
templates/
├── _shared/                    # 공통 자산
│   ├── base.css                # 브랜드 토큰: 컬러, 폰트, 간격, 워터마크
│   ├── fonts/                  # Pretendard 등 (라이선스 확인된 폰트)
│   ├── logos/                  # 기업·기관·국기 로고 라이브러리 (핵심 자산!)
│   └── components/             # 헤더, 출처 표기, 순위 배지, 증감 화살표 등
├── ranking-table/
│   ├── template.html           # Handlebars/EJS 템플릿
│   ├── schema.json             # 입력 데이터 계약 (JSON Schema)
│   ├── sample.json             # 샘플 데이터 (개발·회귀 테스트용)
│   ├── config.json             # 항목 수 범위, 폰트 축소 단계, 변형 옵션
│   └── preview.png             # 샘플 렌더 결과
└── ...
```

- **로고 라이브러리**가 의외의 핵심 자산이다. 참고 계정 콘텐츠의 정보 밀도는 기업 로고·국기·대학 엠블럼에서 나온다. 초기부터 `logos/{slug}.png` 컬렉션을 체계적으로 구축하고, 편집 에이전트가 slug로 참조한다. 없는 로고는 QA에서 걸려 사람에게 요청.
- **버전 관리**: 템플릿 ID는 `ranking-table@1`처럼 버전을 포함. 콘텐츠 JSON이 참조하는 버전이 고정되므로 과거 콘텐츠 재렌더가 항상 가능.

## 2. 초기 템플릿 라인업 (참고 계정 역설계 기반 8종)

| # | 템플릿 | 설명 | 참고 사례 | 자동화 난도 |
|---|---|---|---|---|
| 1 | `ranking-table` | 순위 + 로고 + 수치 1~3열 표 | 건설사 연봉, 부자 순위, 감독 연봉 | ★ 쉬움 |
| 2 | `vs-compare` | 2개 대상 항목별 비교 (좌우 대칭) | 삼성전자 vs SK하이닉스 | ★ 쉬움 |
| 3 | `market-daily` | 빅넘버 3개 + 1년 차트 + 종목 등락 그리드 | 간밤의 미국 증시, 오늘의 한국 증시 | ★ 쉬움 (완전 자동 슬롯) |
| 4 | `timeseries-story` | 시계열 차트 + 주석 (스토리텔링형) | 기준금리 추이, 하이먼 민스키 | ★★ 중간 |
| 5 | `map-region` | 지도 + 지역별 수치 라벨 | 동작구 동별 APT, 재산세 지도 | ★★★ 어려움 (지도 SVG 준비 필요) |
| 6 | `share-donut` | 점유율 도넛/블록 + 로고 | 파운드리 점유율, 낸드 점유율 | ★ 쉬움 |
| 7 | `bracket` | 대진표 (토너먼트) | 월드컵 대진표 | ★★ 중간 (시즌성) |
| 8 | `info-grid` | 아이콘/로고 그리드 + 짧은 설명 | 8대 국제학교, 정책 총정리 | ★★ 중간 |

전략: 1·2·3·6번(쉬움)으로 런칭 → 4·8 추가 → 5·7은 니치 확정 후. **3번 market-daily는 데이터가 100% API로 나오므로 첫 번째 "완전 무인 콘텐츠"로 만들어 매일 발행 기반을 깐다.**

## 3. 템플릿 제작 프로세스 (사람 + AI 협업, 템플릿당 1~3일)

1. 참고 게시물 3~5개를 골라 레이아웃 요소 분해 (헤더/표/강조/출처/워터마크)
2. AI(Claude)에게 HTML/CSS 초안 생성 요청 → 사람이 디테일 튜닝 (여백, 폰트 크기, 밀도)
3. `schema.json` 확정 — **여기서 엣지 케이스를 미리 설계**: 항목이 5개일 때/15개일 때, 이름이 길 때, 값이 음수일 때
4. `config.json`에 자동 대응 규칙: 항목 수에 따른 행 높이 조정, 텍스트 길이에 따른 폰트 축소 3단계, 말줄임 규칙
5. 샘플 데이터 10종으로 렌더 회귀 테스트 → 통과 시 등록

## 4. 렌더러 구현 스펙

```bash
# CLI
render --data content/2026-07-18/content-001.json --out out/2026-07-18/
# → content-001-p1.png, content-001-p2.png ... (캐러셀 다중 페이지)
```

- 입력 JSON을 템플릿 `schema.json`으로 검증 → 실패 시 명확한 에러 (편집 에이전트가 읽고 수정할 수 있는 메시지)
- Playwright: viewport 1080×1350, deviceScaleFactor 2 (레티나 품질), 폰트 로딩 대기 후 캡처
- 캐러셀: 콘텐츠 JSON의 `pages[]` 배열 → 페이지별 캡처
- 차트: 렌더 전에 서버사이드 ECharts로 SVG 생성 → 템플릿에 인라인 삽입 (스크린샷 시점 애니메이션 이슈 방지)
- 결정성: 동일 입력 = 동일 픽셀 출력 (타임스탬프·랜덤 요소 금지) → QA와 회귀 테스트 가능

## 5. 브랜드 시스템 (base.css 토큰)

> **컬러·워터마크·타이포는 [BRAND.md](./BRAND.md)에 확정돼 있다** (wirit 잉크네이비 팔레트). base.css는 BRAND.md의 CSS 토큰을 그대로 구현한다.

- 컬러: 웜화이트 배경 / 잉크네이비 본문 / 코발트 강조 1축 / 레드는 상승·경고 시그널 전용 (상세 규칙은 BRAND.md)
- 타이포: 제목(Black 웨이트, 큰 사이즈) / 수치(고정폭 느낌의 강한 웨이트) / 라벨(Regular) — 참고 계정처럼 **모바일에서 축소돼도 읽히는 크기**가 기준
- 고정 요소: 상단 카테고리 뱃지 + 제목, 하단 워터마크 + 출처 표기 — 모든 템플릿이 `_shared/components` 재사용
- 밀도 철학: 참고 계정은 "빽빽하지만 위계가 명확"하다. 여백을 늘리기보다 위계(크기 대비)로 승부.

## 6. 표지(커버) 전략

캐러셀 1장이 피드 노출을 결정한다. 규칙:
- 1장: 후킹 제목 + 가장 놀라운 수치 1개 (빅넘버) 또는 완결된 요약표
- 2장~: 상세 데이터
- 커버 제목은 기획 에이전트의 제목 시안 중 운영자가 게이트 1에서 선택 → Phase 4에서 A/B 테스트로 자동화
