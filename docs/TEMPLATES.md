# 디자인 템플릿 시스템 — "무한 생산"의 핵심

참고 계정(@flow, APT_LAP)의 비밀은 화려한 디자인이 아니라 **철저한 템플릿화**다. 같은 레이아웃에 데이터만 갈아끼우기 때문에 매일 생산이 가능하고, 팔로워는 "익숙한 틀 + 새로운 정보"로 즉시 소비한다. 우리 시스템은 이것을 코드로 구현한다.

## 1. 렌더링 방식

**HTML/CSS 템플릿 + JSON 데이터 바인딩 → Playwright(headless Chromium) 스크린샷 → 1080×1350 PNG**

이미지 생성 AI를 쓰지 않는 이유:
- 텍스트·숫자 정확도가 보장되지 않는다 (인포그래픽에 치명적)
- 매번 다른 결과 = 브랜드 일관성 붕괴
- HTML/CSS는 픽셀 단위로 재현 가능하고, 웹 개발 역량으로 무한히 개선 가능

```
templates/
├── _shared/                    # 공통 자산
│   ├── base.css                # 브랜드 토큰: 컬러, 폰트, 간격, 워터마크
│   ├── fonts/                  # Pretendard 등 (라이선스 확인된 폰트)
│   ├── logos/                  # 기업·기관·국기 로고 라이브러리 (핵심 자산!)
│   └── components/             # 헤더, 출처 표기, 순위 배지, 증감 화살표 등
├── ranking-table/
│   ├── template.html           # Handlebars/EJS 템플릿
│   ├── schema.json             # 입력 데이터 계약 (JSON Schema)
│   ├── sample.json             # 샘플 데이터 (개발·회귀 테스트용)
│   ├── config.json             # 항목 수 범위, 폰트 축소 단계, 변형 옵션
│   └── preview.png             # 샘플 렌더 결과
└── ...
```

- **로고 라이브러리**가 의외의 핵심 자산이다. 참고 계정 콘텐츠의 정보 밀도는 기업 로고·국기·대학 엠블럼에서 나온다. 초기부터 `logos/{slug}.png` 컬렉션을 체계적으로 구축하고, 편집 에이전트가 slug로 참조한다. 없는 로고는 QA에서 걸려 사람에게 요청.
- **버전 관리**: 템플릿 ID는 `ranking-table@1`처럼 버전을 포함. 콘텐츠 JSON이 참조하는 버전이 고정되므로 과거 콘텐츠 재렌더가 항상 가능.

## 2. 초기 템플릿 라인업 (참고 계정 역설계 기반 8종)

| # | 템플릿 | 설명 | 참고 사례 | 자동화 난도 |
|---|---|---|---|---|
| 1 | `ranking-table` | 순위 + 로고 + 수치 1~3열 표 | 건설사 연봉, 부자 순위, 감독 연봉 | ★ 쉬움 |
| 2 | `vs-compare` | 2개 대상 항목별 비교 (좌우 대칭) | 삼성전자 vs SK하이닉스 | ★ 쉬움 |
| 3 | `market-daily` | 빅넘버 3개 + 1년 차트 + 종목 등락 그리드 | 간밤의 미국 증시, 오늘의 한국 증시 | ★ 쉬움 (완전 자동 슬롯) |
| 4 | `timeseries-story` | 시계열 차트 + 주석 (스토리텔링형) | 기준금리 추이, 하이먼 민스키 | ★★ 중간 |
| 5 | `map-region` | 지도 + 지역별 수치 라벨 | 동작구 동별 APT, 재산세 지도 | ★★★ 어려움 (지도 SVG 준비 필요) |
| 6 | `share-donut` | 점유율 도넛/블록 + 로고 | 파운드리 점유율, 낸드 점유율 | ★ 쉬움 |
| 7 | `bracket` | 대진표 (토너먼트) | 월드컵 대진표 | ★★ 중간 (시즌성) |
| 8 | `info-grid` | 아이콘/로고/국기 그리드 + 짧은 설명 | 8대 국제학교, 로스쿨 합격률, 정책 총정리 | ★★ 중간 |
| 9 | `photo-topic` | **큰 실물 사진**(항공/현장/제품) + 제목 + 정보박스 | 용인 반도체 단지, 신도시 조감도 | ★★ 중간 (사진 조달 필요) |

전략: 1·2·3·6번(쉬움)으로 런칭 → 4·8·9 추가 → 5·7은 니치 확정 후. **3번 market-daily는 데이터가 100% API로 나오므로 첫 번째 "완전 무인 콘텐츠"로 만들어 매일 발행 기반을 깐다.**
사진 계열(9·8·5)과 표/차트 계열(1·2·3·6) 구분은 §5b 참조.

## 3. 템플릿 제작 프로세스 (사람 + AI 협업, 템플릿당 1~3일)

1. 참고 게시물 3~5개를 골라 레이아웃 요소 분해 (헤더/표/강조/출처/워터마크)
2. AI(Claude)에게 HTML/CSS 초안 생성 요청 → 사람이 디테일 튜닝 (여백, 폰트 크기, 밀도)
3. `schema.json` 확정 — **여기서 엣지 케이스를 미리 설계**: 항목이 5개일 때/15개일 때, 이름이 길 때, 값이 음수일 때
4. `config.json`에 자동 대응 규칙: 항목 수에 따른 행 높이 조정, 텍스트 길이에 따른 폰트 축소 3단계, 말줄임 규칙
5. 샘플 데이터 10종으로 렌더 회귀 테스트 → 통과 시 등록

## 4. 렌더러 구현 스펙

```bash
# CLI
render --data content/2026-07-18/content-001.json --out out/2026-07-18/
# → content-001-p1.png, content-001-p2.png ... (캐러셀 다중 페이지)
```

- 입력 JSON을 템플릿 `schema.json`으로 검증 → 실패 시 명확한 에러 (편집 에이전트가 읽고 수정할 수 있는 메시지)
- Playwright: viewport 1080×1350, deviceScaleFactor 2 (레티나 품질), 폰트 로딩 대기 후 캡처
- 캐러셀: 콘텐츠 JSON의 `pages[]` 배열 → 페이지별 캡처
- 차트: 렌더 전에 서버사이드 ECharts로 SVG 생성 → 템플릿에 인라인 삽입 (스크린샷 시점 애니메이션 이슈 방지)
- 결정성: 동일 입력 = 동일 픽셀 출력 (타임스탬프·랜덤 요소 금지) → QA와 회귀 테스트 가능

## 5. 브랜드 시스템 (base.css 토큰)

> **컬러·워터마크·타이포는 [BRAND.md](./BRAND.md)에 확정돼 있다** (wirit 잉크네이비 팔레트). base.css는 BRAND.md의 CSS 토큰을 그대로 구현한다.

- 컬러: 웜화이트 배경 / 잉크네이비 본문 / 코발트 강조 1축 / 레드는 상승·경고 시그널 전용 (상세 규칙은 BRAND.md)
- 타이포: 제목(Black 웨이트, 큰 사이즈) / 수치(고정폭 느낌의 강한 웨이트) / 라벨(Regular) — 참고 계정처럼 **모바일에서 축소돼도 읽히는 크기**가 기준
- 고정 요소: 상단 카테고리 뱃지 + 제목, 하단 워터마크 + 출처 표기 — 모든 템플릿이 `_shared/components` 재사용
- 밀도 철학: 참고 계정은 "빽빽하지만 위계가 명확"하다. 여백을 늘리기보다 위계(크기 대비)로 승부.
- 하단 워터마크 라인: **flow보다 얇게**(선 1px, 22px, 바닥에 밀착) — 콘텐츠 영역을 최대한 확보 (운영자 지정, 2026-07-18).

## 5b. 이미지 자산: 실물 사진·로고·국기 (1급 요소) — 운영자 강조 (2026-07-18)

flow의 핵심은 표뿐 아니라 **실물 사진이 많다**는 점이다(항공사진, 인물, 제품, 국기, 기업 CI). wirit도 사진·이미지를 **표와 동등한 1급 요소**로 다룬다. HTML/CSS 렌더러는 `<img object-fit:cover>`로 사진을 정확히 크롭·배치할 수 있어, flow가 하는 사진 레이아웃을 그대로 구현한다.

- **템플릿은 두 계열로 나뉜다**:
  - **표/차트 계열** (사진 적음): `ranking-table`, `market-daily`, `share-donut` — 신문형에 가까움
  - **사진 계열** (사진이 주인공): `photo-topic`(단일 이슈 항공/현장 사진 + 정보박스, 예: 반도체 단지), `info-grid`(국기·엠블럼 그리드, 예: 월드컵·로스쿨), `map-region`(지도 이미지) — 타블로이드에 가까움
  - 대부분의 카드는 둘을 섞는다 (표 + 로고, 차트 + 인물사진).
- **이미지 자산 종류와 조달**:
  | 종류 | 예 | 조달 | 저작권 |
  |---|---|---|---|
  | 기업·기관 로고, 대학 엠블럼 | 삼성, SK, 대학 | 로고 라이브러리(`_shared/logos/{slug}`) | 정보전달 목적 지명적 사용, 문제 시 즉시 교체 |
  | 국기 | 월드컵 대진 | 오픈 라이선스 국기 세트 번들 | 퍼블릭 도메인 |
  | 실물 사진 | 항공사진, 현장, 제품 | **공식 보도자료·기관 제공 사진·라이선스 스톡 우선** | 출처 표기 + 이용약관 확인. 언론사 사진 무단전재 금지 |
  | 인물 사진 | 총재·CEO | 공식 프로필·보도자료 | 초상권·맥락 주의 (조롱·왜곡 금지) |
- **결정성 유지**: 모든 이미지는 저장소/자산 스토리지에 두고 로컬 경로로 참조(런타임 외부 URL fetch 금지) → 동일 입력 = 동일 픽셀 유지.
- **QA 연동**(M10): 깨진 이미지·빈 사진칸·저대비 위 텍스트 가독성을 디자인 QA가 검출.
- **정책**: 사진 조달·저작권 세부는 [DATA_SOURCES.md](./DATA_SOURCES.md) §법적·윤리 체크리스트를 따른다. 사진 확보가 어려운 소재는 표/차트 계열 템플릿으로 우회.

## 6. 포맷·표지(커버) 전략

**포맷 기본값 = 단일 카드 1장** (2026-07-23 운영자 확정). 캐러셀은 아래 **3조건 중 하나**일 때만 쓴다.

| 조건 | 예시 |
|---|---|
| ① **정답 가리기**가 콘텐츠의 핵심 | "서울에서 가장 비싼 34평은?" → 다음 장에서 공개 |
| ② 한 장에 **물리적으로 안 들어감** | 25개 자치구 랭킹 → p1(1~13위)·p2(14~25위) |
| ③ **시리즈 연재** (넘버링·세계관이 자산) | 대장 도감 No.01, 지하철이 온다 EP.1 |

- **목표 배분**: 단일 70~80% / 캐러셀 20~30%
- **왜 단일이 기본인가**: 공유(DM 전송)·저장(스크린샷 1회 완결)·발행 빈도에서 우세하고, 무엇보다 **커버 사진 취득이 무인화(R3)의 구조적 병목**(라이선스·눈검증에 사람 개입 필요).
- **단일 카드 후킹 = "제목이 곧 반전"** — 궁금증 갭 대신 놀라움으로 스크롤을 멈춘다. 제목이 결론을 말하고 본문이 증명한다. 예: 「신고가는 **강남**이 아니었다」
- **커버가 필요하면 그래픽 커버 우선**(타이포·색·도형만) — 결정적 렌더가 유지돼 자동화가 안 깨진다. 사진 커버는 감성이 핵심일 때만.

**캐러셀을 쓸 때의 구성** (기존 규칙 유효):
- 1장(커버): 후킹 제목 + 가장 놀라운 수치 1개(빅넘버), 정답은 가림 + "👉 다음장에서" CTA
- 2장: 데이터 표 — 팔로우 유도는 표 하단 푸터로 흡수
- 마무리(p3) 장은 **기본 미포함**
- 커버 제목은 기획 에이전트의 제목 시안 중 운영자가 게이트 1에서 선택 → Phase 4에서 A/B 테스트로 자동화

## 7. `singoga-map@1` — 순위표 + 코로플레스 지도 (2026-07-25 확정)

지역 단위 집계를 **좌: 순위표 / 우: 지도** 한 장으로 보여주는 단일 카드. 서울판(`singoga-map.json`)과
수도권 토허제판(`tohuh-rank.json`) 2종이 이 템플릿을 공유한다. 제작 경위 전문 =
[../research/production-logs/2026-07-25-tohuh-singoga-map.md](../research/production-logs/2026-07-25-tohuh-singoga-map.md)

### 문서 필드

| 필드 | 설명 |
|---|---|
| `title` / `note` | 제목(HTML 허용) / 좌상단 옅은 캡션 |
| `mapSvg` | 빌더가 만든 결정적 SVG 문자열 (좌표·색 전부 코드 산출) |
| `rows[]` | `{rank, medal, top, gu, hits, ratio?}` |
| `head` | 표 헤더 좌/우 라벨 |
| `insight` | 하단 결론 한 줄(HTML 허용, `<b>`=레드 강조) |
| `cta` / `footnote` / `legend` | 선택 — 서울판에서 사용 |
| `compact` | **행이 많은 카드용 variant `.sm-c`** 활성화 |
| `stamp` | 그래픽 내부 아이덴티티 스탬프(CSS 배치형) |
| `hideFooterId` | 푸터 `@wirit_note` 숨김 — 아이디를 그래픽 안에 둘 때 |

### 규칙

- **variant 격리 필수**: 새 스타일은 반드시 `.sm-c` 안에 넣는다. 공용 규칙을 고치면 이미 승인된
  서울 카드가 조용히 바뀐다(실제로 발생). 수정 후 승인 카드 md5 회귀검사가 완료 조건.
- **제목은 한 줄(`white-space:nowrap`)**, 상단 여백으로 우상단 로고 뱃지와 **30px 이상 이격**.
- **행 수를 바꾸면 실측**: designQa가 flex 넘침을 못 잡으므로 `마지막 행 bottom ≤ 본문 bottom`을
  Playwright로 확인한다.
- **지도 표기 기법**(빌더 쪽 계약): 신설 행정구는 하위 행정동 합성(`subCodes`), 하천은 인접 그룹의
  공유 정점에서 도출, 시 경계는 evenodd 클립으로 외곽선만. 상세는 위 제작 기록 §3.

## 8. `year-bars@1` — 연도별 변화율 발산 막대 (2026-07-30 신설)

한 지표의 **방향이 뒤집힌 지점**을 한 장에 보여준다. 첫 사용: `wolse-flip` 세트 p1
(서울 아파트 월세가격지수, 5년 연속 마이너스 → 6년 연속 플러스).

### 왜 순위표가 아닌가

연도별 변화율은 **순위가 아니다.** `ranking-table@1`에 넣으면 연도 옆에 1·2·3이 붙어
"2025년이 1위"처럼 읽힌다 — 시간축이 순위로 오독된다. 그래서 시간 순서를 유지하고
0을 기준으로 좌우로 가른다.

### 구조

`[연속구간 라벨] [연도] [음수 트랙] │0 [양수 트랙] [값]`

| 필드 | 설명 |
|---|---|
| `title` | 줄바꿈(`\n`) 허용. 태백체 |
| `lede` | 제목 아래 한 줄 |
| `negLabel` / `posLabel` | 축 좌/우 라벨. 기본 `하락`/`상승` |
| `many` | 12행 이상일 때 트랙 폭을 좁힌다 |
| `groups[]` | `{tone: neg\|pos, label, split, rows[]}` — **구간을 나누는 것 자체가 "몇 년 연속"이라는 정보** |
| `groups[].rows[]` | `{year, value(표시 문자열), dir, w(0~100), note, max, partial}` |
| `foot[]` | 하단 요약 `{k, v, accent}` 최대 3개 |
| `caveat` | 정직 문구. 기준·한계를 반드시 적는다 |

### 규칙

- **`w`(막대 폭)는 빌더가 계산한다.** 최대 절대값이 100이 되게 정규화. 템플릿은 표시만 한다.
- **색 규칙: 오름 = 레드(`--wirit-red`), 내림 = 코발트(`--wirit-cobalt`).** `index-2026@1`의
  하락 아크가 코발트인 것과 같은 언어다. 이 규칙을 카드마다 바꾸면 색이 정보가 아니라 장식이 된다.
- **끝나지 않은 연도는 `partial: true`.** 막대가 사선으로 칠해진다 — 값 옆 `note`만 믿으면
  그래픽만 잘라 썼을 때 경고가 사라진다.
- **강조(`max`)는 한 곳만**, 그리고 **끝난 연도 중에서** 고른다. 진행 중인 연도를
  "가장 많이 오른 해"라고 하면 연말에 그 말이 틀린다.
- **`caveat`는 한 줄에 들어와야 한다.** 두 줄로 밀리면 끝 글자가 잘려 경고가 반쪽이 된다.

## 9. `map-choropleth@1` 확장 — 발산 배색 + 제목 축소 (2026-07-30)

기존 필드는 그대로 두고 **선택 필드만 추가**했다(기존 카드 md5 회귀검사 통과).

| 추가 필드 | 설명 |
|---|---|
| `colorMid` / `midAt` | 발산 범례의 가운데 색과 그 위치(%). 주면 `.diverging` 이 켜진다 |
| `legendMid` | 범례 옆 괄호 문구(예: `0 기준`) |

- **값이 0을 가로지르면 발산 배색을 쓴다.** 단색 농담으로 칠하면 마이너스 지역이
  "조금 오른" 것처럼 보인다 — 전세 지도 첫 렌더에서 −5.0%인 금천구가 그렇게 읽혔다. 색이 거짓말한다.
- **0의 위치는 실제 비율로 찍는다.** 가운데에 두면 "절반이 마이너스"처럼 보인다.
- **제목은 넘치면 자동으로 줄어든다(`__wiritFit`).** 단 **키우지는 않는다** — 이미 확정된
  기존 카드의 픽셀이 바뀌면 결정성 위반이다.
- **지도 라벨은 면적으로 크기를 정하고(`polyArea`), 자기 구 색으로 후광을 깐다.**
  작은 구(성동·광진·중)에서 라벨이 겹쳐 읽히지 않던 문제의 해법. 투영·무게중심·면적 계산은
  `scripts/lib/seoul-map.mjs` 하나에만 둔다 — 복사하면 카드마다 지도 모양이 갈린다.
