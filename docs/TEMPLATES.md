## 1. 렌더링 방식

**HTML/CSS 템플릿 + JSON 데이터 바인딩 → Playwright(headless Chromium) 스크린샷 → 1080×1350 PNG**

이미지 생성 AI를 쓰지 않는 이유:
- 텍스트·숫자 정확도가 보장되지 않는다 (인포그래픽에 치명적)
- 매번 다른 결과 = 브랜드 일관성 붕괴
- HTML/CSS는 픽셀 단위로 재현 가능하고, 웹 개발 역량으로 무한히 개선 가능

```
templates/
├── _shared/                    # 공통 자산
│   ├── base.css                # 브랜드 토큰: 컬러, 폰트, 간격, 워터마크
│   ├── fonts/                  # Pretendard 등 (라이선스 확인된 폰트)
│   ├── logos/                  # 기업·기관·국기 로고 라이브러리 (핵심 자산!)
│   └── components/             # 헤더, 출처 표기, 순위 배지, 증감 화살표 등
├── ranking-table/
│   ├── template.html           # Handlebars/EJS 템플릿
│   ├── schema.json             # 입력 데이터 계약 (JSON Schema)
│   ├── sample.json             # 샘플 데이터 (개발·회귀 테스트용)
│   ├── config.json             # 항목 수 범위, 폰트 축소 단계, 변형 옵션
│   └── preview.png             # 샘플 렌더 결과
└── ...
```

- **로고 라이브러리**가 의외의 핵심 자산이다. 참고 계정 콘텐츠의 정보 밀도는 기업 로고·국기·대학 엠블럼에서 나온다. 초기부터 `logos/{slug}.png` 컬렉션을 체계적으로 구축하고, 편집 에이전트가 slug로 참조한다. 없는 로고는 QA에서 걸려 사람에게 요청.
- **버전 관리**: 템플릿 ID는 `ranking-table@1`처럼 버전을 포함. 콘텐츠 JSON이 참조하는 버전이 고정되므로 과거 콘텐츠 재렌더가 항상 가능.

## 3. 템플릿 제작 프로세스 (사람 + AI 협업, 템플릿당 1~3일)

1. 참고 게시물 3~5개를 골라 레이아웃 요소 분해 (헤더/표/강조/출처/워터마크)
2. AI(Claude)에게 HTML/CSS 초안 생성 요청 → 사람이 디테일 튜닝 (여백, 폰트 크기, 밀도)
3. `schema.json` 확정 — **여기서 엣지 케이스를 미리 설계**: 항목이 5개일 때/15개일 때, 이름이 길 때, 값이 음수일 때
4. `config.json`에 자동 대응 규칙: 항목 수에 따른 행 높이 조정, 텍스트 길이에 따른 폰트 축소 3단계, 말줄임 규칙
5. 샘플 데이터 10종으로 렌더 회귀 테스트 → 통과 시 등록

## 4. 렌더러 구현 스펙

```bash
# CLI
render --data content/2026-07-18/content-001.json --out out/2026-07-18/
# → content-001-p1.png, content-001-p2.png ... (캐러셀 다중 페이지)
```

- 입력 JSON을 템플릿 `schema.json`으로 검증 → 실패 시 명확한 에러 (편집 에이전트가 읽고 수정할 수 있는 메시지)
- Playwright: viewport 1080×1350, deviceScaleFactor 2 (레티나 품질), 폰트 로딩 대기 후 캡처
- 캐러셀: 콘텐츠 JSON의 `pages[]` 배열 → 페이지별 캡처
- 차트: 렌더 전에 서버사이드 ECharts로 SVG 생성 → 템플릿에 인라인 삽입 (스크린샷 시점 애니메이션 이슈 방지)
- 결정성: 동일 입력 = 동일 픽셀 출력 (타임스탬프·랜덤 요소 금지) → QA와 회귀 테스트 가능

## 5. 브랜드 시스템 (base.css 토큰)

> **컬러·워터마크·타이포는 [BRAND.md](./BRAND.md)에 확정돼 있다** (wirit 잉크네이비 팔레트). base.css는 BRAND.md의 CSS 토큰을 그대로 구현한다.

- 컬러: 웜화이트 배경 / 잉크네이비 본문 / 코발트 강조 1축 / 레드는 상승·경고 시그널 전용 (상세 규칙은 BRAND.md)
- 타이포: 제목(Black 웨이트, 큰 사이즈) / 수치(고정폭 느낌의 강한 웨이트) / 라벨(Regular) — 참고 계정처럼 **모바일에서 축소돼도 읽히는 크기**가 기준
- 고정 요소: 상단 카테고리 뱃지 + 제목, 하단 워터마크 + 출처 표기 — 모든 템플릿이 `_shared/components` 재사용
- 밀도 철학: 참고 계정은 "빽빽하지만 위계가 명확"하다. 여백을 늘리기보다 위계(크기 대비)로 승부.
- 하단 워터마크 라인: **flow보다 얇게**(선 1px, 22px, 바닥에 밀착) — 콘텐츠 영역을 최대한 확보 (운영자 지정, 2026-07-18).

## 5b. 이미지 자산: 실물 사진·로고·국기 (1급 요소) — 운영자 강조 (2026-07-18)

flow의 핵심은 표뿐 아니라 **실물 사진이 많다**는 점이다(항공사진, 인물, 제품, 국기, 기업 CI). wirit도 사진·이미지를 **표와 동등한 1급 요소**로 다룬다. HTML/CSS 렌더러는 `<img object-fit:cover>`로 사진을 정확히 크롭·배치할 수 있어, flow가 하는 사진 레이아웃을 그대로 구현한다.

- **템플릿은 두 계열로 나뉜다**:
  - **표/차트 계열** (사진 적음): `ranking-table`, `market-daily`, `share-donut` — 신문형에 가까움
  - **사진 계열** (사진이 주인공): `photo-topic`(단일 이슈 항공/현장 사진 + 정보박스, 예: 반도체 단지), `info-grid`(국기·엠블럼 그리드, 예: 월드컵·로스쿨), `map-region`(지도 이미지) — 타블로이드에 가까움
  - 대부분의 카드는 둘을 섞는다 (표 + 로고, 차트 + 인물사진).
- **이미지 자산 종류와 조달**:
  | 종류 | 예 | 조달 | 저작권 |
  |---|---|---|---|
  | 기업·기관 로고, 대학 엠블럼 | 삼성, SK, 대학 | 로고 라이브러리(`_shared/logos/{slug}`) | 정보전달 목적 지명적 사용, 문제 시 즉시 교체 |
  | 국기 | 월드컵 대진 | 오픈 라이선스 국기 세트 번들 | 퍼블릭 도메인 |
  | 실물 사진 | 항공사진, 현장, 제품 | **공식 보도자료·기관 제공 사진·라이선스 스톡 우선** | 출처 표기 + 이용약관 확인. 언론사 사진 무단전재 금지 |
  | 인물 사진 | 총재·CEO | 공식 프로필·보도자료 | 초상권·맥락 주의 (조롱·왜곡 금지) |
- **결정성 유지**: 모든 이미지는 저장소/자산 스토리지에 두고 로컬 경로로 참조(런타임 외부 URL fetch 금지) → 동일 입력 = 동일 픽셀 유지.
- **QA 연동**(M10): 깨진 이미지·빈 사진칸·저대비 위 텍스트 가독성을 디자인 QA가 검출.
- **정책**: 사진 조달·저작권 세부는 [DATA_SOURCES.md](./DATA_SOURCES.md) §법적·윤리 체크리스트를 따른다. 사진 확보가 어려운 소재는 표/차트 계열 템플릿으로 우회.

## 6. 포맷·표지(커버) 전략

**포맷 기본값 = 단일 카드 1장** (2026-07-23 운영자 확정). 캐러셀은 아래 **3조건 중 하나**일 때만 쓴다.

| 조건 | 예시 |
|---|---|
| ① **정답 가리기**가 콘텐츠의 핵심 | "서울에서 가장 비싼 34평은?" → 다음 장에서 공개 |
| ② 한 장에 **물리적으로 안 들어감** | 25개 자치구 랭킹 → p1(1~13위)·p2(14~25위) |
| ③ **시리즈 연재** (넘버링·세계관이 자산) | 대장 도감 No.01, 지하철이 온다 EP.1 |

- **목표 배분**: 단일 70~80% / 캐러셀 20~30%
- **왜 단일이 기본인가**: 공유(DM 전송)·저장(스크린샷 1회 완결)·발행 빈도에서 우세하고, 무엇보다 **커버 사진 취득이 무인화(R3)의 구조적 병목**(라이선스·눈검증에 사람 개입 필요).
- **단일 카드 후킹 = "제목이 곧 반전"** — 궁금증 갭 대신 놀라움으로 스크롤을 멈춘다. 제목이 결론을 말하고 본문이 증명한다. 예: 「신고가는 **강남**이 아니었다」
- **커버가 필요하면 그래픽 커버 우선**(타이포·색·도형만) — 결정적 렌더가 유지돼 자동화가 안 깨진다. 사진 커버는 감성이 핵심일 때만.

**캐러셀을 쓸 때의 구성** (기존 규칙 유효):

연도별 변화율은 **순위가 아니다.** `ranking-table@1`에 넣으면 연도 옆에 1·2·3이 붙어
"2025년이 1위"처럼 읽힌다 — 시간축이 순위로 오독된다.

### 구조

`[플롯: 0선 기준 위(오름)/아래(내림)] → [연도 축] → [요약 카드]`

| 필드 | 설명 |
|---|---|
| `title` | **한 줄(nowrap)·가운데.** `__wiritFit` 이 폭에 맞춰 축소. `<span class="hi">` 레드 강조 가능 |
| `subtitle` | 좌상단 옅은 캡션 — 대상·지표를 적는다. ~~`lede`(제목 아래 회색 줄)는 폐지~~ (07-30 오너 지시) |
| `zeroAt` | 0선 위치(플롯 높이 대비 %). 빌더가 최대 오름/내림 비율로 계산 |
| `splitAt` | 실측/추정 경계 세로 점선 위치(%) |
| `points[]` | `{year, value, dir(up\|down), h, hEst, totalH, tag, solidValue, valueInside, peak}` |

### 오너 확정 스펙 (2026-07-30, 6차 다듬기까지)

| 요소 | 규칙 |
|---|---|
| 제목 | 한 줄·가운데. `__wiritFit` 이 폭(936px)에 맞춰 폰트를 **줄이는 방향으로만** 조정. `<span class="hi">`로 일부 레드 강조(레드 = 오름이라 뜻이 어긋나지 않는다) |
| 강조 박스 `side.cards[]` | **정사각 2장**을 제목 아래 좌우로(좌 = 수준 / 우 = 변화율). 각(3px) + 종이 바탕 + 괘선 — **실선 = 실측(`idx`) / 점선 = 추정(`est`)**. 라벨 2줄(`lines`)은 빌더가 줄 단위로 고정하고, 3번째 줄이 큰 레드 숫자(`value`), `small`(예 `(추정)`)만 작게. 값 폰트는 **두 카드 공통 크기**를 실측해 함께 적용 |
| 지수 곡선 `line` | 막대 = 연간 변화율 / 곡선 = 지수 수준 — **축이 다르니 눈금을 넣지 않는다**. 막대 **앞** 레이어(z-index 3)이지만 색은 회색으로 낮춘다. 값은 `line.labels[]` 의 **원형 뱃지**(80px, 소수 1자리) 3개만: 시작·바닥·현재. `anchor`(`s`=시작점 / `l`=끝점)로 막대를 피한다 → `barclip` 검수가 강제 |
| 추정 구간 | 점선+사선 막대 + **2줄 꼬리표**(`tag: ["하반기","추정"]`) — 상자 없이 글자만, 진한 레드(사선 바탕이 옅어 흰 글씨는 사라진다). 막대보다 좁게 둬야 막대 경계를 타고 오르는 곡선을 피한다 + 경계 세로선(`splitAt`) + 캡션의 산술 가정. **넷 다 있어야** 추정치가 사실로 안 읽힌다 |
| 막대 안 값 | `valueInside` — 막대 위 라벨 자리가 곡선보다 위로 올라가는 칸만 흰 글씨로 안에 넣는다. **칸 번호를 손으로 박지 않는다**(빌더가 실측 거리로 판정) |
| 워터마크 | `stamp`(0선 아래 빈 칸) + `stamp2`(지수 곡선 아래·막대 위 빈 칸). `stamp2` 는 **초년도 막대가 0선 아래에만 있을 때만** 켠다 — 아니면 막대를 덮는다 |
| 곡선 Y 매핑 | 바닥을 **첫 플러스 막대 상단 위**로 올린다(최하점이 막대를 관통하지 않게). 끝점은 `Y_TOP` 앵커라 최고점 위치는 안 움직인다 |
| `foot[]` | 하단 요약 `{k, v, hot}` 최대 3개 |

### 규칙

- **막대 높이(h·hEst·totalH)는 빌더가 % 로 계산한다.** 템플릿은 그리기만 한다.
- **색: 오름 = 레드, 내림 = 코발트.** `index-2026@1`의 하락 아크가 코발트인 것과 같은 언어다.
- **추정 구간은 네 곳에서 실측과 분리한다** — 점선 테두리 + 사선 칠 + `tag`("하반기 추정")
  + `splitAt` 세로 경계선. 하나만 빠뜨리면 추정치가 사실로 읽힌다. 계산 규칙은 빌더 주석에 명시.
- **값 라벨은 칸 폭을 넘지 않는다.** `left/right`를 음수로 넓히면 옆 칸 라벨과 겹친다
  (첫 렌더에서 +2.0% / +1.8% / +2.3% 가 뭉쳤다). 단위(%)는 라벨에서 빼고 좌상단 캡션(`subtitle`)이나 강조 카드 값에만 남긴다.
- **강조는 한 곳만.** 최고 실측 연도와 추정 연도를 동시에 강조하면 초점이 흐려진다.

## 9. `map-choropleth@1` 확장 — 발산 배색 + 제목 축소 (2026-07-30)

기존 필드는 그대로 두고 **선택 필드만 추가**했다(기존 카드 md5 회귀검사 통과).

| 추가 필드 | 설명 |
|---|---|
| `colorMid` / `midAt` | 발산 범례의 가운데 색과 그 위치(%). 주면 `.diverging` 이 켜진다 |
| `legendMid` | 범례 옆 괄호 문구(예: `0 기준`) |

- **값이 0을 가로지르면 발산 배색을 쓴다.** 단색 농담으로 칠하면 마이너스 지역이
  "조금 오른" 것처럼 보인다 — 전세 지도 첫 렌더에서 −5.0%인 금천구가 그렇게 읽혔다. 색이 거짓말한다.
- **0의 위치는 실제 비율로 찍는다.** 가운데에 두면 "절반이 마이너스"처럼 보인다.
- **제목은 넘치면 자동으로 줄어든다(`__wiritFit`).** 단 **키우지는 않는다** — 이미 확정된
  기존 카드의 픽셀이 바뀌면 결정성 위반이다.
- **지도 라벨은 면적으로 크기를 정하고(`polyArea`), 자기 구 색으로 후광을 깐다.**
  작은 구(성동·광진·중)에서 라벨이 겹쳐 읽히지 않던 문제의 해법. 투영·무게중심·면적 계산은
  `scripts/lib/seoul-map.mjs` 하나에만 둔다 — 복사하면 카드마다 지도 모양이 갈린다.

- **`hideLegend`** — 값이 지도 위에 다 적혀 있어 색 눈금이 불필요할 때 하단 범례 행을 없앤다.
  단 **`footnote`(기준·한계 한 줄)는 남긴다** — 범례는 편의고 기준 표기는 정직의 문제다.
- **`framedBy` / `margin`** (`scripts/lib/seoul-map.mjs`) — 화면(bbox)을 **색칠 대상만으로** 잡는다.
  대상이 일부에 몰린 지도를 전체 bbox 로 그리면 대상이 깨알처럼 작아진다(토허제 40곳 지도를
  경기 전체 bbox 로 그렸더니 서울 라벨을 읽을 수 없었다). 잘려도 되는 건 배경이다.
- **`scope`** — `"seoul"`(서울 25개 자치구) / `"capital"`(서울+경기 시·군·구). 경계 파일명을
  빌더에 흩어 놓지 않는다 — 어느 카드가 어느 경계를 쓰는지 한 곳에서 보여야 한다.
- **색칠 지역을 배경보다 나중에 그린다.** 경계를 맞댈 때 뒤에 그린 쪽의 흰 테두리가 위에 얹히므로,
  배경이 위로 오면 대상 지역 윤곽이 갉아먹힌다.
- **지도 라벨 이름은 짧게.** 구 단위는 구 이름만(서울 자치구를 "강남·송파"로 적는 것과 같다).
  "수원팔달"처럼 시+구를 붙이면 라벨이 도형보다 넓어져 옆 지역과 겹친다. 시 이름은 캡션이 밝힌다.

## 10. 토허제 지도 표준 (2026-07-30 오너 지시 — **앞으로 항상 이 기준**)

> **토지거래허가구역 지도를 쓰는 카드는 새로 그리지 않는다.**
> 「2026년 6월 신고가 쏟아진 지역은?」 카드의 지도를 그대로 불러온다.

### 그리는 코드는 한 곳: `scripts/lib/tohuh-map.mjs`

`tohuhParts(areas)` → 표시 단위 목록 / `tohuhMapSvg({parts, valueOf, textOf, labelWidth})` → SVG.
이 모듈이 담당하는 것:

| | |
|---|---|
| **한강** | 손으로 안 그린다. 한강 이북 구와 이남 구가 **공유하는 경계 정점**을 경도순으로 이어 만든다(양 끝단만 시계 좌표 2개씩 보정) |
| **서울 시 외곽선** | 25구 링을 굵게 stroke 하고 "서울 바깥"만 남기는 evenodd 클립 → 폴리곤 union 없이 시 경계만 남는다 |
| **화면 채우기** | bbox 를 **표시 대상만**으로 잡는다. 미지정 지역은 아예 안 그린다(회색 배경 없음) |
| **신설 구 합성** | `subCodes`(읍면동)를 한 path 로 합치고 내부 경계선을 지운다 — 화성 동탄구 |
| **라벨 배치** | `placement` 로 고른다 — 아래 표 참고. 폭은 `labelWidth`로 받는다 |
| **워터마크** | 지도 안 빈 여백 2곳에 `@wirit_note` 스탬프. 그래픽만 잘라 써도 출처가 따라간다 |

`labelWidth` 기본값 **140** 은 신고가 카드("성남 수정 26") 기준이다. 값 문자열이 길어지면
(예: "성남 수정 +6.9%") **176** 처럼 키운다 — 기본값을 바꾸면 신고가 카드 픽셀이 변한다.
2줄 라벨(`twoLine: true` — 이름 / 값)이면 폭이 절반쯤이라 **118** 로 줄인다.

### 라벨 배치 방식 (`placement`) — 새 카드는 `"nearest"`

| 값 | 동작 | 언제 |
|---|---|---|
| `"down"`(기본) | 겹치면 아래로만 7px씩 민다 | **발행된 신고가 카드가 이 배치로 굳어 있다.** 기본값을 바꾸면 그 카드 픽셀이 달라진다 — 절대 건드리지 않는다 |
| `"nearest"` | 후보 격자를 훑어 **거리 + 도형 밖 벌점 + 겹침 면적 벌점**의 합이 최소인 자리 | 새로 만드는 카드는 전부 이것 |

`"nearest"` 가 지키는 세 가지 — 순서가 곧 우선순위다:

1. **소속이 겹침보다 앞선다.** "빈 자리를 먼저 찾는" 방식은 중랑·서대문·금천을 남의 구 위로 밀어냈다.
   라벨이 남의 구에 있으면 숫자가 통째로 오독된다 — 살짝 겹치는 것보다 나쁘다
2. **도형 안 판정은 무게중심이 아니라 링 전체의 점-포함 판정.** 오목한 구(중랑·성동)는 무게중심이 옆 구에 떨어진다
3. **겹침 벌점은 연속값**(0/1 아님). 그래서 라벨보다 좁은 구(수원 팔달)는 "살짝 겹치고 제자리"를 택한다

큰 구부터 자리를 잡는다(작은 구는 어차피 밀리므로 큰 구의 중앙을 지켜준다). 격자·순서가 고정이라 같은 입력 → 같은 배치.

| `subCodes` | 2013 경계에 없는 신설 구의 읍면동 | 동탄면·동탄1~3동 |
| `isNew`(신규 지정) | 표 이름 뒤 `⚡` | `구리시 ⚡` |

- **이름으로 지역을 집지 않는다.** 중구·강서구처럼 동명 지역이 여러 도시에 있다.
  `rebCode` 가 없는 지역이 생기면 빌더가 던진다 — 조용히 빠지지 않게.
- 지정 목록이 바뀌면 이 파일만 고친다. 카드는 따라 바뀐다.

### 카드 레이아웃 표준 (`singoga-map@1`)

- 왼쪽 **행정구역 표**(`label`) + 오른쪽 **지도**(`mapLabel` + 값)
- 40곳을 표에 다 넣을 수 없다 → **상위 12 + 하위 3 + 「가운데 N곳 생략」**.
  생략 수를 표 안에 적고, **캡션에 40곳 전부**를 적는다. 조용히 자르면 "다 보여준 표"로 읽힌다
- `unit` 으로 값 단위를 바꾼다(기본 `건`, 상승률 카드는 `%`)
- `hideFooterId: true` — 아이디는 지도 안 스탬프에 있으니 푸터에서 중복 제거
- `head.c: ["순위","지역","월세 상승분"]` — 표 머리글 3열 가운데 정렬(데이터 행과 같은 그리드).
  ⚠️ Handlebars 에서 숫자 인덱스는 **`{{head.c.[0]}}` 브래킷**이다. `{{head.c.0}}` 은 파싱 오류
- `fitTitle: true` — 제목을 폭에 맞춰 자동 확대(좌우 여백 최소). `asOfNote` 를 함께 주면
  기준 시점이 **제목의 절반 크기**로 표 오른쪽·지도 위에 붙는다(제목 크기에 연동)
- `spread: true` — 행이 10개 이하일 때 행 간격을 펴서 표가 본문 높이를 채운다. 행이 많으면 넘친다
- **상단 캡션(`note`)·푸터(`source.name`)는 한 줄.** 넘치면 두 줄로 접혀 잘린다

## 11. `danji-cover@1` — 청약·분양 카드 **표준 판형** (오너 확정 2026-08-03)

> **2026-09-03 변경 — 표지가 늘어난다.** 높이 690px 은 이제 **최소치**다. `.dcv-cover` 가
> `flex:1` 로 종이가 안 쓰는 세로를 가져가고, 사진 칸(`.dcv-photo`)은 표지에서 잉크 밴드를 뺀
> 나머지 전부다. 상한은 빌더가 주는 `hero.coverMax`(원본이 폭 1080 에서 갖는 높이 + 밴드).
> 끌어올림은 `hero.shift` 대신 **`object-position: 50% 42.5%`** 가 한다 — 규칙(남는 세로의
> 42.5% 를 위에서 걷어냄)은 그대로고, 계산 시점만 빌더에서 브라우저로 옮겼다.

> 먹어 표지가 못 늘어나기 때문이다.


> 청약·분양 소재는 **전부 이 판형으로 만든다.** 판형을 바꾸려면 오너 승인이 필요하다.
> 왜 이렇게 생겼는지, 무엇을 건드리면 안 되는지는 **`docs/guides/청약분양-카드-기준.md`** 가
> 원천이다 — 이 절은 구조와 규격만 적는다.
>
> 전신: `danji-brief@1~@3` → 배치 시안 A·B·C → **C(표지형) 채택** → 마감 지시 12건.

### 사진 위치는 계산한다 — **빌더가**, 매 빌드마다

```
renderH = round(1080 × 원본높이 / 원본가로)
shift   = round((renderH − 446) × 0.425)      // 남는 세로의 42.5% 를 위에서 걷어낸다
```

한강 카드(1200×660 → renderH 594 → 남는 148 → **shift 63**)가 오너가 승인한 값이고,
이 식이 그 값을 그대로 재현한다. 사진을 바꾸면 값이 저절로 따라온다.
`build-danji.mjs` 의 `heroShift()` 가 JPEG/PNG 헤더에서 크기를 직접 읽는다(외부 의존성 없음).

- `renderH < 446`(가로로 너무 긴 사진) → **던진다.** 조용히 늘리지 않는다.
- 크롭 하단이 원본 아래 5% 에 닿으면 **경고**한다 — 건설사 고지문이 거기 박혀 있다.

> ⚠️ `object-position` 으로는 이 조절이 안 된다. 칸이 원본보다 세로로 길면 `object-fit: cover`
> 가 원본 전체 높이를 채워 세로 여유가 0이 되고, 퍼센트를 어떻게 줘도 그림이 움직이지 않는다.
> 그래서 `width:100% / height:auto` 로 그린 뒤 `top` 으로 직접 끌어올린다.
> ⚠️ **CSS 에 px 를 박지 않는다.** 사진에 딸린 수치는 데이터로 흘러야 다음 사진에서 안 틀어진다.

### 열 폭은 데이터가 정한다

일정 4칸을 균등 분할하면 가장 긴 '2031년 1월'이 **공통 수치 크기를 통째로 끌어내린다**
(52 → 41px). 그래서 마지막 칸만 1.5배로 넓혔다. 덤으로 `1:1:1:1.5` 의 마지막 경계가
936×3/4.5 = **624px** 로 위 줄(3등분)의 두 번째 세로선과 정확히 겹친다.
일정이 3칸인 카드(청약 결과 등)는 `:has(.cell:nth-child(3):last-child)` 로 **균등 3열**이 되고,
그때는 위 줄과 **세로선 두 개가 모두** 겹친다.

### 이 판형의 규칙

- **어두운 배경 위 브랜드 마크는 흰색으로 뒤집는다** — `filter: brightness(0) invert(1)`.
  짙은 단색 마크(푸르지오 등)는 조감도 위에서 그대로 묻힌다.
- **강조는 한 군데.** 흰 영역에서 색을 쓰는 곳은 주력 면적대 **금액** 하나다.
  타입은 주력이든 아니든 회색 — 타입은 금액을 읽기 위한 열쇠지 그 자체가 강조 대상이 아니다.
- **라벨을 지우는 것과 뜻을 지우는 것은 다르다.** 제원 라벨(세대수·동수)은 값이 단위를
  데리고 있어 지웠지만, 층수에는 `pre: "최고"` 를, 결과 카드의 경쟁률에는 `pre: "1순위"` 를
  값 앞에 회색으로 붙인다.
- **조감도가 없으면 노란 경고(`.dcv-ph` "조감도 미확보 · 대체 이미지")가 사진 위에 뜬다.**
  출처 표기를 지우는 것과 아무 사진을 그 단지 조감도로 읽히게 두는 것은 다르다.
  이 뱃지가 보이는 카드는 **발행 금지**다.
- **AI티 금지**: 라운드 없음, 옅은 회색 채움 상자 없음. 덩어리는 표지와 종이 둘,
  경계는 그라데이션 하나 + 괘선.

- **없으면**(송도) — 위 단 = 전용면적별 잔여 세대, 아래 단 = 잔여/동수/층수
- **있으면**(장위) — 위 단 = 단지 규모 4칸, 아래 단 = 타입별 세대수·최고 분양가 4칸(`.frow.four`)

새 판형 CSS 는 **선택자로 가둔다**(`.frow.four`, `:has(.frow.four)`). 공통 규칙을 건드리면
확정본이 같이 움직인다 — 판형을 고칠 때마다 위 표의 md5 를 **전부 다시 찍는다.**

### 판형 회귀 — `templates/danji-cover/sample.json`

오너 확정 시점(2026-08-03)의 카드 JSON을 **얼려서** 템플릿 옆에 둔다. 판형이 바뀌면 md5가 바뀐다.

```bash
pnpm --filter @wirit/renderer render -- --data ../../templates/danji-cover/sample.json --out /tmp/samp
md5sum /tmp/samp/sample-p1.png   # 확정 시점: 3dc78a132f5c2affb52f16eeb5e9abbc
pnpm --filter @wirit/renderer qa templates/danji-cover/sample.json
```

> **왜 `pixel-baselines.json` 이 아닌가.** 이 카드는 청약홈 수집분(`applyhome-latest.json`)을
> 읽는데, 그 파일은 워크플로가 **매일 갱신**한다. 접수가 끝나 공고가 목록에서 빠지면 빌더가
> 던지고 doctor 가 통째로 빨간불이 된다 — `confirm.mjs` 가 경고하는 '정기물을 기준값에 넣는'
> 실수다. **판형의 약속은 "픽셀이 안 바뀐다"가 아니라 "같은 데이터면 같은 픽셀"이다.**
> 그래서 데이터를 얼린 픽스처로 잰다.

## 12. `news-figure@1` — 인물(CEO·정치인)/뉴스 이슈 카드 (2026-08-05 시안)

> 오너 지시: 참고 계정(APT_LAP)의 "인물 사진 + 큰 헤드라인 + 형광펜 본문" 이슈 카드 방식을
> **위릿 판형으로** 한 판 잡아 달라. 크롬(72px 머리·우상단 `wirit.` 잉크 뱃지·잉크 푸터·
> 흰/잉크 프레임)은 `base.css` 상속, 형광펜·인물 배치만 새로 만들었다.

### 구조 (좌 헤드라인 / 우 인물, 하단 선택형 정보 바)

- **머리**: 좌 `.nf-src`(출처 줄) + 우 `.nf-chip`(카테고리 칩, 기본 잉크 / `accent`·`red`). 칩은
  우상단 `wirit.` 뱃지 자리(200px)를 비워 두고 왼쪽에 붙는다.
- **히어로**: 좌 `.nf-title`(태백체, `flex:1` — `__wiritFit` 이 좌열 폭에 맞춰 이분탐색으로 줄인다.
  줄바꿈은 빌더가 `\n` 으로 지정) / 우 `.nf-right`( `.nf-photo` 인물 사진 + `.nf-name` 이름·직함 태그).
- **본문**: `lead[]` — 항목마다 `.nf-lead`(좌측 잉크 괘선, `accent` 면 코발트) + `.nf-lead-h`(옅은 소제목)
  + `.nf-lead-t`(형광펜 강조). 형광펜은 `<mark>`(노랑·기본) / `<mark class="g">`(라임) / `<mark class="b">`(코발트).
- **하단(선택)**: `bars[]` — `{k,v}` 잉크 정보 바(접수기간·근무지 등). 없으면 그리지 않는다.
- **사진 없을 때**: `figure.photo` 미지정이면 실루엣 자리표시(`.nf-ph`)를 그린다(시안용). 실제 발행은
  `_shared/photos/` 에 인물 사진을 넣고 파일명을 지정한다. `figure.stamp` 로 사진 위 빨강 스탬프
  (예: "🖐 확정된 바 없음")를 빈 곳에 얹을 수 있다.

### 문서 필드

```json
{
  "template": "news-figure@1",
  "category": "부동산 이슈", "categoryStyle": "",
  "source": { "name": "…", "asOf": "…" },
  "headline": "수도권\n주택공급\n<span class=\"em\">보도해명</span>",
  "figure": { "photo": "person.jpg", "name": "○○○ 장관", "role": "국토교통부", "stamp": "🖐 확정된 바 없음" },
  "lead": [ { "heading": "보도내용 요약", "text": "… <mark>수도권 5만호 이상</mark> …" },
            { "heading": "부처 입장", "style": "accent", "text": "… <mark class=\"g\">확정된 바 없음.</mark>" } ],
  "bars": [ { "k": "접수기간", "v": "8.20 ~ 26" } ],
  "footer": "…"
}
```

### 규칙

- **오보 0**: 인물 발언·수치는 1차 출처(보도자료·공시)에서 확인한 것만. 시안(`build-news-figure.mjs`)은
  전부 예시 문구(`verified=false`)이니, 실제 카드는 원문을 대조해 채우고 세트 note 에 근거를 적는다.
- **강조는 형광펜으로**, 한 문단에 한 곳이 기본. 노랑/라임을 섞더라도 "무엇을 강조하는가"가 서게.
- **인물 사진**은 실물만. 없으면 실루엣 자리표시로 두고 발행 전에 채운다(직접 그린 초상 금지).
- 검수 등록: `designQa.ts` `LEAF` 에 `.nf-title,.nf-photo,.nf-src,.nf-chip,.nf-name .nm,.nf-name .role,`
  `.nf-lead-h,.nf-lead-t,.nf-bar .k,.nf-bar .v` 추가, `footerGap` 위 요소에 `.nf-bars,.nf-body` 추가
  (일부러 겹쳐 `textclip` 이 잡히는 것 확인함).

### 시안

```bash
node scripts/build-news-figure.mjs         # data/out/_spike/news-figure/*.json
pnpm --filter @wirit/renderer render -- --data <절대경로>/news-figure-demo-issue.json --out <절대경로>
pnpm --filter @wirit/renderer qa <절대경로>/news-figure-demo-issue.json   # error 0
```

> **미확정.** 오너가 이 판형을 고르면 `builders.json`·`sets.json` 에 등록하고, 첫 실제 카드를
> 확정할 때 판형 회귀용 `sample.json` 을 얼린다(danji-cover §11 방식). 그 전까지는 시안만 둔다.


## 13. `gov-bars@1` — 정부별 세로 막대 + 인물 사진 축 (2026-08-12)

정권 단위로 끊은 한 지표의 **누적 증가폭**을 세로 막대로 세우고, 가로축 자리에 인물 사진·이름·재임 개월을 놓는다.
첫 사용: 「역대 정부 통화량 증가 규모」(M2).

### 왜 `year-bars@2` 를 안 썼나
`year-bars@2` 는 **연도별 변화율**용이라 0선 위아래로 갈리고 지수 곡선이 얹힌다. 여기는 전부 플러스 누적값이고
0선 아래가 없다. 남의 판형에 억지로 끼우면 안 쓰는 요소가 유령처럼 남는다.

### 구조
`[뱃지=기준] → [제목 1줄 가운데] → [SVG 플롯: 좌상단 현재총량 · 막대 · 월평균 · 총액 알약 · 뱃지]
 → [인물 축: 사진 + 이름 + 재임개월] → [하단 문구(폭 채움)] → [푸터]`

| 필드 | 설명 |
|---|---|
| `chart.bars[]` | `x/y/w/h/fill` + 선택 `stroke/sw/dash`(진행 중 구간) |
| `chart.values[]` | 막대 위 큰 숫자 = **월평균**(주인공). 임기 길이가 12~62개월로 달라 총액만 세우면 오래 재임한 정부가 자동으로 커 보인다 |
| `chart.rates[]` | 막대 안 알약 = **총 증가액**(막대 높이가 뜻하는 그 값) |
| `chart.badges[]` | 빈 칸의 다줄 뱃지(그라데이션+네온). 줄마다 색을 준다 |
| `chart.level` | 좌상단 '지금 얼마나 쌓였나'. 막대(증가폭)와 축이 달라 글자로만 둔다. 줄마다 `size`·`dy` |
| `faces[]` | `name`·`term`(재임 개월)·`photo`(`-face.png`)·`hot` |

### 못박은 규칙
- **좌표는 전부 빌더가 계산한다.** 템플릿은 그리기만 한다.
- **SVG 좌우 여백 0** — 플롯의 끝 = 카드 패딩선 = 제목·푸터와 같은 선. 인물 축도 `gap: 0` 으로 같은 자를 쓴다.
- **색은 뜻 하나씩만.** 레드 = 현 정부(진행 중, 옅은 칠 + 점선) · 잉크 = 나머지 · 최대 총액은 **숫자 색으로만** 짚는다.
  (한때 최대 총액 막대를 레드/코발트로 칠했다가 "한 장에서 색이 두 가지를 뜻한다"로 되돌렸다)
- **진행 중인 구간은 모양으로도 말한다** — 점선 테두리. 글자만으로는 그래픽만 잘라 썼을 때 경고가 사라진다.
- 인물 사진은 `scripts/normalize-portraits.py` 로 **얼굴 크기를 재서** 맞춘 `-face.png` 를 쓴다.
- 새 글자 요소는 `designQa.ts` 의 `LEAF`(`.gb-sub,.gb-photo,.gb-name,.gb-term,.gb-note`)·`footerGap`(`.gb-note`)에 등록돼 있다.

### 정기물
M2 는 매월 갱신된다 — **`pixel-baselines` 에 넣지 않는다.** 약속은 "같은 데이터면 같은 픽셀"(결정성)이다.
