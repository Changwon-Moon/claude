# 실행 전략 — 비개발자가 Claude 세션들로 이 시스템을 완성하는 방법

이 문서는 "**누가(어떤 세션이), 언제, 무엇을, 어떤 순서로** 만드는가"를 정의한다. 로드맵(ROADMAP.md)이 '무엇을 만들지'라면, 이 문서는 '어떻게 작업을 진행할지'다.

---

## 1. 가장 중요한 개념 구분: 빌드타임 vs 런타임

혼동하기 쉬운 지점이라 먼저 정리한다. **"AI 에이전트 팀"은 두 종류가 있고, 서로 완전히 다르다.**

| | 빌드타임 (시스템을 만드는 동안) | 런타임 (시스템이 매일 돌아갈 때) |
|---|---|---|
| 누가 일하나 | **Claude Code 세션** (지금 이 세션 같은 것) | 파이프라인 안의 **Claude API 호출** (리서치·기획·편집 에이전트) |
| 어디서 도나 | 세션 컨테이너 (일회성) | **서버/GitHub Actions** (상시, 세션과 무관) |
| 당신의 역할 | PM — 마일스톤 지시, 결과 확인 | 편집장 — 아침 승인, 발행 승인 |
| 산출물 | 코드, 템플릿, 문서 (git에 커밋) | 카드뉴스 PNG, 인스타 게시물 |

즉, **로드맵의 "리서치팀·기획팀·편집팀 에이전트"는 Claude Code 세션이 아니다.** 그것들은 우리가 만들 소프트웨어의 부품(코드 + 프롬프트 파일)이고, 완성되면 서버에서 매일 새벽 자동으로 돈다. Claude Code 세션은 그 소프트웨어를 **만들어주는 개발자**다.

따라서 "세션을 여러 개 띄워 에이전트를 하나씩 맡긴다"는 접근은 필요 없다. 에이전트들은 이 저장소 안의 코드로 만들어지고, 세션은 그 코드를 작성하는 도구일 뿐이다.

## 2. 세션 운영 전략: 단일 저장소 + 마일스톤 단위 세션

### 2-1. 왜 "한 세션에서 전부"는 안 되는가

- 전체 구현은 수십 시간 분량의 작업 + 중간중간 **당신만 할 수 있는 일**(인스타 계정 전환, Meta 앱 승인, API 키 발급, 디자인 시안 고르기)이 끼어 있다. 한 번에 끝낼 수 없는 구조다.
- 세션 컨테이너는 일회성이다. 대화가 길어지면 맥락이 압축되고, 세션이 끝나면 커밋 안 된 작업은 사라진다.
- 한 세션에 너무 많은 걸 시키면 각 부분의 완성도 검증 없이 다음으로 넘어가 **부실이 누적**된다.

### 2-2. 왜 "세션별로 따로 설계 후 통합"도 아닌가

- 소프트웨어에서 가장 비싸고 위험한 작업이 **통합**이다. 각자 설계하면 데이터 형식·이름·가정이 미묘하게 어긋나고, 비개발자는 그 어긋남을 스스로 발견·수정하기 어렵다.
- 올바른 해법은 **계약 우선(contract-first)**: 부품 간 인터페이스(JSON 스키마, 파일 경로, 상태 이름)를 문서로 먼저 확정하고(이미 ARCHITECTURE.md에 있음), 모든 세션이 같은 계약을 읽고 구현한다. 그러면 병렬로 만들어도 끼워 맞춰진다.

### 2-3. 결론: 이렇게 운영한다

1. **이 저장소가 유일한 진실 원천이다.** 설계 문서, 코드, 진행 상황(STATUS.md)이 전부 여기 있다. 세션은 오고 가지만 저장소는 남는다.
2. **한 세션 = 한 마일스톤.** 아래 §4의 M1, M2… 단위로 새 세션을 열고, 준비된 프롬프트를 붙여넣고, 완료 기준을 확인하고, 커밋됐는지 확인하고 끝낸다.
3. **모든 세션은 시작할 때 CLAUDE.md와 STATUS.md를 자동으로 읽는다.** 그래서 "지난 세션에서 뭘 했는지" 설명할 필요가 없다 — 저장소가 기억한다.
4. **병렬은 독립 부품만.** 계약이 확정된 뒤에는 [템플릿 제작]과 [데이터 수집기]처럼 서로 안 만나는 작업은 세션 2개를 동시에 돌려도 안전하다(각자 다른 브랜치). 단, 부품들을 연결하는 오케스트레이터·대시보드는 반드시 순차로.
5. **당신의 품질 관리 도구는 '완료 확인 체크리스트'다.** 각 마일스톤에 비개발자가 눈으로/클릭으로 확인 가능한 기준을 정의해 뒀다(§4). 코드를 읽을 필요 없이, 결과물이 기준을 통과하는지만 본다.

### 2-4. 도구 선택: Claude Code vs Cowork

| 작업 | 추천 도구 |
|---|---|
| 이 저장소의 코드·템플릿·에이전트 구축 (M1~M12) | **Claude Code** (웹/데스크톱) — 지금 방식 그대로 |
| 레퍼런스 계정 분석 스프레드시트, 로고 수집·정리, 브랜드 시안 비교 같은 문서 작업 | Cowork도 가능 — 단, 결과물은 반드시 이 저장소에 커밋해 달라고 요청 |
| 인스타 계정 전환, Meta 앱 생성, API 키 발급 | **당신이 직접** (가이드는 M0 세션이 만들어 줌) |
| 완성 후 일일 운영 (승인, 지시) | 폰의 Slack/Telegram + 대시보드 — 세션 불필요 |

핵심 규칙: **어떤 도구를 쓰든 산출물이 이 저장소에 커밋되지 않으면 존재하지 않는 것과 같다.**

### 2-5. 파이프라인은 어디서 매일 도는가 (비개발자 친화 배포 전략)

- **1단계 (M5~M11): GitHub Actions 스케줄 실행.** 서버 없이 GitHub이 매일 새벽 파이프라인을 대신 실행해 준다. 관리할 인프라가 없고, 실행 로그가 웹에서 보이고, 소규모는 무료 한도로 충분하다. 비개발자에게 최적.
- **2단계 (규모 확장 시): 소형 서버(Fly.io/Railway)로 이전.** 대시보드를 상시 띄우거나 실행 시간이 길어지면 이전한다. 이전 작업도 마일스톤 하나로 세션에 맡기면 된다.

## 3. 당신(운영자)의 역할 정의

당신은 코드를 쓰지 않는다. 대신 아래 다섯 가지를 한다 — 이것이 "직접 컨트롤하고 감독한다"의 실체다.

1. **결정**: 니치, 브랜드, 템플릿 시안 선택, 자동화 수위(L0~L3) 조절 — 세션이 항상 선택지를 만들어 오고, 당신이 고른다
2. **계정·권한 소유**: 인스타그램, Meta 앱, API 키, GitHub — 모든 열쇠는 당신 명의
3. **마일스톤 발주와 검수**: §4의 프롬프트로 세션에 발주 → 완료 확인 체크리스트로 검수
4. **런타임 승인**: 완성 후엔 게이트 1·2에서 콘텐츠 승인 (OPERATIONS.md)
5. **방향 지시**: 자연어로 ("이번 주는 부동산 비중 줄여줘") — 시스템이 파라미터로 반영

## 4. 마일스톤 분해 (세션 발주서)

각 마일스톤은 **세션 1~2회 분량**이다. `[병렬 ○]` 표시는 선행 조건만 충족되면 다른 마일스톤과 동시에 다른 세션에서 진행 가능하다는 뜻. 각 항목의 "발주 프롬프트"는 새 세션에 그대로 복사해 붙여넣으면 된다.

> 진행 상황은 [../STATUS.md](../STATUS.md)에서 추적한다. 세션은 마일스톤을 끝낼 때마다 STATUS.md를 갱신할 의무가 있다(CLAUDE.md에 명시).

### M0. 준비 — 계정·키 발급 (당신 + 세션 반반)

- **내용**: 세션이 "따라하기 가이드"(스크린샷 포인트 포함)를 만들어 주면, 당신이 직접: ① 인스타그램 프로페셔널 계정 전환 ② Meta 개발자 앱 생성 + Instagram Graph API 권한 ③ 공공데이터포털·ECOS API 키 발급 ④ GitHub 저장소 Secrets에 키 저장
- **발주 프롬프트**: "docs/EXECUTION_PLAN.md의 M0을 진행해줘. 내가 직접 해야 하는 계정·API 키 발급 절차를 비개발자용 단계별 가이드(docs/guides/M0-setup.md)로 만들어줘. 각 키를 GitHub Secrets에 저장하는 방법까지 포함해서."
- **완료 확인**: 가이드를 따라 4개 항목을 완료하고, 키 이름 목록이 STATUS.md에 기록됨 (키 값 자체는 절대 저장소에 넣지 않음)

### M1. 레포 스캐폴딩 + 렌더러 코어

- **내용**: 모노레포 구조 생성, `콘텐츠 JSON → PNG` 렌더러 구현, 더미 템플릿으로 렌더 성공
- **발주 프롬프트**: "docs/EXECUTION_PLAN.md의 M1을 진행해줘. ARCHITECTURE.md와 TEMPLATES.md의 계약대로 렌더러를 구현하고, 더미 템플릿으로 1080×1350 PNG가 나오는 것까지 확인한 후 결과 이미지를 보여줘."
- **완료 확인**: 세션이 보여주는 PNG가 실제로 렌더됨 + STATUS.md 갱신 + 커밋 확인

### M2. 템플릿 1호: `ranking-table`

- **내용**: 랭킹표 템플릿 제작. 세션이 시안 2~3개를 렌더해서 보여주면 당신이 선택·피드백 (2~3회 반복)
- **발주 프롬프트**: "M2를 진행해줘. TEMPLATES.md 스펙대로 ranking-table 템플릿을 만들되, 스타일 시안 3개를 각각 렌더해서 이미지로 보여줘. 내가 고르면 그 방향으로 완성도를 올리자. 항목 5개/10개/15개, 긴 이름 케이스 렌더도 보여줘."
- **완료 확인**: 참고 계정과 나란히 놓고 어색하지 않은 수준의 PNG + 엣지 케이스 3종 통과

### M3. 템플릿 2·3호: `market-daily`, `vs-compare` [병렬 ○ — M2 완료 후, M4와 병렬 가능]

- **발주 프롬프트**: "M3을 진행해줘. M2에서 확정된 브랜드 스타일(base.css)을 재사용해서 market-daily와 vs-compare 템플릿을 만들고 샘플 렌더를 보여줘."
- **완료 확인**: M2와 같은 기준. 세 템플릿의 룩이 한 계정처럼 통일돼 보일 것

### M4. 데이터 수집기 P0: 증시·환율·금리 [병렬 ○ — M1 완료 후 가능]

- **내용**: 미국/한국 증시, 환율, 기준금리 수집기 + 정규화. GitHub Actions로 매일 새벽 자동 실행
- **발주 프롬프트**: "M4를 진행해줘. DATA_SOURCES.md의 P0 소스 수집기를 만들고, GitHub Actions 스케줄로 매일 자동 실행되게 해줘. 오늘 데이터를 실제로 수집해서 raw JSON 샘플을 보여줘."
- **완료 확인**: GitHub Actions 탭에서 초록 체크 표시 + raw JSON에 오늘 날짜의 실제 수치

### M5. 첫 무인 콘텐츠: 증시 데일리 E2E 연결

- **내용**: M4 데이터 → 자동 JSON 생성(코드) → M3 템플릿 렌더 → Instagram Graph API 발행까지 한 줄로 연결. **여기서 처음으로 "매일 자동 발행되는 콘텐츠"가 생긴다**
- **발주 프롬프트**: "M5를 진행해줘. 수집된 증시 데이터로 market-daily 콘텐츠를 자동 생성·렌더하고, Graph API로 내 계정에 테스트 발행까지 성공시켜줘. 이후 매일 아침 자동 실행되도록 GitHub Actions에 등록해줘."
- **완료 확인**: **당신의 인스타 계정에 자동 발행된 게시물이 실제로 보임** — 프로젝트 최초의 눈에 보이는 성과

### M6. 편집 에이전트 + 팩트체크

- **발주 프롬프트**: "M6을 진행해줘. AGENTS.md의 편집 에이전트와 팩트체크(코드 대조 + LLM 검증)를 구현하고, 지난주 raw 데이터로 ranking-table 콘텐츠를 1건 생성하는 데모를 보여줘. provenance 검증이 실패하는 케이스도 일부러 만들어서 반려되는 것까지 보여줘."
- **완료 확인**: 정상 케이스 통과 + 조작된 수치가 자동 반려되는 데모 확인

### M7. 리서치·기획 에이전트

- **발주 프롬프트**: "M7을 진행해줘. AGENTS.md대로 리서치·기획 에이전트를 구현하고, 오늘 데이터로 실제 브리핑과 기획안을 생성해서 보여줘. 프롬프트 파일은 prompts/ 아래에 두고 내가 나중에 문구를 고칠 수 있게 주석을 달아줘."
- **완료 확인**: 브리핑·기획안을 읽고 "이 정도면 내가 고를 만하다" 판단. 마음에 안 들면 프롬프트 수정 반복 (이 반복이 곧 팀 교육)

### M8. 오케스트레이터 + 모바일 승인 게이트

- **내용**: 상태 머신으로 전체 연결 + Slack/Telegram 봇으로 게이트 1·2 승인. **여기서 "아침에 폰으로 승인하는 하루"가 시작된다**
- **발주 프롬프트**: "M8을 진행해줘. ARCHITECTURE.md의 상태 머신으로 수집→리서치→기획→[승인]→편집→렌더→[승인]→발행을 연결하고, Telegram 봇 승인 게이트를 붙여줘. 전체 플로우를 1회 실제로 돌려서 내 폰으로 승인 요청이 오는 것까지 확인하자."
- **완료 확인**: 폰으로 기획안 수신 → 승인 → 자동 제작 → 발행 승인 → 실제 게시, 전 과정 1회 성공

### M9. 운영 대시보드 [병렬 ○ — M8 완료 후, M10과 병렬 가능]

- **발주 프롬프트**: "M9를 진행해줘. 파이프라인 칸반, 미리보기+인라인 수정, 승인/반려, 발행 이력을 갖춘 웹 대시보드를 만들어줘. 내 폰 브라우저에서도 쓸 수 있어야 해."
