# 운영 워크플로우 & 리스크 관리

## 1. 운영자의 하루 (Phase 3 완성 시점 기준 — 총 10~15분)

```
04:00~06:00  [자동] 수집기 실행 → raw 데이터 적재
06:00~07:00  [자동] 리서치 브리핑 → 기획안 3~5건 생성 → 데일리 고정 코너는 제작까지 완료
07:30        [사람·5분] ☕ 게이트 1: 폰으로 기획안 확인
             - ✅ 승인 / ✏️ "제목 2안으로, 부동산 건은 내일로" / ❌ 반려
08:00~10:00  [자동] 편집 → 팩트체크 → 렌더 → 디자인 QA
10:30        [사람·5분] 게이트 2: 최종 이미지+캡션 확인 → 발행 승인
11:00, 19:00 [자동] 슬롯별 발행 (Graph API)
익일         [자동] 인사이트 수집 → 성과 DB 적재
월요일       [사람·15분] 주간 성과 리포트 검토 → 다음 주 방향 한 줄 지시
```

**감독 수단**: 모든 개입은 폰(Slack/Telegram 봇) 또는 웹 대시보드에서. 자연어 지시가 파이프라인 파라미터로 반영되므로 "코드 수정 없이" 방향을 조종할 수 있다.

## 2. 승인 게이트 정책 (자동화 수위 조절 다이얼)

| 레벨 | 게이트 1 (기획) | 게이트 2 (발행) | 적용 시점 |
|---|---|---|---|
| L0 수동 | 사람이 기획 | 사람이 발행 | Phase 1 |
| L1 반자동 | 사람 승인 필수 | 사람 승인 필수 | Phase 2~3 |
| L2 신뢰 | 자동 승인 + 사후 통보 | 사람 승인 필수 | Phase 3 후반 |
| L3 무인 | 자동 | 자동 발행 + 사후 통보 (데일리 고정 코너만) | Phase 4, 콘텐츠 유형별 선택 |

**콘텐츠 유형별로 레벨을 달리 적용한다**: 증시 요약처럼 데이터가 기계적인 코너는 L3까지 올리고, 정책·정치 등 민감 소재는 L1을 유지. "최대한 자동화 + 내가 컨트롤"의 균형점.

## 3. 품질 관리 (오보 0건 체계)

1. 수치는 항상 1차 출처에서 코드로 추출 (LLM이 숫자를 쓰지 않음)
2. `provenance` 강제 — 출처 경로 없는 수치는 렌더 불가
3. 팩트체크 이중 검증 (코드 대조 + LLM 상식 검증)
4. 디자인 QA (비전 검사)
5. 사람 최종 승인 (게이트 2)
6. **발행 후 정정 프로세스**: 오류 발견 시 → 즉시 게시물 수정/삭제 → 정정 스토리 → 원인을 회귀 테스트로 추가

## 4. 리스크 레지스터

| 리스크 | 영향 | 대응 |
|---|---|---|
| 수치 오보 | 계정 신뢰도 치명타 | §3 체계 + 민감 콘텐츠 L1 유지 |
| 데이터 소스 중단/포맷 변경 | 콘텐츠 결측 | 소스별 스키마 검증 + 실패 알림 + 콘텐츠 뱅크 폴백 |
| Instagram API 정책 변화·계정 제재 | 발행 불가 | 발행 빈도 준수(도배 금지), 커뮤니티 가이드 준수, 수동 발행 폴백 절차 문서화 |
| 저작권 (로고·지도·폰트·데이터) | 법적 분쟁 | DATA_SOURCES.md 체크리스트, 라이선스 확인된 자산만 라이브러리 등록 |
| 유사 계정과의 차별화 실패 | 성장 정체 | 니치 특화 + 성과 학습 루프로 독자 포맷 개발 |
| LLM 비용 폭주 | 운영비 초과 | 에이전트별 모델 등급 분리, 일일 비용 한도 + 알림 |
| 운영자 부재 (휴가 등) | 결측 | L3 코너 + 콘텐츠 뱅크로 최소 발행 유지, "무인 모드" 스위치 |

## 5. 콘텐츠 뱅크 (재고 시스템)

- 시의성 없는 에버그린 콘텐츠(역대 총정리, 개념 설명, "다시보는" 시리즈)를 한가한 시간에 미리 생산 → 검수 완료 상태로 재고화
- 목표 재고: **최소 7일치**. 이슈가 없는 날, 소스 장애일, 운영자 부재일에 자동 투입
- 참고 계정도 같은 전략을 쓴다: "다시보는 하이먼 민스키", "역대 대통령 학력 총정리" 같은 콘텐츠는 시의성이 없어 언제든 발행 가능

## 6. 성장 전략 메모

- **저장(save) 최적화**: 인포그래픽 계정의 알고리즘 핵심은 저장률. "나중에 다시 볼 정보"(순위표, 총정리, 일정표)가 저장을 부른다 — 기획 스코어링에 반영됨
- **시리즈화**: "동별 대표 APT", "5년 변화" 같은 반복 시리즈는 팔로우 유인 + 생산 자동화 둘 다에 유리 (파라미터만 바꾸면 되므로)
- **발행 리듬**: 데일리 고정 코너(신뢰·습관 형성) + 이슈 대응(도달 확장) + 에버그린(저장 수확)의 3축 믹스
- **초기 90일**: 팔로워보다 포맷-성과 데이터 확보가 목표. 어떤 [포맷×소재]가 이 계정에서 통하는지 학습이 끝나면 스케일은 자동화가 해결한다
