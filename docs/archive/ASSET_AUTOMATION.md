# 실사 이미지(로고·사진) 자동 취득 설계

> 오너 질문: "실사 이미지가 앞으로도 많이 쓰일 텐데, 내 개입 없이 자동으로 못 하나?"
> 답: **된다. 단, 코드 대화창(이 세션)이 아니라 네트워크가 열린 GitHub Actions에서, 라이선스가 안전한 소스에서만.**

## 1. 왜 이 세션에선 못 긁나 (사실관계)

이 세션의 아웃바운드는 **정책 프록시**를 거친다. npm·pypi 등 패키지 레지스트리와 Anthropic만 허용되고, **일반 웹/회사 홈페이지/구글/위키미디어로의 이미지 다운로드는 403·차단**된다(실측: HTTP 000/403). 그래서:
- WebSearch/WebFetch는 **텍스트**만 준다(이미지 바이너리 X).
- 회사 홈페이지 CI 파일도 여기선 못 받는다.
- **유일하게 되는 자동 소스 = npm 패키지**(예: simple-icons) + 오너가 저장소에 올린 파일.

→ **진짜 자동화는 네트워크가 열린 GitHub Actions에서** 돌려야 한다(데이터 수집기가 이미 거기서 도는 것과 동일).

## 2. 로고 — 3단계 자동 해결기 (거의 무개입)

| 티어 | 소스 | 키 | 어디서 | 커버리지 |
|---|---|---|---|---|
| **A** | **simple-icons** (npm) | 불필요 | 이 세션·Actions 어디서나 | 글로벌·대형 소비 브랜드(현대·기아·삼성·LG·네이버·카카오…) |
| **B** | **Wikimedia Commons** API | 불필요 | Actions | 한국 대기업 상당수(SK하이닉스·한화·포스코·HMM·삼성바이오·HD현대 등) — 라이선스 태그 있는 파일만 |
| **C** | Brandfetch/Clearbit (도메인→로고) | 무료키 1개 | Actions | B에서 빠진 잔여(웹사이트 있는 거의 모든 회사) |
| 사람 | 오너가 파일 업로드 | — | — | 잔여 극소수 |

- **A**: `scripts/lib/logo-resolver.mjs` — 회사명→simple-icons 매칭→`_shared/logos/{slug}.svg` 생성+카탈로그. (이미 가동: 기아 실로고 등)
- **B**: `packages/collectors/src/sources/logoFetch.ts` + `logoCli.ts` — 검색→최적 파일 선택(svg·logo 우선)→**라이선스 안전성 검사**(PD-textlogo·CC·PD·trademark만 허용)→다운로드→카탈로그에 출처·라이선스 기록. 파서 셀프테스트 통과. 워크플로 `.github/workflows/asset-fetch.yml`(수동 실행).
- **법적**: 로고는 상표. 사실 식별용 **nominative use**는 허용. Commons의 라이선스 태그를 그대로 기록해 근거를 남긴다.

**무개입 흐름(Actions)**: 데이터셋의 회사 목록 → `fetch-logos` → 새 로고 커밋 → 카드 빌드가 자동으로 실제 로고 채택. 못 찾은 것만 오너에게 목록으로 보고.

## 3. 실사 사진 — 반자동 (저작권 때문에 사람 확인 유지)

사진은 로고와 다르다. **아무 웹/뉴스 사진을 긁으면 저작권 침해**다. 그래서 **라이선스 안전 소스**로만, 그리고 **관련성 판단은 사람이**:

| 종류 | 방법 | 자동화 |
|---|---|---|
| 범용 이미지(도시 스카이라인·돈·반도체 웨이퍼·빌딩 일반) | **Unsplash·Pexels·Pixabay** API(무료·관대 라이선스) 키워드 검색 | 후보 자동 수집(R2) → 관제탑에서 사람이 택1 |
| 특정 랜드마크·건물 | **Wikimedia Commons**(CC/PD) | 후보 자동(R1) |
| 공공 이미지(정부·통계) | **공공누리(공공저작물)** | 자동(R2) |
| 특정 아파트·인물·사건 | 안전 소스 없음 → **뉴스 사진 금지**. 그래픽/일러스트 대체 or 오너 제공 | 사람(R0) |

- 사진 파이프라인: 키워드→라이선스 필터 검색→후보 다운로드→catalog에 **라이선스·저작자·출처** 기록→관제탑 디자인 QA에서 사람이 승인.
- **가드레일**(코드로 강제): 라이선스 ∈ {public-domain, cc, open, 공공누리} 아니면 취득 거부. 뉴스·출처불명은 자동 차단.

## 4. 자동화 수위(R0~R3) 적용

- **로고**: R2~R3. 소싱이 결정적이고 법적으로 깨끗(nominative) → 거의 무인. 잔여만 사람.
- **범용 스톡 사진**: R1~R2. 자동 후보 → 사람이 관제탑에서 택1(관련성·품질).
- **특정 실물 사진**: R0~R1. 저작권 위험 커 사람이 제공/승인.

## 5. 오너가 할 1회 준비 (선택)

- **로고 B티어(Wikimedia)**: 키 불필요 — 바로 가능.
- **로고 C티어(Brandfetch)**: 무료 키 1개 → GitHub Secrets `BRANDFETCH_API_KEY` (선택, 커버리지 보강용).
- **사진**: `UNSPLASH_ACCESS_KEY`(무료) → GitHub Secrets. 없으면 Wikimedia/공공누리만 사용.

## 6. 지금 상태 / 다음

- ✅ 티어 A(simple-icons) 가동, 티어 B(Wikimedia) 코드+테스트+워크플로 완성.
