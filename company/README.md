# wirit 주식회사 — 회사 운영 체계

> 이 저장소는 단순한 코드가 아니라 **하나의 회사**다. 운영자(오너)가 방향을 정하고, CEO 에이전트가 오너의 판단을 선별적으로 누적 습득하며, 9개 팀이 각자의 도구·지식을 가지고 일하면서 **스스로 학습해 성장**한다.

## 조직도

```
                    👤 오너 (운영자)
                     │  결정·취향·거부권
                    🧠 CEO ─ 오너 판단의 누적 습득 → 전 팀에 전파 (company/CEO.md)
                     │
 ┌─────────┬─────────┼──────────┬─────────────┐
 트렌드분석   리서치     기획        자료허브       (지원)
 수요·패턴    소재·데이터  편성·시리즈  자산·캐시

      └──── 편집 → 품질검수 → 디자인 → 마케팅·성장 ──→ 성과 ♻️ 트렌드분석으로
```

## 학습 프로토콜 — 회사가 똑똑해지는 방법

**모든 세션은 오너의 피드백을 받으면 다음 중 알맞은 곳에 기록할 의무가 있다** (CLAUDE.md 규칙):

1. **판단·취향·전략** ("테두리는 잉크네이비로", "수요 검증이 더 중요해") → `CEO.md`의 판단 원칙에 추가
2. **특정 팀의 일하는 방식** ("검수에서 이런 것도 봐줘", "캡션은 이 톤으로") → 해당 `teams/{팀}.md`의 학습 로그에 추가
3. **소재 선택의 이유** → `DECISION_LOG.md`
4. **터진 콘텐츠 발견** → `PATTERN_LIBRARY.md`

기록 형식: `날짜 | 배운 것(한 줄) | 출처(오너 발언 요지)` — 나중에 각 팀의 런타임 에이전트(M6~)를 만들 때 **이 로그가 시스템 프롬프트의 재료**가 된다. 즉, 지금 쌓는 학습 로그 = 미래 AI 직원의 교육 자료.

### 선별 습득의 원칙 (CEO)
- 오너의 **일회성 지시**(이번 카드만 이렇게)와 **영구 원칙**(앞으로 항상 이렇게)을 구분한다. 애매하면 원칙 후보로 적되 `(확인 대기)` 표시 → 다음 기회에 오너에게 확인
- 원칙끼리 충돌하면 **최신 발언이 우선**하되, 구 원칙은 삭제하지 않고 취소선으로 남긴다(판단 변화의 역사도 학습 데이터)
