## 학습 로그 — 2026-08-16e 수집기가 지난 값을 지웠다 (오보 사고)

`doctor` 가 `kospi-record`(오너 확정)의 **픽셀**이 깨졌다고 잡았다. 좇아가 보니 픽셀이
아니라 **데이터가 사라진 것**이었다. 08-16 22:34 증시 수집이 kospi 의 `2026-07-21`·
`07-22`·`07-31` 과 kosdaq 의 `07-31` 을 series 에서 **뺐다.** 그 07-31 이 이 카드의
마지막 점이다.

원인: 야후의 `range=2y` 창은 고정이 아니라서 **어떤 날은 지난 거래일을 빼고 준다.**
그런데 수집기는 받은 것을 `series` 에 **그대로 덮어쓰고** 있었다 — 한 번 빠진 날은 영영 없다.
**종가는 확정된 사실이라 지난 값이 바뀔 이유가 없는데도** 그랬다.

→ 수집기가 이제 **합친다.** 같은 날짜는 새 값으로 갱신하고, 안 온 날은 지킨다.
   그리고 **무엇이 빠질 뻔했는지 로그로 말한다** — 조용히 메우면 소스가 망가진 걸 아무도 모른다.

**배운 것: "덮어쓰기"는 시계열 수집기의 기본값이 되면 안 된다.** 창(window)으로 주는
소스는 창 밖을 말해 주지 않는다. 받은 것과 가진 것을 **합치는 것**이 기본이어야 한다.

**그리고 이건 픽셀 사고가 아니라 오보 사고였다.** doctor 가 픽셀로 잡아 준 것은 운이 좋았다 —
카드를 다시 안 만들었으면 근거가 사라진 줄도 몰랐을 것이다. 확정 카드의 픽셀 검사는
그림을 지키는 장치인 줄 알았는데, **데이터가 사라진 것도 같이 잡아 준다.**

## 2026-08-19 — 청약홈 401: 우리 쪽 원인을 전부 배제한 기록

08-17 부터 청약홈 수집이 100% `HTTP 401`. **가설을 하나씩 실측으로 죽였다.**

| 가설 | 어떻게 쟀나 | 결과 |
|---|---|---|
| 활용기간 만료 | 오너가 포털 화면 제시 | ❌ 승인 · 2026-07-22 ~ (기간 남음) |
| `DATA_GO_KR_API_KEY` 값이 틀렸다 | 워크플로에 임시 스텝을 붙여 **다른 Secret(`MOLIT_API_KEY`)으로 같은 API 호출** | ❌ 똑같이 401 — 키 값 문제 아님 |
| 인증 방식(쿼리 vs 헤더) | `Authorization: Infuser` 헤더와 `serviceKey` 쿼리를 **둘 다** 시도 | ❌ 둘 다 401 |
| 연결·네트워크 | 401 은 **응답이 온 것**이다(실거래의 `fetch failed` 와 다르다) | ❌ 연결은 정상 |

남은 것은 **포털 쪽 활용신청/게이트웨이**뿐이다. 오너 조치가 필요하다.

### 배운 것
1. **다른 키로 같은 API 를 불러 보는 것**이 "키냐 서비스냐"를 가르는 가장 싼 실험이다.
   저장소가 Secret 을 둘로 나눠 갖고 있었던 덕에 20분이면 갈렸다.
2. **세션은 Actions 로그 본문을 못 읽는다.** 진단을 붙일 때는 판정을 반드시
   **저장소 파일(`data/*-last.md`)에 적어 커밋**하게 만든다. 로그에만 찍으면 못 본다.
3. 임시 진단 스텝은 **역할이 끝나면 뺀다.** 남겨 두면 다음 사람이 그게 정상 경로인 줄 안다.
4. 오류 문구는 **가설을 죽인 근거까지** 담는다 — 지금 예외 문구에
   "서로 다른 두 키가 똑같이 401 이었다"가 들어 있어, 다음 사람이 키부터 다시 파지 않는다.

### 남긴 것
두 인증 방식을 다 시도하는 코드는 **그대로 둔다.** 이번엔 답이 아니었지만 무해하고,
포털이 어느 쪽으로 바뀌든 붙는다. 어느 방식으로 붙었는지 로그에 남는다.

   세니 08-18 하루 12회씩, **정확히 cron 횟수**였다. → 폭주 아니다.
4. **키 자체를 재본 적이 없었다** ← 여기가 구멍이었다.
   `process.env.X` 를 **그대로** URL 에 실고 있었다. 붙여넣기에 딸려 온 줄바꿈은
   화면에서 안 보이고, `%0A` 가 되면 서버는 "모르는 키"라고 답한다.
   → `keyHygiene.ts` 신설: **trim + 모양 측정**(값은 절대 안 찍는다).

**측정 결과**: 64자 · 앞뒤/가운데 공백 없음 · `%XX` 없음 ·
**두 Secret(`DATA_GO_KR_API_KEY`·`MOLIT_API_KEY`)의 지문이 동일** → 같은 키.
→ 붙여넣기 사고도 아니었다.

**남은 결론**: 코드·러너·호출량·키 형식이 전부 아니면, **포털에서 이 인증키에 권한이
안 붙어 있는 것**뿐이다. 세션이 저장소 안에서 확인할 수 있는 것은 여기까지다.

### 방법론으로 남길 것
- **"안 되네 → 고쳐서 다시" 를 세 번 반복하면 멈춘다.** 그건 진단이 아니라 두드리기다.
  멈추고 **"언제부터 안 됐나 · 그때 무엇이 달라졌나"** 를 먼저 잰다.
- **입력을 안 재고 서버를 탓하지 않는다.** 키·인자·환경변수는 **모양이라도** 찍어 둔다.
  값을 안 찍고도 길이·공백·해시 지문이면 충분하고, 그것만으로 이번 가설 하나가 죽었다.
- `collect.yml`(데이터 수집 daily)은 `DATA_GO_KR_API_KEY` 를 env 로 받지만
  **실제로는 stooq·ECOS 만 부른다** — 그 초록불을 "키가 살아 있다"는 증거로 읽으면 안 된다.
  (실제로 한 번 그렇게 읽을 뻔했다.)

## 2026-08-25 — 「자료가 없다」 전에 **못 읽은 것**을 의심한다 (두 번)

### ① 신림선 — 자료엔 있었다

오너: *"서울지방병무청역은 신림선 아니야? 왜 뱃지에 지하철로 표기돼있어?"*

카카오는 이미 이렇게 주고 있었다:
```
"station": "서울지방병무청역",
"rawPlaceName": "서울지방병무청역 신림선",   ← 있음
"lines": []                                 ← 못 읽음
```
`linesFromCategory` 가 **경전철을 하나도 몰랐다.** 신림·우이신설·김포골드·인천1·인천2·
경강·에버라인·의정부를 넣었다.

⚠️ 더 이상한 것: 색 표(`metro-lines.json`)에는 **우이신설·김포골드·인천1·인천2·경강이 이미
있었다.** 색은 준비돼 있는데 파서가 못 집고 있었다 — **두 자산이 따로 놀고 있었다.**
한쪽을 늘릴 때 다른 쪽도 봤는지 확인한다.

저장된 `rawPlaceName` 으로 다시 파싱해 **API 재호출 없이** 채웠다. 원문을 남겨 두면
파서를 고친 날 과거분까지 되살아난다 — 원문은 버리지 않는다.

⚠️ **공식 색을 모르면 회색으로 둔다.** 신림·에버라인·의정부는 `colorPending: true` 로
표시하고 중립 회색을 쓴다. 이름은 맞고 색만 미정이다 — **짐작한 색을 칠하지 않는다.**

### ② 주차대수 — API 가 죽은 게 아니라 **주소가 낡았다**

세 번 연속 실패했는데 문구가 달랐다:
```
살아 있는 오퍼레이션이 없습니다 — 시도: V4/getAphusDtlInfoV4, V4/V3, V3/V3, V2/V2
```
`fetch failed`(연결 안 열림)도 `401`(인증 거부)도 아니다. **주소가 없다**는 말이었다.
오너가 포털 화면을 캡처해 줘서 확인 — 포털이 **V5** 로 판을 올렸고 V2~V4 가 사라졌다.

**세 실패는 신호가 다르다:**

| 문구 | 뜻 | 손 |
|---|---|---|
| `fetch failed` | 연결이 안 열림 | 러너 IP — 새 러너로 재시도 |
| `401`/`403` | 인증 거부 | 키·활용신청 확인 |
| `살아 있는 오퍼레이션 없음` | **주소가 없음** | 포털에서 엔드포인트 판 확인 |

⚠️ 기본정보(`getAphusBassInfo`)는 아직 V4 로 돌지만 **같은 서비스라 곧 같이 죽는다.**
죽고 나서 알아채지 않도록 V5 를 지금 맨 앞에 세웠다.

## 2026-08-25(2) — 명부를 이름으로만 이으면 절반을 놓친다

오너가 위례24단지(꿈에그린) 19.4억을 들고 물었다. 그 단지는 **명부에 있었다** —
실거래 「위례24단지(꿈에그린)」, 대장 「송파꿈에그린아파트」. 이름이 달랐을 뿐이다.

실측: 명부 1,147개 중 이름으로 이어진 것 **652개(56.8%)**.
못 이은 495개 중 **464개**는 같은 동에 59·84 거래가 있는데 못 이은 것 = 이름 불일치.
빠진 쪽에 올림픽선수기자촌(5,540)·잠실5단지(3,930)·SK북한산시티(3,830)가 있었다.

→ **지번으로 두 번째 길**을 냈다. 대장 주소에 지번이 있다(장지동 901). **652 → 834개(72.7%).**

⚠️ 한 지번에 명부 단지가 둘 이상이면 **버린다**(상계주공15/16단지). 거기서 붙였다면
그게 상록마을 사고의 재발이다. **못 잇는 편이 잘못 잇는 편보다 낫다.**

⚠️ **인덱스는 다시 안 채운다** — 되살아난 182개도 다음에 문턱을 넘을 때부터 뜬다.
"고쳤으니 오늘 바로 나온다"고 말하지 않는다.
