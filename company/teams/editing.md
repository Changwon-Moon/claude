# ✏️ 편집팀

**가치관**: 모든 숫자에 출처 경로. 출처 없으면 카드 없다.
**책임**: 기획안+데이터 → 템플릿 콘텐츠 JSON 생성. 수치는 코드로 추출, 문구만 작성

## 도구 (구현됨)
- 결정적 변환 파이프라인: `packages/pipeline` (raw→콘텐츠 JSON→렌더, 예: 간밤의 미국 증시)
- **DART 평균연봉 카드 빌더(구현)**: `scripts/build-avgsalary-card.mjs` — 데이터셋(1차 출처)에서 수치를 **코드로 추출**해 순위표 콘텐츠 생성. 동일값 **공동순위(rank)**, 직원수 **figure-space 소수 정렬**, 로고 자동 해결. LLM 수치 창작 0(provenance 준수)
- 포맷 헬퍼: `packages/pipeline/src/format.ts` (천단위·등락·날짜)
- 스키마 검증: 템플릿별 `schema.json` (위반 시 렌더 거부)

## 지식
- 캐시 우선 원칙: `data/datasets` 확인 → 없으면 수집 → 등록
- 문체: 명사형 종결, 숫자 우선, 과장 금지 (`docs/AGENTS.md`)

## 기본 업무 기준 (07-21 확정)
- **빌더는 수치를 코드로 추출 + 재계산 내부정합 검증**: 파생값은 원자료로 다시 계산해 대조하고 임계 초과 시 경고(예: 표정속도=거리÷(분/60) vs 표기값, 오차>2km/h 경고). LLM 수치 창작 0
- **빌더가 카드 세트를 일괄 생성**: 하나의 데이터셋 → 커버·표·2단·하이라이트 등 파생 JSON을 한 스크립트로(예: `build-metro-speed-card.mjs` 5종). 정렬·태그·하이라이트도 코드로 결정
- **provenance 필수**: 모든 표기 수치는 데이터셋(1차 출처) 경로를 가진다. `verified` 플래그는 편집이 아니라 검증(리서치/검수) 후 승격
- 문구(제목·후킹·CTA)만 사람/세션이 작성, 수치는 손대지 않는다

## 학습 로그 — 2026-08-16 캡션

- **금액을 손으로 옮겨 적지 않는다.** 캡션 검수는 캡션의 '억' 금액이 카드 수치에 있는지 대조한다
  (`captionNumberMatch`). 보고 적는 순간 그게 오보의 자리다.
  → `node scripts/gen-singo-caption.mjs <카드.json> --out <세트라벨>` 이 카드 `meta` 에서 꺼내 쓴다.
- **생성된 캡션은 초안이다.** 문장을 다듬는 건 사람 몫이지만, **카드에 없는 사실**(재건축·학군·호재)은
  덧붙이지 않는다. 덧붙이는 순간 카드가 근거를 대지 못한다.
- **날짜는 계약일**로 쓴다. 발행일을 쓰면 "오늘 팔린 값"으로 읽힌다.
- **"역대"라고 쓰지 않는다.** 기준선은 2020-01 이다.

## 학습 로그 — 2026-08-16b 캡션 생성기

- **이야기의 순서는 데이터를 만든 순서가 아니다.** "걸어온 길"을 `시작 → 최저점 → 사이클고점`
  으로 못박아 넣었더니, 최저점이 고점보다 **나중**인 단지에서 2023년 다음에 2021년이 나왔다.
  그날 만든 5장 중 3장이 그랬다. → 양 끝은 고정, **가운데 마디는 날짜로 정렬**.
- **같은 사건을 두 이름으로 부르지 않는다.** 늘푸른벽산은 2021.09 5.8억이 '지난 사이클 고점'이자
  '직전 최고가'였는데, 두 문장으로 적으니 서로 다른 두 거래처럼 읽혔다. 같으면 한 번만 말한다.
- **연도는 날짜 앞에.** `11월 22일 …이었습니다. (2025년)` 은 다 읽고 나서야 연도를 안다.
- **해시태그는 검색하는 말로.** `수원시영통구` 를 그대로 쓰면 `#수원시영통아파트` 가 되는데
  아무도 그렇게 검색하지 않는다 → 시를 쓴다(`#수원아파트`). 태그 상한이 5개라 지역은 한 자리뿐이다.
- **생성기는 확정본을 못 덮는다.** 확정 캡션에는 사람이 다듬은 문장과 고정 서명이 들어 있다.
  실제로 광명한진타운 확정본을 덮어써서 되살려야 했다 → `state: 오너 확정` 이면 스스로 멈춘다.

## 학습 로그 — 2026-08-16d 서명은 절차의 맨 뒤에 붙인다

고정 서명(위릿노트 3줄)은 **캡션을 다시 쓰는 모든 단계**보다 뒤에 와야 한다.
`rebuild-cards` 만 조심하면 되는 줄 알았는데 `doctor` 도 카드를 다시 만든다 —
그래서 재생성 직후에 붙여도 뒤의 doctor 가 날렸다.

→ 순서: 카드를 만드는 것 전부 → **`apply-signature`** → **`apply-signature --check`**.
붙였다고 믿지 말고 **붙었는지 증명한다.** `--check` 없이는 다음 세션이 또 잃는다.

캡션에 주차 한 줄이 붙었다(`세대당 주차는 N대입니다`). 카드 `meta.parking` 에서 코드가
꺼낸다 — 사람이 카드를 보며 옮겨 적지 않는다.

## 학습 로그 — 2026-08-25 알림 문구는 **재는 것과 같아야** 한다

오너가 두 번 물었다 — *"계약일은 한참 전인데 왜 오늘 뜨냐."*

**기준은 맞았다.** 알림은 이미 「그날 처음 문턱을 넘은 건」만 싣는다. 오해의 원인은
목록의 계약일이 흩어져 보인 것이고, 그건 신고기한(최대 30일) 탓이다.
8월 히트 93건 실측: 계약→확인 **중앙값 10일**, 최장 37일, **계약 다음 날 들어온 건 0건.**

→ **고칠 곳은 기준이 아니라 문구였다.** 제목을 「오늘 **새로 확인된** 신고가」로 바꾸고,
목록 끝에 계약일이 섞이는 이유 두 줄을 붙였다. **같은 질문이 두 번 오면 그건 문서화 실패가
아니라 산출물 자체의 결함이다.**

⚠️ 그 두 줄을 **셀프테스트로 붙잡았다.** 문구는 리팩터링 때 가장 먼저 사라진다.
지워서 2건이 실패하는 것을 확인한 뒤 되돌렸다.

⚠️ **알림 본문에 마크다운을 쓰지 않는다.** `notify-telegram` 은 `parse_mode` 를 안 넘겨
평문으로 보낸다 — `**굵게**` 를 적으면 별표가 그대로 찍힌다. 미리보기에서 잡았다.
**보낼 문구는 보내는 형태로 미리 찍어 본다.**
