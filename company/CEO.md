> **역할**: 오너(운영자)의 결정·취향·거부를 관찰해 **영구 원칙**으로 선별 축적하고, 모든 팀이 일하기 전에 이 원칙을 참조하게 한다. 오너가 같은 말을 두 번 하게 만들지 않는 것이 CEO의 존재 이유다.

> **갱신 규칙**: [README.md](./README.md) 학습 프로토콜. 일회성 지시는 여기 안 적는다. 충돌 시 최신 우선, 구 원칙은 취소선 보존.

## 2026-07-31 정비사업 지도 카드에서 굳은 원칙

한 장을 만들며 오너가 열두 번 되짚었다. 아래는 **다음 카드에 기본으로 적용**한다 —
다시 말하게 하면 그건 이 문서의 실패다.

### 일하는 순서

- **단계마다 끊어 묻는다.** 소재 → 그림 형태 → 제목 → 확정 → 캡션. 앞 단계를 오너가
  승인하기 전에 다음 단계를 만들어 오지 않는다. 특히 **캡션은 카드가 확정된 뒤에** 쓴다.
- **"가능한지 시험해 보고 싶다"는 실험을 하라는 말이다.** 완성품을 대신 내밀지 않는다.
  시험 산출물에는 "발행 금지"라고 적고 sets.json 에 올리지 않는다.
- **선택지는 렌더해서 보여준다.** 제목 3안·로고 14종·색 팔레트 모두 이미지 한 장으로
  비교하게 만든다. 글로 설명한 선택지는 오너의 시간을 쓴다.
- **자동으로 가져온 자산은 붙이기 전에 대조표로 확인받는다.** 로고 자동 취득은 이름만
  보면 성공으로 찍히지만 그림은 다른 것일 수 있다(2026-07-31 '더샵'을 찾다 포스코이앤씨
  회사 로고를 집었고 로그에는 ✅ 로 남았다).
- **오너가 준 원본은 지우지 않는다.** `_source/` 에 받은 그대로 두고 가공본은 따로 만든다.
  규격을 다시 잡을 때 오너에게 파일을 또 달라고 하지 않기 위해서다.

### 캡션 (발행본이 기준)

- **짧게. 카드가 이미 말한 것은 캡션에서 반복하지 않는다.** 2026-07-31 오너는 내가 쓴
  47줄에서 절반을 덜어내고 올렸다. 무엇을 덜어냈는지는 `data/review/captions/_alt/README.md`.
- **구조**: 훅 한 줄 → 핵심 수치 한 줄 → 순위·목록 → **전환 한 줄**("그런데 지도를 보면
  다른 게 보입니다") → 두 번째 목록 → 저장 유도 → 출처 → 해시태그.
- **「짚고 갈 점」은 오해를 부르는 것만 남긴다.** 단서를 목록으로 길게 붙이면 본문이 묻힌다.
  카드에서 뺀 각주라고 캡션에 다 옮기지 않는다.
- **해시태그는 최대 5개**(코드가 막는다 — `CAPTION_MAX_TAGS`, 초과는 error), **사람이 검색창에 치는 한글**(`#서울재개발 #서울재건축 #정비사업`). 규칙 정본은 `docs/CAPTION.md`.
  브랜드·지역 태그를 열 개씩 붙이지 않는다.

### 출처

- **기사 한 건에서 온 수치를 '각종 뉴스 기사'라고 쓰지 않는다.** 없는 취재를 있다고 말하는
  것이다. 매체명과 날짜를 적고, 그 매체가 취합한 것이면 그렇게 적는다
  (`뉴시스 (2026.7.30) · 각 사 취합`).
- 좌표·지오코딩처럼 **내가 붙인 처리도 출처에 적는다**(`카카오 로컬 검색으로 좌표 확인`).
- **여러 시점의 자료를 한 카드에 담으면 푸터에 기준일을 적지 않는다** (2026-07-31 오너 "기준일 지워줘").
  브랜드 순위 카드는 다섯 조사의 발표 시점이 2025.3~2026.7 로 제각각인데, 아래에 날짜를 하나
  적으면 **다섯이 모두 그 날짜인 것처럼 읽힌다.** 그건 틀린 정보다.
  시점이 줄마다 다르면 시점도 줄마다 적는다 — 이 카드는 표 왼쪽 칸이 갖고 있다.
  기준일은 카드 전체가 **한 시점의 스냅숏일 때만** 쓴다.

### 아이덴티티는 그래픽에 양보하지 않는다 (2026-07-31)

- **카드 머리(위 여백·우상단 뱃지·상단캡)는 공용 규격 그대로 쓴다.** 지도를 키우려고
  머리를 줄이면 그 카드만 계정에서 튄다 — 한 계정의 카드는 윗부분이 같아야 시리즈로 읽힌다.
  세로가 모자라면 **그래픽이 양보한다.**
- **눈으로 비교해야 알아채는 것은 검수로 내린다.** 이 건은 오너가 완성본 3장과 나란히 놓고서야
  발견했다. 배경색·글자 크기·패딩은 좌표로 잴 수 있으므로 `designQa brandhead` 로 승격했다.
- **제목을 키우면 아래 여백이 함께 줄어든다** (2026-07-31 오너 "제목과 표 헤드라인이 너무 붙어있어").
  제목은 카드 폭을 채우도록 자동으로 커지는데, 여백을 건드린 적이 없어도 아래가 좁아진다.
  **"더 크게"를 반영한 다음에는 반드시 아래 간격을 다시 본다.** 좌표로 잴 수 있으므로
  `designQa titlegap` 으로 승격했다(제목 아래 28px 미만이면 경고).
- **세로가 모자라면 그래픽이 줄어 여백을 만든다.** 여백은 남는 자리가 아니라 배정하는 자리다.
- **출처에는 원 출처를 적는다.** 수치의 출처는 각 사 발표이고 매체는 그것을 모아 준 경로다.
  카드에는 원 출처를 적되, 어느 기사에서 옮겼는지는 데이터셋과 research/ 에 남겨 추적 가능하게 둔다.

부딪혔다 — 코드 체계가 지도와 안 맞고(동작구 11200 vs 11590), API 규격을 세션에서 검증할 수 없었다.
**그대로 진행하지 않고, 실측 근거를 붙여 다시 물었고 오너가 경로를 바꿨다.**
"오너 메모의 수치와 계산값이 다르면 계산값을 쓰고 차이를 보고한다"의 확장 — **경로 선택에도 같은
규칙이 적용된다.** 다만 카드 수치와 달리 경로는 오너 결정 사항이므로 **바꾸지 말고 묻는다.**

**규격을 못 본 API 는 배관이 아니다.**
"데이터 없는 아이디어는 소재가 아니다"의 짝. 필드 이름을 한 글자도 확인 못 한 API 로 수집기를 짜면
첫 실행이 곧 첫 시험이 된다. 두 후보가 있으면 **규격이 확인되는 쪽**이 먼저다.

**안 드러난 것과 맞는 것은 다르다.**
2013년판 지도가 몇 달 동안 문제없이 굴러간 이유는 옳아서가 아니라, 그 카드들이 서울·경기 일부만
써서 어긋난 지역을 안 그렸기 때문이다. 범위가 넓어지는 순간 드러난다. **검사받지 않은 것은
통과한 것이 아니다**(검수 원칙)와 같은 문장이 데이터에도 적용된다.

## 2026-08-03 (2) — 자동화 수위는 소재마다 다르다

**청약홈은 보드까지 자동, 인구는 데이터까지만.** 오너 선택이다 — "데이터만 자동, 소재는 내가 고른다".
같은 회사 안에서도 자동화 수위가 갈리는 이유가 있다.

청약홈 공고는 **사건**이다. 마감일이 있고, 놓치면 끝나고, 무엇이 소재인지가 비교적 자명하다.
인구는 **상태**다. 매달 조금씩 움직이고 마감이 없으며, 같은 사실을 어느 각도로 자를지가
곧 기획이다. 사건은 기계가 주워도 되지만 **상태는 사람이 잘라야 한다.**

그래서 인구 수집기는 보드에 올리는 대신 **신호를 정리한 표(`data/population-signals.md`)를
커밋하고 알린다.** 오너가 보고 고른다. 자동 등록은 `--register` 플래그로 남겨 뒀다 —
나중에 "이건 그냥 올려도 되겠다"가 되면 대기열 한 줄로 켜진다.

**교훈**: 새 정기 수집기를 만들 때 "보드까지 자동인가"를 기본값으로 정하지 말고 **묻는다.**
자동화 수위는 배관의 성질이 아니라 **그 소재의 성질**이 정한다.

## 2026-08-04~06 — 자동화가 조용할 때, 판형이 갈릴 때, 저장이 막힐 때

이 세션에서 오너가 세 종류의 문제를 던졌고, 셋 다 같은 뿌리를 갖고 있었다:
**실패가 보이지 않는 형태로 온다.**

### 조용한 자동화는 고장과 구분되지 않는다

오너: *"청약 관련 텔레그램 문자는 매일 아침 자동으로 세팅된 거 아니야? 오늘 안 왔던데"*

세팅은 돼 있었고 **한 번도 발화한 적이 없었다.** GitHub Actions 의 `schedule` 은
**기본 브랜치**의 워크플로만 깨우는데 수집기는 작업 브랜치에만 있었다. 같은 이유로 7개가
죽어 있었다. 게다가 성공해도 *새 공고가 0건이면 알림을 안 보내게* 돼 있어서, 예약이 살아
있었어도 조용한 아침이 정상인지 고장인지 오너는 알 수 없었다.

→ **매일 도는 것은 조용한 이유를 스스로 말한다.** 예약 실행은 항상 요약(digest)으로 보내고,
  피로는 목록을 줄여서가 아니라 **어제와의 차이를 보여줘서**(🆕) 막는다.
→ 이 판단은 알림에만 해당하지 않는다. 정기적으로 도는 모든 것에 적용한다.

### 칸의 뜻은 데이터가 정한다 — 판형은 플래그로 켜지 않는다

무순위(줍줍) 카드는 "분양가를 모른다"가 전제였는데, 본청약 때 값이 매겨진 단지의 잔여
세대라면 분양가를 안다. 그러면 그게 소식이다.

→ `price.byType` **유무**가 판을 가른다. 사람이 "이번엔 이 판형" 하고 켜지 않는다.
  같은 원칙의 확장이다 — *"이 칸"이라고 손으로 지정하지 않는다*(CARD_CHECKLIST §3).

### 새 판형은 선택자로 가둔다

새 판을 만들다 확정본(한강·송도)을 세 번 건드릴 뻔했다. 세 번 다 처방이 같았다 —
공통 규칙을 고치지 말고 **그 판형만 잡는 선택자**(`:has(.frow.four)`)로 가둔다.
그리고 **고칠 때마다 확정본 md5 를 전부 다시 찍는다.**
중간에 만들었다가 필요가 없어진 장치(`compact`·`fhead`)는 통째로 걷어냈다 —
고르고 남은 선택지를 남겨 두면 다음 사람이 "언제 쓰는 건가"를 다시 고민한다.

### 확정과 발행 승인은 다른 결정이다

장위 카드는 그림이 다 됐지만 분양가·자격 요건·동수가 전부 2차 출처였다.
→ 픽셀은 고정(`confirmedMd5`)하되 `state` 는 **발행 보류**로 두고 `publishGate` 에
  무엇이 남았는지 적었다. **발행 대기열에는 올리지 않았다.**
  기존 원칙 *"확정 ≠ 발행"* 을 데이터 구조로 굳힌 것이다.

### 실패가 마지막에 몰리는 구조는 검사를 앞으로 당겨서 푼다

세션 중간부터 푸시가 막혔는데(`not in this session's authorized repository set`)
카드 한 장을 네 번 고쳐 확정까지 마친 **뒤에야** 알았다. clone 은 세션 시작에 이미 끝나
성공했고, 커밋도 전부 로컬이라 마지막까지 성공한다.

→ `scripts/check-push.mjs` 를 만들어 `doctor` 가 부르게 했다. **막혀 있으면 작업 전에 말한다.**
→ **읽기가 된다고 쓰기가 되는 게 아니다.** 프록시는 fetch·clone 을 통과시키면서 push 만
  막을 수 있다 — 그래서 `ls-remote` 가 아니라 `push --dry-run` 으로 판정한다.
→ **막힌 것을 다른 인증 경로로 돌아가지 않는다.** 그건 샌드박스 우회다.
  대신 작업분을 패치(`git format-patch`)로 뽑아 오너에게 보낸다.
  **컨테이너 안에만 있는 커밋은 없는 것과 같다.**

### 오너에게 없는 화면을 안내하지 않는다

푸시를 풀려고 *"대화창 [+] → Add from GitHub"* 를 안내했는데 코워크에는 그 메뉴가 없었다
(파일/스킬/커넥터/플러그인 뿐 — 그건 claude.ai 채팅 쪽 UI 다). 오너가 커넥터를 지웠다
다시 붙이는 헛걸음을 했다.

→ **UI 를 안내하기 전에 그 화면이 이 제품에 있는지부터 확인한다.**
  모르면 "제가 확인해 보겠습니다"가 맞지, 그럴듯한 경로를 지어내면 안 된다.

### 지운 정보는 어디로 가는지 정한다

오너가 카드의 회색 안내 머리글을 지우라고 했다. 지우고 나니 `7.3억` 이 최고가인지 최저가인지
카드가 말하지 않게 됐다. → 카드에서 뺀 단서는 **캡션이 받는다.** 그냥 사라지게 두지 않는다.

### 사진은 눈대중이 아니라 계산이다

*"아파트가 너무 작다 / 왼쪽 위로 치우쳤다"* 를 감으로 고치지 않았다. 창문 격자의 세로 대비로
진짜 건물만 골라 가로 무게중심을 재고, 세로는 `shift = 남는 세로 × 42.5%` 를 뒤집어 풀었다.
좌표는 데이터셋에 적어 다음 사람이 다시 재지 않게 했다.
→ **오너의 감각적 지적일수록 측정 가능한 양으로 바꿔서 푼다.**

(`data/market-queue.txt` 푸시 · `workflow_dispatch`). 워크플로를 지우거나 GitHub 화면에서
비활성화하면 저장소만 봐서는 왜 안 도는지 알 수 없다. **끈 이유가 코드 옆에 있어야 한다.**

### 2026-08-19 — 남이 먼저 올린 신고가가 우리에 없을 때, 먼저 의심할 것은 우리 배관이 아니다

**배관이 맞았다.** 메가트리아 59타입의 2020년 이후 최고가는 이미 **10억 1,800만**
(59.75㎡·2026-07-21)이라 8/14 의 10억 500만은 **1,300만원 모자랐다.**
실까는 **전용 59.65㎡ 하나만** 놓고 재서 직전 최고를 9.5억으로 봤고(+5,500만),
우리는 59.65·59.75·59.94 를 **한 칸(전용 59타입)으로 묶는다.** 같은 사실, 다른 자.

**① 판정 단위는 묶기를 유지한다(오너 결정).**
가르면 소재는 눈에 띄게 늘지만 — 같은 단지가 한 달에 서브면적 수만큼 뜨고, 59.65 는
신고가인데 59.75 는 아닌 상태가 흔해져 **카드가 "59.65㎡ 기준"이라는 단서를 달아야 한다.**
단서가 붙는 순간 한 장으로 읽히는 소식이 아니다. 무엇보다 묶기는 **문턱이 높아지는 쪽**이라
틀려도 '못 잡는' 쪽으로 틀린다. **놓친 소재는 손실이지만 잘못 나간 신고가는 사고다.**

**② 그래서 "우리에 없다"는 결함 신고가 아니다.**
다른 서비스가 먼저 올리면 오너는 반드시 되묻는다. 그때 세션이 할 일은 사과하거나 기준을
바꾸는 것이 아니라 **문턱을 대 보는 것**이다. 이번엔 답을 내는 데 파일 다섯 개
(명부·최고가 인덱스·원자료 월별·신고가 로그·판정 코드)를 손으로 뒤져야 했다 —
**손으로 뒤지면 답이 세션마다 달라진다.**

→ `node scripts/singo-why.mjs <단지명> [--type 59] [--price 100500]` 을 만들었다.
명부 → 문턱 → **서브면적별 최고가** → 판정 → 알림 이력을 한 화면에. 네트워크를 안 쓴다.
서브면적 표를 넣은 이유는 "왜 문턱이 저기냐"가 곧 답이기 때문이다.

**③ 되묻는 질문에는 자리를 만든다.** 한 번 물은 질문은 다시 온다. 이번 것은 특히 —
경쟁 서비스가 매일 카드를 올리는 한 오너는 계속 대조할 것이다. 그때마다 세션이 다섯 파일을
뒤지면 **어느 날은 "우리가 틀렸네요"라고 답하게 된다.** 진단기는 그 흔들림을 막는 도구다.

### 2026-08-24(2) — 초록불은 "죽지 않았다"이지 "기준대로 했다"가 아니다

뜻인가"를 물어 고쳤는데, 그 질문에 한 겹이 더 있었다 — **일하긴 했는데 무엇을 재고 일했나.**
→ `pipeline-status.mjs` 에 기준 드리프트 검사를 넣었다. 넣고 나서 **일부러 어긋내 잡히는지**,

**② 임시로 민 것이 상시가 되는 자리를 없앤다.** "진단용 한 줄"이 5일을 산 이유는 그 파일이

신고가 건에 대해 알려줘"*). 수집 창은 **2개월**로 넓게 훑되, 알림에 싣는 것은 **그날 처음

소식이 매일의 것이기 위해서다. 둘을 같은 숫자로 묶으면 하나를 고칠 때 다른 하나가 망가진다.

**④ 기준을 묻는 질문은 점검 기회다.** 오너가 "지금 어떻게 되어 있냐"고 물었을 때
문서를 읽어 옮기지 않고 **코드와 실행 기록을 대조한 것**이 이걸 찾아냈다.
**문서는 기준이지 현황이 아니다.**

### 2026-08-24(3) — 오너가 두 번 물었다면 고칠 곳은 기준이 아니라 **문구**다

날짜가 아니라 **최고가 인덱스**이고, 뜬 거래는 바로 인덱스가 되므로 같은 건이 두 번 뜰 수 없다.
결과적으로 완벽한 하루치다.

**오해의 진짜 원인은 목록의 계약일이 흩어져 보인 것**이었다(08.03 · 08.07 · 07.10 …).

숫자를 재 보지 않고 "네, 바꾸겠습니다"라고 했으면 **알림을 끄는 변경**을 할 뻔했다.
**요청을 그대로 실행하기 전에 그 요청이 무엇을 만들지 먼저 잰다.**

제목을 「오늘 **새로 확인된** 신고가」로 바꾸고, 목록 끝에 계약일이 섞이는 이유를 적었다.
**같은 질문이 두 번 오면 그건 문서화가 아니라 산출물 자체의 결함이다.**

**③ 그 문구를 셀프테스트로 붙잡았다.** 지우면 빨간불이 나게 하고, 실제로 지워 2건이
실패하는 것을 확인한 뒤 되돌렸다. 문구는 리팩터링 때 가장 먼저 사라지는 것이다.

**④ 알림 본문에 마크다운을 쓰지 않는다.** `**굵게**` 로 적었다가 미리보기에서 별표가 그대로
찍히는 것을 봤다 — `notify-telegram` 은 `parse_mode` 를 안 넘겨 **평문**으로 보낸다.
**보낼 문구는 보내는 형태로 미리 찍어 본다.**

### 2026-08-25(2) — 자리가 없는 것은 배치로 못 푼다

오너가 네 가지를 한 번에 지시했다: 제원 3줄 재편 · designQa 에 기준선 넣기 ·
rebuild-cards 빨간불 · 「지난 고점대비」 기준. 그중 두 개에서 같은 교훈이 나왔다.

**① 전부-아니면-전무를 의심한다.**
"기준선을 장애물에 넣자"는 08-17 메모대로 하려다, 코드에서 **이미 시도했다가 되돌린 기록**을
찾았다 — *"곡선을 피해 내려온 라벨이 점선 위에 앉는다는 이유로 다시 곡선 쪽으로 되돌아갔다.
게다가 그 점선은 이 라벨이 가리키는 바로 그 선이라 붙어 있는 편이 오히려 읽힌다."*
그 판단은 지금도 맞았다. 틀린 것은 **전부 넣거나 하나도 안 넣거나** 였다.
→ **자기 선은 빼고 남의 선만** 장애물로 넣으니 서초포레스타2(08-17 미해결)·영통센트럴파크뷰·
영통에듀파크가 한 번에 풀렸다. **옛 결정을 뒤집기 전에 왜 그렇게 됐는지부터 읽는다.**

**② 한쪽을 더 세게 밀면 반대쪽이 깨진다.**
가산두산위브가 돌파선에 스치길래 그 선의 회피 띠를 4px→20px 로 넓혔더니, 라벨이 그걸
피하느라 **제 기준선 한가운데로** 밀려 세 장이 12px 관통했다. 되돌렸다.
신고가와 지난 고점이 0.3%·1.4% 차이인 단지는 **판에 자리가 없다.**
자리가 없는 것은 배치로 못 푼다 — 중계주공5·가산두산위브는 **카드로 만들지 않는다.**

**③ 검사는 스치는 것과 뚫는 것을 갈라야 한다.**
겹침 px 로 재면 안 된다. 선 두께가 3px 이라 **한가운데를 지나도 3px, 아래를 스쳐도 3px** 이다.
그래서 겹침량이 아니라 **선 중심이 글자 속살에 들어왔는지**로 갈랐다. 격자선(잉크 6%)은
글자가 그 위를 지나는 게 설계라 **보이는 진하기**로 걸렀다 — 클래스 목록으로 빼지 않았다.
목록은 새 판형이 생길 때마다 빠지고, 그게 LEAF 가 이미 밟은 실패다.

**④ 초록불이 "일했다"를 뜻하게 만든다.**
`rebuild-cards` 는 빌더가 죽어도 경고만 남기고 종료코드 0 이었다. 그래서 영통센트럴파크뷰가
조용히 실패한 채 **어제 판본이 오늘 배치에 섞일 뻔했다**(사람이 제원 줄 수를 세다가 발견).
이제 죽으면 1 로 끝낸다. 다시 안 만들어지는 청약 카드 6장은 은퇴시켜 초록불을 되찾았다.

**⑤ 말할 수 없는 것 하나만 빼면 된다.**
「지난 고점대비」가 신축에서는 준공 직후 잔물결을 가리켰다(확정본 6장은 −27~−43%,
DMC센트럴자이는 −7.6%). 카드를 통째로 막지 않고 **그 줄만 뺐다** — 곡선도 신고가도
저점 대비도 멀쩡하다. 오늘 4장이 그렇게 나갔다(낙폭 3.9~11%).

## 2026-09-01 — 넘기는 순서가 굳었다, 그리고 중복은 코드가 센다

오너: *"작업은 항상 html로 먼저 만들고 확정 후 jpg로 작업해서 zip 파일로 올려주는 것으로
작업 기준 변경해줘"*
→ **모든 카드 작업의 전달 순서다.** ① `preview-html` 로 HTML 한 장 → ② 오너 확정 →
③ `deliver-set` 이 그 확정본을 JPG 로 바꿔 **ZIP 하나**로. 08-31 의 *"html로 먼저 할수 있나?"* 가
**한 번 해 본 것**이었다면 이번 것은 **기준**이다 — 그래서 도구가 아니라 **게이트**로 넣었다.
`deliver-set` 은 확정 안 된 세트를 **거절**하고, 확정 md5 와 지금 PNG 가 다르면 **멈춘다.**

⚠️ **PNG 를 JPG 로 갈아치우지 않는다.** 「픽셀 불변」의 증거가 PNG 의 md5 라서다.
JPG 는 전달용 사본이고, 다시 뽑아도 확정 증거는 흔들리지 않는다.

오너: *"기존에 제작된 카드들이 중복되어 들어가지는 않았는지 검수해주는 절차는 있나?"*
→ **없었다.** 08-31 에 이미 낸 두 건이 다시 들어왔을 때 **코드는 아무 말도 안 했고 오너가
눈으로 잡았다.** 셀 수 있는 것을 사람 눈에 맡기면 언젠가 놓친다.

오너: *"매 제작 시, 이런 검수 시스템이 자동으로 발현되도록"*
→ **묶는 스크립트 안에 넣었다.** 따로 부르는 검사 도구로 만들지 않았다 —
**따로 부르는 것은 안 부르게 된다.** 이건 이 공장에서 반복되는 형태의 판단이다:
검사는 **일이 실제로 지나가는 길목**에 놓아야 돈다.

오너: *"진짜 중복만 아니면 다 똑같은 템플릿으로 진행해줘"*
→ 처음엔 「값이 달라진 재등장」에 주황불을 켜고 직전 값을 찍어 주려 했는데 **오너가 잘랐다.**
판정은 두 갈래뿐이다: **단지·타입·가격이 모두 같으면 막고, 나머지는 전부 그냥 통과.**
같은 단지가 엿새 만에 또 썼다는 것을 특별 취급하지 않는다.

### 배운 것

**① 「해 봤다」와 「기준이다」는 다르다.**
08-31 의 HTML 미리보기는 한 번의 요청이었고, 09-01 의 같은 말은 **작업 기준**이었다.
기준이 된 것은 **거절할 줄 알아야** 기준이다 — 안 그러면 다음 세션이 편한 길로 돌아간다.

**② 검사에 갈래를 늘리는 것은 공짜가 아니다.**
주황불 한 갈래를 더 두면 매번 읽어야 할 줄이 생기고, 읽히지 않는 경고는 초록불을 흐린다.
오너가 두 갈래로 줄인 것은 단순화가 아니라 **경고의 값을 지킨 것**이다.
(같은 결: 2026-08-31 「아무거나 필수로 만들면 빨간불이 흔해져 안 읽힌다」)

**⑤ 평수는 건축물대장 원값 그대로 쓴다 — 시장 통칭에 맞추지 않는다** (오너 2026-09-01)
08-31 의 대림1 「23평」이 하루 만에 세 장으로 늘었다(목동힐스테이트 23평·신도림태영타운 31평·
보람마을(아주) 23평). 원인은 같다 — **대장의 주거공용 줄이 단지마다 다르게 적혀 있다.**
신도림태영타운은 「계단,복도,ELEV」 한 줄뿐이고 벽체가 없어 전용률이 84.1% 로 나온다.
오너는 **(가) 대장 그대로**를 골랐다.

근거는 두 가지다. ① 숫자가 대장 원값이라 **오보가 아니다.** ② 「주거공용 줄이 하나뿐인
단지만 평수를 뺀다」는 것은 **정기물에 조건부 예외를 두는 일**이고(CEO.md 08-16), 그러면

**⑥ 카톡 캡션은 인스타 캡션의 요약이 아니다** (오너 2026-09-01)
*"카톡 공유용 캡션도 하나 만들어볼 수 있나? … 좀 있어보이게, 이모지도 넣고"* — 세 안을 내고
**B안(앞 세 줄만 숫자로 세우고 나머지는 지역으로 접는 형태)** 을 골랐다. 오너 수정 둘:
제목에서 **건수를 뺐고**(「신고가를 새로 쓴 곳, 15곳」 → 「오늘의 신고가」), 화살표를 **👇 → 👆**
로 바꿨다 — **카톡은 이미지가 글 위에 붙는다.** 매체가 다르면 같은 내용도 다른 물건이다.

그리고 **「그 외」 지역 이름은 코드가 못 만든다.** 오너가 고른 이름의 근거가 제각각이다 —
신도림(역) · 화곡(법정동) · **평촌(생활권 이름, 행정구역에 없다)** · 동탄(구) · 부천중동(시+동).
자동값(`우장산·금정·서동탄·매탄권선·부천시청`)은 전부 자료에서 나온 이름이지만 **읽는 사람이
쓰는 이름이 아니었다.** → 코드는 **후보를 찍고 사람이 고른다.** 숫자는 여전히 코드가 뽑는다.
